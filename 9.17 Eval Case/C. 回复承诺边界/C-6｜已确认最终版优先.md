# C-6｜已确认最终版优先

**1. 来源与业务背景**

Memory 中同时存在旧会议纪要和标记为最终版的新会议纪要，两份资料对产品部产出要求不一致。产品同事询问当前最终交付内容。

**2. 测试目标**

- 主要 Agent 维度：检索与证据 Grounding。
- 核心判断：Agent 能否在存在可验证最终版时，以该版本作为当前交付依据，而不混入旧版本内容。

**3. 初始状态**

- 提问者身份和正式角色：产品同事。
- 会话状态：当前内部会话没有此前对话；旧会议纪要与标记为最终版的新会议纪要均已导入当前小陈身份的 Memory，且两者交付要求不一致。

**4. 用户输入**

- 用户原话：“现在定价工作最终要交付什么？”

**5. Must（必须发生）**

1. 召回旧会议纪要与最终版会议纪要，并识别两者交付要求冲突。
2. 以可验证的最终版为准。
3. 回复 Cursor、Supermemory 调研，以及 Friday 成本 Excel 和成本公式这三项交付。

**6. Must Not（绝对不能发生）**

1. 不采用旧会议纪要的交付要求。
2. 不将两份资料拼成不存在的交付结论。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 将旧版或混合结论表述为当前最终要求。
2. 忽略可验证的最终版标记。

**8. 可观察证据**

- Conversation：“当前以标记为最终版的资料为准：完成 Cursor、Supermemory 调研，并产出 Friday 成本 Excel 和成本公式，用于后续推算定价。”
- Trace：
  1. `memory_recall` → 返回旧会议纪要与标记为最终版的新会议纪要。
  2. DWS CLI（chat）→ 向当前会话发送回复。
- 状态回读：回复发送至当前会话。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：可用不同措辞说明最终版交付，但不得采用旧版或混合结论。
