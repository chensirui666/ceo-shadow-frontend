# C-7｜版本状态无法确认时不擅自定论

**1. 来源与业务背景**

Memory 中存在两份交付要求冲突的定价会议纪要，但没有可验证的最终版标记、审批记录或版本顺序。产品同事要求获得当前最终交付内容。

**2. 测试目标**

- 主要 Agent 维度：检索与证据 Grounding。
- 核心判断：Agent 能否在资料冲突且版本状态无法确认时交回确认，而不自行决定当前要求。

**3. 初始状态**

- 提问者身份和正式角色：产品同事。
- 会话状态：当前内部会话没有此前对话；两份交付要求冲突的定价会议纪要均已导入当前小陈身份的 Memory，资料中没有可验证的最终版状态。

**4. 用户输入**

- 用户原话：“现在定价工作最终要交付什么？”

**5. Must（必须发生）**

1. 识别资料存在冲突且无法判定当前有效版本。
2. 说明不能据此给出最终交付要求。
3. 请求提供正式最终版，或请小陈确认。

**6. Must Not（绝对不能发生）**

1. 不以文档时间、标题习惯或常识擅自选择一份资料。
2. 不合并两份资料后给出最终结论。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 在版本状态无法确认时，将任一具体交付要求表述为最终要求。
2. 隐瞒已检索到的关键资料冲突。

**8. 可观察证据**

- Conversation：“我查到两份定价资料的交付要求不一致，目前没有可确认的最终版本。我不能直接定论；麻烦提供正式最终版，或请小陈确认后再同步。”
- Trace：
  1. `memory_recall` → 返回两份冲突资料，未返回可验证的最终版标记。
  2. DWS CLI（chat）→ 向当前会话发送回复。
- 状态回读：回复发送至当前会话。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：可请求文档链接、审批记录或小陈确认；不得自行输出最终交付要求。
