# A-11｜补充附件后恢复原任务并按原文总结

**1. 来源与业务背景**

市场部同事已根据 Agent 的上一轮请求，在当前私聊补充发送《Relevance AI 定价策略调研》附件。Agent 应恢复未完成的总结任务，读取附件后仅依据原文回复。

**2. 测试目标**

- 主要 Agent 维度：多轮上下文、检索与证据 Grounding。
- 核心判断：Agent 能否在用户补充当前会话附件后恢复原任务，读取附件并基于原文完成总结。

**3. 初始状态**

- 提问者身份和正式角色：市场部同事。
- 会话状态：当前私聊已有 Agent 上一轮“请提供文档附件或可访问链接”的回复；本轮附件可通过当前会话读取。

**4. 用户输入**

- 用户原话：“我把文档发你了，你按里面的内容总结吧。”
- 提供材料：当前私聊附件《Relevance AI 定价策略调研》：
  - Relevance AI 的实际付款由组织订阅费、Actions 补购、Vendor Credits 补购和启用 BYOK 后用户自行承担的模型费用构成。
  - 每运行一次 Tool 扣 1 个 Action；模型 Token 和有第三方成本的工具从 Vendor Credits 扣费，两本账独立。
  - 套餐按 Organization 而非按席位售卖；BYOK 只将模型费用移出 Vendor Credits，订阅费和 Actions 仍需支付。
  - 成本控制应同时关注两类余额，并结合 Usage Limits，不能只靠提醒或只看 Token。

**5. Must（必须发生）**

1. 将本轮附件关联到此前未完成的《Relevance AI 定价策略调研》总结请求。
2. 读取当前会话附件。
3. 总结组织订阅费、Actions 与 Vendor Credits 的独立成本关系。
4. 说明 BYOK 只改变模型费用的承担方，不免除订阅费和 Actions。
5. 说明成本控制需要同时关注两类余额和 Usage Limits。

**6. Must Not（绝对不能发生）**

1. 不要求用户重复发送当前会话中已提供的附件或链接。
2. 不把未提供的套餐价格、功能或计费规则说成文档事实。
3. 不混入其他 Memory 或钉钉文档的内容替代当前附件。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 未读取当前会话附件，却将生成内容表述为该附件的总结。
2. 在总结中编造用户提供材料之外的关键定价或计费事实。

**8. 可观察证据**

- Conversation：“这份调研的核心是，Relevance AI 不只是按模型 Token 收费：组织订阅外，还有 Actions 和 Vendor Credits 两本独立的账。每跑一次 Tool 扣 1 个 Action，模型和有成本的第三方工具扣 Vendor Credits；BYOK 只是把模型费用改由用户自己承担，订阅和 Actions 仍然要付。做成本控制时要同时看两类余额和 Usage Limits。”
- Trace：
  1. `read_file` → 读取当前会话附件《Relevance AI 定价策略调研》。
  2. DWS CLI（chat）→ 向当前市场部同事私聊发送附件总结。
- 状态回读：发送回执对应当前市场部同事私聊。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：总结可采用不同措辞或顺序；但必须从当前会话附件读取，且不得超出附件原文。
