# A-10｜会话附件的跨轮按需读取

**1. 来源与业务背景**

产品同事先在私聊中发送一份文档附件，但没有提出处理请求；稍后才使用“这个文档”追问核心观点。Agent 应先保持跳过，再利用当前会话中已收到的附件读取并回答。

**2. 测试目标**

- 主要 Agent 维度：多轮上下文、工具使用与状态变更。
- 核心判断：Agent 能否保留会话附件上下文，在后续指代不含文档标题或链接时按需读取正确附件，而不是在收到附件时擅自处理或在提问后要求用户重新发送。

**3. 初始状态**

- 提问者身份和正式角色：产品同事。
- 会话状态：当前私聊没有此前对话；没有待确认草稿、待办或文件编辑状态；本 Case 的会话附件内容未预先导入 Memory 或钉钉资料库。

**4. 用户输入**

- 用户原话：
  1. （发送附件《数字人分身需求评审会（会话附件）》）
  2. “帮我总结一下这个文档的核心观点是什么？”
- 前置对话：第二句发生在第一轮附件发送后；用户第二句不提供文档标题、链接或新的附件。
- 提供材料（第一轮）：附件《数字人分身需求评审会（会话附件）》：
  - 数字人分身定位为连接工作应用、沉淀个人 Memory、继承用户回复风格的独立工作应用。
  - 一期优先完成聊天和 Memory 底座。
  - Task、反馈看板等复杂能力在后续阶段迭代，并补齐 PRD 的交互细节与研发交接。

**5. Must（必须发生）**

1. 第一轮 Conversation 为“跳过”，不主动读取、总结或回复附件内容。
2. 第二轮将“这个文档”关联到第一轮当前会话附件。
3. 第二轮调用 read_file 读取该附件。
4. 第二轮总结数字人分身的产品定位、一期聊天和 Memory 底座，以及后续迭代 Task/反馈等方向。

**6. Must Not（绝对不能发生）**

1. 不在第一轮发送附件确认、摘要或其他回复。
2. 不在第二轮要求用户重新发送附件、补充链接或重复提供标题。
3. 不读取或混入其他 Memory、钉钉文档的内容替代当前会话附件。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 第一轮对用户可见地回复、总结或处理附件。
2. 第二轮未读取当前会话附件，却将生成内容表述为附件的总结。
3. 第二轮找不到附件时，虚构已读取或已总结的结果。

**8. 可观察证据**

- Conversation：
  1. 跳过。
  2. “这个文档主要是在对齐数字人分身的定位和一期范围：它要连接工作应用、沉淀个人 Memory，并继承用户的回复风格；一期先把聊天和 Memory 底座做扎实，Task、反馈看板等复杂能力放到后续迭代，同时补齐交互细节和研发交接。”
- Trace：
  1. 对话一：跳过。
  2. 对话二：read_file → 读取当前会话附件《数字人分身需求评审会（会话附件）》。
  3. 对话二：DWS CLI（chat）→ 向当前产品同事私聊发送附件总结。
- 状态回读：第一轮没有新增外发消息；第二轮发送回执对应当前产品同事私聊。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：总结可使用不同措辞；但第一轮必须跳过，第二轮必须从当前会话附件读取，且不得要求用户补充已在当前会话中提供的文档链接。
