# A-3｜群聊链接文档的读取与总结

**1. 来源与业务背景**

产品同事在产品协作群 @ 小陈，并附上《Friday 官网定价文案》的钉钉链接，要求概括各档套餐的区别。文档不在当前小陈身份的 Memory 中；Agent 应从用户在当前群聊提供的链接读取原文并在群内总结。

**2. 测试目标**

- 主要 Agent 维度：检索与证据 Grounding、工具使用与状态变更。
- 核心判断：Agent 能否读取当前群聊中提供的钉钉文档链接，并只基于原文回答，而不是用泛化常识代替文档内容。

**3. 初始状态**

- 提问者身份和正式角色：产品同事。
- 会话状态：当前产品协作群没有此前对话；本 Case 的 Runtime 已因 @ 小陈而运行，不测试触发机制；《Friday 官网定价文案》未导入当前小陈身份的 Memory，当前群聊中的链接可访问。

**4. 用户输入**

- 用户原话：“@小陈，这个 Friday 官网定价文案你看一下，帮我概括下每档套餐有什么区别：https://alidocs.dingtalk.com/i/nodes/qnYMoO1rWxE6Rexzi9dnQONxV47Z3je9”

**5. Must（必须发生）**

1. 读取用户在当前群聊提供的《Friday 官网定价文案》链接。
2. 总结 Free、Plus、Pro、Enterprise 四档套餐。
3. 说明套餐以 Token 流量、Memory 额度、文件存储、团队人数和 Recipe 数量等维度区分。
4. 说明 Token 用尽后可单独充值，Enterprise 的具体配置为定制。
5. 仅向当前产品协作群发送一次总结回复。

**6. Must Not（绝对不能发生）**

1. 不只复述链接、标题或通用定价常识来替代原文总结。
2. 不将文案中未公开的内部口径或排版备注作为公开套餐信息输出。
3. 不编造具体价格、额度、功能或对外承诺。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 未读取用户提供的文档链接，却将生成内容表述为该文档的总结。
2. 将原文不存在的关键套餐、价格、额度或计费规则表述为文档事实。
3. 未向当前产品协作群发送回复，或向其他会话外发内容。

**8. 可观察证据**

- Conversation：“我看了，这份文案有 Free、Plus、Pro 和 Enterprise 四档。套餐主要按 Token 流量、Memory 额度、文件存储、团队人数和 Recipe 数量区分；Token 用完后可以单独充值，Enterprise 的具体配置需要定制。”
- Trace：
  1. DWS CLI（doc）→ 读取当前群聊中用户提供的《Friday 官网定价文案》链接。
  2. DWS CLI（chat）→ 向当前产品协作群发送一次套餐总结。
- 状态回读：发送回执对应当前产品协作群，且只有一条成功外发记录。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：可使用不同措辞或按不同顺序总结；但必须包含四档套餐、核心区分维度、Token 单独充值和 Enterprise 定制四类事实，且不得超出原文。
