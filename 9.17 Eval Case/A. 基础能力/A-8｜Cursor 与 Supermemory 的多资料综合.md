# A-8｜Cursor 与 Supermemory 的多资料综合

**1. 来源与业务背景**

市场部同事想快速了解两份竞品调研各自的重点。Agent 需要分别召回 Cursor 与 Supermemory 的资料，再给出并列、可区分的回答。

**2. 测试目标**

- 主要 Agent 维度：检索与证据 Grounding、多轮上下文、Memory。
- 核心判断：Agent 能否综合两份不同的调研资料，而不是只回答其中一家或用无来源的泛化描述替代。

**3. 初始状态**

- 提问者身份和正式角色：市场部同事。
- 会话状态：当前私聊没有此前对话；《Cursor 定价策略调研》和《Supermemory 定价策略调研》均已导入当前小陈身份的 Memory。

**4. 用户输入**

- 用户原话：“Cursor 和 Supermemory 的调研，分别有哪些重点内容？”

**5. Must（必须发生）**

1. 分别回答 Cursor 与 Supermemory 的调研内容。
2. 对 Cursor 至少给出一条来自调研的具体计费、用量或团队计费事实。
3. 对 Supermemory 至少给出一条来自调研的具体计费、用量或团队计费事实。
4. 两部分内容能够清楚区分对应的竞品，不混淆归属。

**6. Must Not（绝对不能发生）**

1. 不只回答 Cursor 或只回答 Supermemory。
2. 不把一家竞品的计费或用量机制归给另一家。
3. 不用“都要看定价、用量、计费”之类的泛化描述替代资料事实。
4. 不引入 Friday 的成本公式或最终定价结论。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 编造任一竞品未在调研中出现的关键计费、用量或团队机制。
2. 将 Cursor 与 Supermemory 的核心事实混淆或归错。

**8. 可观察证据**

- Conversation：“Cursor 重点看团队按活跃付费席位收费，以及第三方模型用量和 Cursor 自有模型容量分开计算；Supermemory 重点看付费套餐的月度余额如何覆盖使用量，以及余额不足时能否自动充值。两份调研都在看用量和计费，但具体机制不一样。”
- Trace：
  1. memory_recall → 返回《Cursor 定价策略调研》中的相关内容。
  2. memory_recall → 返回《Supermemory 定价策略调研》中的相关内容。
  3. DWS CLI（chat）→ 向当前市场部同事私聊发送回复。
- 状态回读：发送回执对应当前市场部同事私聊。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：可使用两份调研中其他明确且可区分的事实；每份资料至少要有一条具体事实，不要求报出价格数字。
