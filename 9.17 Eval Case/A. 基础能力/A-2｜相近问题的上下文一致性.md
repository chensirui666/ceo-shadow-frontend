# A-2｜相近问题的上下文一致性

**1. 来源与业务背景**

小连在同一私聊中连续追问定价会议的产出及其具体含义。两轮问题表述不同，但指向同一会议结论。

**2. 测试目标**

- 主要 Agent 维度：多轮上下文、Memory。
- 核心判断：Agent 能否让第二轮解释与第一轮已给出的核心事实保持一致，不因换一种问法而改变结论。

**3. 初始状态**

- 提问者身份和正式角色：小连，产品同事。
- 会话状态：当前私聊没有此前对话；《Friday 定价策略讨论会》已导入当前小陈身份的 Memory。

**4. 用户输入**

- 用户原话：
  1. “之前定价会上，老板让产品部主要产出什么？”
  2. “你说的两个产出，分别要做什么？”
- 前置对话：第二句发生在第一轮 Agent 回复之后。

**5. Must（必须发生）**

1. 第一轮说明两项产出是竞品调研与 Friday 成本公式。
2. 第二轮仍将竞品调研解释为调研 Cursor 和 Supermemory 的定价、用量或计费信息。
3. 第二轮仍将成本公式解释为摊开 Friday 成本并用于后续推算定价。
4. 两轮不得出现相互冲突的产出、完成状态或定价结论。

**6. Must Not（绝对不能发生）**

1. 不在第二轮新增第一轮没有依据的第三项产出。
2. 不在第二轮否定或替换第一轮的两项产出。
3. 不把任一产出说成已完成或已形成最终价格。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 两轮对同一会议结论给出互相矛盾的核心答案。
2. 因第二轮追问编造最终价格或新的会议结论。

**8. 可观察证据**

- Conversation：
  1. “主要两项：调研 Cursor 和 Supermemory；把 Friday 的各项成本摊开做成成本公式，用它反推定价。”
  2. “竞品调研要看它们怎么定价、按什么用量和计费；成本公式要把 Friday 的成本项摊开，最后用来推定价。”
- Trace：
  1. 对话一：memory_recall → 返回《Friday 定价策略讨论会》中两项待产出工作。
  2. 对话一：DWS CLI（chat）→ 向当前小连私聊发送第一轮回复。
  3. 对话二：DWS CLI（chat）→ 向当前小连私聊发送第二轮回复。
- 状态回读：两条发送回执均对应当前小连私聊。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：第二轮可以换一种解释方式，但不得改变第一轮已确认的两项产出、它们的含义或完成状态。
