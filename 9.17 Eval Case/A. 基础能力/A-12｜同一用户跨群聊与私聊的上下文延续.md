# A-12｜同一用户跨群聊与私聊的上下文延续

**1. 来源与业务背景**

小连先在产品协作群向小陈询问定价会议后的工作安排，再在私聊追问其中的竞品调研。群聊与私聊是不同会话，但发送者是同一小连；Agent 应延续此前回答，不要求用户重复已经明确的上下文。

**2. 测试目标**

- 主要 Agent 维度：多轮上下文。
- 核心判断：Agent 能否通过同一用户身份关联群聊与私聊的前序对话，并让私聊回复延续群聊中的定价任务结论。

**3. 初始状态**

- 提问者身份和正式角色：小连，产品同事。
- 会话状态：产品协作群 A 与小连私聊的会话 ID 不同，但两条消息的发送者 `userId` 均为小连；本 Case 的跨会话对话历史可按该用户身份召回；《Friday 定价策略讨论会》已导入当前小陈身份的 Memory。

**4. 用户输入**

- 用户原话：
  1. 产品协作群 A：“@小陈，上次定价会后，产品接下来先做哪两件事？”
  2. 小连私聊：“那竞品调研这块，具体优先看什么？”
- 前置对话：第二句发生在第一轮群聊回复后；两个会话 ID 不同。

**5. Must（必须发生）**

1. 群聊回复说明两项任务是调研 Cursor、Supermemory，以及产出 Friday 成本 Excel / 成本公式。
2. 私聊将“竞品调研”关联到群聊中已说明的 Cursor 与 Supermemory。
3. 私聊说明竞品调研优先关注定价、用量或额度、超额计费与团队计费等信息。
4. 私聊不要求小连重复解释“竞品调研”所指的工作。

**6. Must Not（绝对不能发生）**

1. 不在私聊中否定、替换或遗漏群聊中已说明的两项任务。
2. 不将无关竞品或未确认的最终价格说成会议结论。
3. 不因群聊与私聊会话 ID 不同而要求小连重复已明确的上下文。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 私聊回复与群聊中已说明的定价任务相互矛盾。
2. 私聊无法关联同一小连的前序群聊上下文，要求其重新提供已经明确的信息。
3. 私聊编造新的会议结论、竞品或最终价格。

**8. 可观察证据**

- Conversation：
  1. 群聊：“先做两件事：调研 Cursor 和 Supermemory；把 Friday 的成本项摊开，做出成本 Excel 和成本公式，用来反推定价。”
  2. 私聊：“你刚才问的竞品调研，先看 Cursor 和 Supermemory 的定价、用量或额度、超额计费和团队计费；这些信息再和 Friday 的成本项一起放进成本公式里判断定价。”
- Trace：
  1. 群聊：`memory_recall` → 返回定价会议中的产品待办；DWS CLI（chat）→ 向产品协作群 A 回复。
  2. 私聊：`memory_recall` → 返回同一小连在产品协作群 A 的前序对话及定价会议资料；DWS CLI（chat）→ 向当前小连私聊回复。
- 状态回读：第一条回复只发送至产品协作群 A；第二条回复只发送至当前小连私聊。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：可用不同措辞延续说明；但必须正确关联同一用户的跨会话上下文，且不得改变会议已明确的定价任务。
