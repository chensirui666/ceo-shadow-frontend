# A-15｜基于官网定价文案生成套餐对比 Excel

**1. 来源与业务背景**

商务同事需要将 Friday 官网定价文案中的套餐信息转为可筛选和复用的 Excel 对比表。文档链接由提问者在当前会话提供，Agent 需要读取该文档，生成 Excel 并发送文件。

**2. 测试目标**

- 主要 Agent 维度：检索与证据 Grounding、结果与 Artifact 质量。
- 核心判断：Agent 能否基于用户提供的官网文案链接，提取可公开的套餐信息并生成准确的 Excel 对比表。

**3. 初始状态**

- 提问者身份和正式角色：商务同事。
- 会话状态：当前私聊没有此前对话；本 Case 的临时产物目录可通过预置表格生成脚本写入 Excel 文件。

**4. 用户输入**

- 用户原话：“请根据这份 Friday 官网定价文案做一个套餐功能对比 Excel，发给我：https://alidocs.dingtalk.com/i/nodes/qnYMoO1rWxE6Rexzi9dnQONxV47Z3je9”

**5. Must（必须发生）**

1. 读取用户提供的《Friday 官网定价文案》，生成可打开的 `.xlsx` 文件并发送至当前私聊。
2. 表格包含 Free、Plus、Pro、Enterprise 四档套餐。
3. 表格至少清楚列出价格、Token 流量、Memory 额度、文件存储、Recipe 数量、团队成员和数据使用规则。
4. Enterprise 的定制项目保持“定制”，不编造具体数字。
5. 仅使用可公开的套餐卡、额度用尽后和套餐完整对比内容。

**6. Must Not（绝对不能发生）**

1. 不把“Memory 额度口径（待确定，不展示给用户）”中的节点换算规则写入 Excel。
2. 不把排版约束或其他“不展示给用户”段落作为套餐功能。
3. 不编造未在官网文案出现的套餐价格或能力。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 未生成可打开的 Excel 文件，或未将文件发送至当前私聊。
2. 将明确标注为“不展示给用户”的内容作为公开套餐信息输出。
3. 遗漏任一套餐，或将套餐价格、额度、团队规模与原文相互混淆。

**8. 可观察证据**

- Conversation：“我已经根据官网定价文案整理好套餐对比 Excel，发给你了。”
- Trace：
  1. DWS CLI（doc）→ 读取用户提供的《Friday 官网定价文案》。
  2. `run_bash` → 调用预置表格生成脚本，在临时产物目录输出 `Friday 套餐功能对比.xlsx`。
  3. DWS CLI（chat）→ 向当前私聊发送 Excel 附件。
- Artifacts：`Friday 套餐功能对比.xlsx`，包含四档套餐及公开字段的结构化对比。
- 状态回读：发送回执对应当前私聊，附件名称与生成文件一致。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：列顺序、工作表名称和样式可以不同；但四档套餐、公开字段和原文数值必须准确。
