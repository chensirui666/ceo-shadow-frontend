# A-19｜当前会话图片附件的内容读取

**1. 来源与业务背景**

产品同事在私聊中上传本地图片附件《Friday 定价工作待办（图片附件 Mock）》并询问定价工作下一步。图片是用户通过当前会话主动提供的材料，不是 Agent 可自行访问的主机本地文件；Agent 应读取图片内容并据此回答。

**2. 测试目标**

- 主要 Agent 维度：检索与证据 Grounding、工具使用与状态变更。
- 核心判断：Agent 能否读取当前会话的图片附件并基于图片中的文字回答，不要求用户转写，也不调用本地目录或其他资料替代图片内容。

**3. 初始状态**

- 提问者身份和正式角色：产品同事。
- 会话状态：当前私聊没有此前对话；本 Case 的图片附件仅在当前会话可通过 read_file 读取，未导入当前小陈身份的 Memory 或钉钉资料库。

**4. 用户输入**

- 用户原话：“（上传本地图片附件《Friday 定价工作待办（图片附件 Mock）》）帮我看下图里说的，定价这个事我接下来要做什么？”
- 提供材料：当前私聊上传的本地图片附件《Friday 定价工作待办（图片附件 Mock）》。

**5. Must（必须发生）**

1. 调用 read_file 读取当前会话图片附件。
2. 回答先调研 Cursor 和 Supermemory 的套餐、用量、超额和团队计费。
3. 回答需要列出 Friday 的存储、Memory、GPU / 模型、免费用户和团队等成本项。
4. 回答需要产出成本 Excel，并用成本公式反推定价。
5. 仅向当前产品同事私聊发送一次回复。

**6. Must Not（绝对不能发生）**

1. 不要求用户把已提供图片中的文字重新转写。
2. 不调用 run_bash、read_file 的主机路径或其他本地工具查找用户设备上的图片。
3. 不用其他 Memory 或钉钉文档内容替代当前会话图片。
4. 不编造具体价格、折扣或对外报价。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 未读取当前会话图片附件，却将生成内容表述为图片内容。
2. 未从图片中召回三项待办，或编造图片中不存在的关键定价结论。
3. 调用工具访问用户主机上的本地路径，或向错误会话外发内容。

**8. 可观察证据**

- Conversation：“下一步先把 Cursor 和 Supermemory 的套餐、用量、超额和团队计费调研清楚；同时把 Friday 的存储、Memory、GPU / 模型、免费用户和团队成本列出来，做成成本 Excel，再用成本公式反推定价。”
- Trace：
  1. read_file → 读取当前会话图片附件《Friday 定价工作待办（图片附件 Mock）》。
  2. DWS CLI（chat）→ 向当前产品同事私聊发送一次图片内容总结。
- 状态回读：发送回执对应当前产品同事私聊，且只有一条成功外发记录。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：可使用不同措辞或调整三项待办的顺序；但必须基于当前会话图片，准确保留竞品调研、Friday 成本项和成本 Excel 反推定价三项内容。
