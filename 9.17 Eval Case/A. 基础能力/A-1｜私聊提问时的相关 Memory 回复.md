# A-1｜私聊提问时的相关 Memory 回复

**1. 来源与业务背景**

小连在私聊中确认小陈在 Friday 定价工作中的当前产出。答案已记录在定价会议 Memory 中，Agent 应在私聊场景下召回相关会议结论并直接回复。

**2. 测试目标**

- 主要 Agent 维度：Memory。
- 核心判断：Agent 能否在私聊中从 Memory 召回与用户问题高度相关的定价任务，而不是泛泛谈定价或引用无关资料。

**3. 初始状态**

- 提问者身份和正式角色：小连，产品同事。
- 会话状态：当前小连私聊没有此前对话；本 Case 的 Runtime 已因私聊消息而运行，不测试触发机制；《Friday 定价策略讨论会》已导入当前小陈身份的 Memory。

**4. 用户输入**

- 用户原话：“之前定价会上，老板让产品部主要产出什么？”

**5. Must（必须发生）**

1. 召回定价会议中“调研 Cursor 和 Supermemory”的待办。
2. 召回“根据 Friday 资源消耗产出成本公式”的待办。
3. 说明成本公式用于后续推算定价。

**6. Must Not（绝对不能发生）**

1. 不用泛化的定价常识替代会议结论。
2. 不把竞品调研或成本公式说成已经完成。
3. 不编造最终价格、折扣或对外报价。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 未依据 Memory 回答，导致遗漏或篡改会议已明确的两项产出。
2. 将任何未批准的价格表述为最终或可对外使用。

**8. 可观察证据**

- Conversation：“主要两项：调研 Cursor 和 Supermemory；把 Friday 的各项成本摊开做成成本公式，用它反推定价。”
- Trace：
  1. `memory_recall` → 返回《Friday 定价策略讨论会》中与产品部定价待办相关的内容。
  2. DWS CLI（chat）→ 向当前小连私聊发送回复。
- 状态回读：发送回执对应当前小连私聊。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：可用不同措辞回答，但必须保留两项产出及成本公式与后续定价的关系。
