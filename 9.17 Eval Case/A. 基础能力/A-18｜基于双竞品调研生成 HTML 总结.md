# A-18｜基于双竞品调研生成 HTML 总结

**1. 来源与业务背景**

产品同事需要一个可直接在浏览器打开的竞品定价说明页。Cursor 与 Supermemory 的定价调研均已导入当前小陈身份的 Memory，Agent 需要基于两份原文生成独立 HTML 文件并发送给提问者。

**2. 测试目标**

- 主要 Agent 维度：结果与 Artifact 质量、工具使用与状态变更。
- 核心判断：Agent 能否把两份竞品资料整理成可离线打开、内容准确且结构清楚的 HTML 文件，并发送至当前会话。

**3. 初始状态**

- 提问者身份和正式角色：产品同事。
- 会话状态：当前私聊没有此前对话；《Cursor 定价策略调研》与《Supermemory 定价策略调研》已导入当前小陈身份的 Memory；本 Case 的临时产物目录可写入 HTML 文件。

**4. 用户输入**

- 用户原话：“帮我把 Cursor 和 Supermemory 的定价调研做成一个 HTML 页面，发给我。”

**5. Must（必须发生）**

1. 生成可直接在浏览器打开的独立 `.html` 文件，并发送至当前私聊。
2. 页面包含 Cursor 与 Supermemory 的独立说明区，以及可读的对比区。
3. Cursor 区说明套餐席位与独立用量池；Supermemory 区说明月度余额、Memory 与 SuperRAG 的区别。
4. 页面不依赖外部网络资源才能展示核心文字和对比内容。

**6. Must Not（绝对不能发生）**

1. 不遗漏任一调研文档。
2. 不编造竞品价格、额度或 Friday 定价结论。
3. 不将只有外部链接或空壳页面作为完成产物。

**7. Hard Gate**

出现以下任一行为，整条 Case 直接失败：

1. 未生成可直接打开的 HTML 文件，或未将文件发送至当前私聊。
2. HTML 缺少任一竞品的核心说明，或核心内容必须依赖外部网络才能显示。
3. 页面包含关键虚构计费事实。

**8. 可观察证据**

- Conversation：“我已经把两份竞品调研做成 HTML 页面，发给你了。”
- Trace：
  1. `memory_recall` → 返回 Cursor 与 Supermemory 定价调研内容。
  2. `write_file` → 在临时产物目录写入 `Cursor 与 Supermemory 定价对比.html`。
  3. DWS CLI（chat）→ 向当前私聊发送 HTML 附件。
- Artifacts：`Cursor 与 Supermemory 定价对比.html`，可直接打开，包含两个竞品的说明区与对比区。
- 状态回读：发送回执对应当前私聊，附件名称与生成文件一致。

**9. 评分说明**

- Case 优先级：P1。
- 允许的其他正确答案或路径：页面布局和 CSS 样式可以不同；但必须是可离线打开的独立 HTML，且内容基于两份调研。
