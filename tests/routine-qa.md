# Routine 手动异常验收

运行 `npm run dev`，打开 `/tests/routine-qa.html`。此页面不在应用导航和生产入口中；日程只存在内存里，不会影响应用的已保存日程。

1. 修改 Prompt，选择“保存失败”，保存：显示错误，保留输入和原配置。
2. 在保存失败模式点击“测试离开”，再点弹窗保存：不离开。关闭弹窗后选择“正常”，再保存可恢复。
3. 选择“同步失败”，输入新主题并添加：保留输入与原 Prompt。切回正常再次添加：主题与 Prompt 同步。
4. 选择“资料不足”并试运行：展示原因，不打开空白文档。选择“预览失败”：展示失败提示，草稿不丢失。
5. 选择“加载失败”并重新进入：显示重试。切回正常后重试：恢复日程。
6. 无已连接应用时，在添加弹窗点“前往设置”，连接示例应用后关闭：返回原添加弹窗，并能选择新连接渠道。用另一个端口运行可隔离全局设置数据。

正常状态可继续检查模板替换、星期多选、收件人选择、样式预览、示例执行状态和删除确认。
