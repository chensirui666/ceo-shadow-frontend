# Friday 9.24 上线验收标准

## 1. 基本信息

| 项目 | 内容 |
| --- | --- |
| 上线时间 | 2026-09-24 |
| 产品负责人 | 陈思睿 |
| 验收模块 | Routine、Library |
| 测试范围 | macOS、Windows 客户端 |

下列 Case 均须在 macOS 和 Windows 通过。Windows 不单列 Case；涉及“打开所在文件夹”时，在系统文件资源管理器中打开对应位置并定位文件即可。

本标准以 [9.24上线功能清单](9.24%E4%B8%8A%E7%BA%BF%E5%8A%9F%E8%83%BD%E6%B8%85%E5%8D%95.md) 的最新产品决定为准：本期验收真实的定时生成、归档和发送能力；Artifact 不提供下载，统一使用“打开所在文件夹”。

## 2. Routine

| 功能 | 功能说明 | 验收标准 |
| --- | --- | --- |
| Routine 创建与管理 | 用户可创建、查看、编辑、开启、关闭和删除独立 Routine。 | **Case 1｜创建 Routine。** 操作：在推荐区点击 Add，选择一个 Recipe，保留默认日程并保存。预期：新 Routine 出现在“我的日程”；保存不会立即生成或发送 Artifact。<br><br>**Case 2｜查看并编辑 Routine。** 操作：从“我的日程”打开已有 Routine，修改名称后保存。预期：名称在详情和“我的日程”中一致；其他已保存配置保持不变。<br><br>**Case 3｜关闭 Routine。** 操作：关闭一条已设置下次执行时间的 Routine，并等待该时间经过。预期：Routine 不发起新的生成或发送；已有 Artifact 和 Recent Sessions 仍可查看。<br><br>**Case 4｜删除 Routine。** 操作：删除一条已有正式 Artifact 的 Routine，并在确认弹窗中确认。预期：Routine 从“我的日程”移除并停止后续执行；Library 中已有 Artifact 保留，来源显示原 Routine 已删除。 |
| 核心 Recipe | 每条 Routine 必须且只能选择一个 Friday 内置 Recipe，用户可查看、添加或更换。 | **Case 1｜选择 Recipe。** 操作：在新 Routine 的“核心能力”中打开 Recipes 侧边栏，查看详情后点击 Add。预期：侧边栏关闭，所选 Recipe 成为当前 Routine 的唯一核心 Recipe。<br><br>**Case 2｜缺少 Recipe 时保存或试运行。** 操作：新建 Routine 后不选择 Recipe，分别点击保存和试运行。预期：两个操作均提示先选择核心 Recipe；不会创建可运行 Routine、试运行结果或执行记录。<br><br>**Case 3｜更换 Recipe。** 操作：为已有 Routine 选择新的 Recipe 后保存。预期：新 Recipe 用于后续执行；已选的执行星期、时间、收件人、文件格式和样式不会被自动改写。 |
| 执行与交付配置 | 用户可配置执行星期、开始生成时间、时区、收件人、文件格式和 PDF、Word 样式。 | **Case 1｜设置执行时间。** 操作：选择周一、周三、周五及一个接近当前时间的开始生成时间后保存。预期：Routine 仅在选定星期的该时间开始生成；显示并使用创建 Routine 时的时区，之后设备时区变化不改变该 Routine 的时区。<br><br>**Case 2｜配置多个收件人。** 操作：在两个已连接 Connector 下，分别搜索并添加不同的个人或群聊后保存。预期：已添加的全部收件人随 Routine 保存；下次正式执行时向每个收件人发送。<br><br>**Case 3｜不配置收件人。** 操作：保存一条没有收件人的 Routine，并等待它正式执行。预期：系统生成正式 Artifact 并归档至 Library，但不向任何外部目标发送。<br><br>**Case 4｜配置格式和样式。** 操作：分别保存 PDF、MD、Word 格式；在 PDF 与 Word 下分别选择预设样式并生成文件，再切换为 MD 后切回 Word。预期：PDF 与 Word 均应用所选预设背景视觉；MD 不应用样式；切回 Word 后恢复此前选择的样式。 |
| 试运行与保存 | 用户可按草稿试运行、查看预览，并决定是否保存对正式 Routine 的修改。 | **Case 1｜试运行成功。** 操作：修改 Routine 草稿后点击试运行，并查看生成的预览。预期：预览使用当前草稿；不发送给收件人、不改变已保存配置、不写入 Recent Sessions，也不进入 Library。<br><br>**Case 2｜试运行失败。** 操作：在资料不足或生成失败的条件下点击试运行。预期：页面说明失败或资料不足原因；不把空白内容展示为成功预览。<br><br>**Case 3｜未保存修改离开。** 操作：修改 Routine 后不保存，尝试返回首页或切换到 Library。预期：出现未保存修改提示；选择保存后才离开并应用草稿，选择取消保存后恢复原配置并离开。 |
| 定时执行与 Recent Sessions | 系统按已保存配置定时生成、归档和可选发送 Artifact，并记录结果及支持失败重试。 | **Case 1｜正式生成并归档。** 操作：为无收件人的 Routine 设置临近执行时间并等待执行完成。预期：系统生成一个正式 Artifact，Library 收录该 Artifact，Recent Sessions 记录为“已生成”。<br><br>**Case 2｜正式生成并发送。** 操作：为有收件人的 Routine 设置临近执行时间并等待全部目标成功返回。预期：系统先生成并归档一个 Artifact，再向所选目标发送；Recent Sessions 显示“已发送”，Library 显示对应发送结果。<br><br>**Case 3｜部分发送失败后重试。** 操作：将同一次执行发送到一个成功目标和一个失败目标，在 Recent Sessions 查看详情后点击重试发送。预期：原 Artifact 保持不变；只向失败目标重试，已成功目标不重复发送；成功后更新该目标的发送结果。<br><br>**Case 4｜生成失败。** 操作：让正式执行返回生成失败。预期：Recent Sessions 显示“生成失败”，不创建新的 Library Artifact；用户可从该记录发起重试。<br><br>**Case 5｜发送结果未知。** 操作：让生成后的某个目标返回未确认的发送结果。预期：Recent Sessions 和 Library 明确显示“结果待确认”，不把它标记为已发送，也不自动重复发送。 |

## 3. Library

| 功能 | 功能说明 | 验收标准 |
| --- | --- | --- |
| Artifact 列表页 | 集中展示 Message 和 Routine 正式生成的 Artifact，支持统计、搜索、筛选、视图切换和状态反馈。 | **Case 1｜收录正式 Artifact。** 操作：完成一次 Message 正式生成、一次 Routine 正式生成和一次 Routine 试运行后进入 Library。预期：Message 与 Routine 的两个正式 Artifact 均显示；试运行预览和 Connector 原始资料不显示。<br><br>**Case 2｜查看本周成果。** 操作：在本周生成不同类型的 Artifact 后进入 Library。预期：本周总数和分类数量基于当前用户本周的实际 Artifact 计算，不显示写死示例数字。<br><br>**Case 3｜搜索和筛选。** 操作：输入 Artifact 名称的一部分，选择来源和类型筛选，再点击清除筛选。预期：搜索只匹配文件名称；名称、来源和类型取交集；清除筛选后恢复全部可访问 Artifact。<br><br>**Case 4｜切换视图。** 操作：在筛选结果中切换列表和网格，再切回列表。预期：两种视图展示同一批 Artifact；当前搜索、筛选和已打开的 Artifact 状态保持不变；默认按生成时间倒序。<br><br>**Case 5｜空态和加载异常。** 操作：分别进入无 Artifact、筛选无结果和列表加载失败的场景。预期：无 Artifact 时说明生成文件会保存在这里；筛选无结果时提供清除筛选；加载失败时说明失败并提供重试，不冒充为空库。 |
| Artifact 操作 | 用户可打开 Artifact 所在文件夹、重命名或删除 Artifact。 | **Case 1｜打开所在文件夹。** 操作：在列表或网格中对一个本地存在的 Artifact 点击“打开所在文件夹”。预期：系统文件管理器打开该 Artifact 所在文件夹，并定位对应文件。<br><br>**Case 2｜原位重命名。** 操作：对 Artifact 选择重命名，输入新名称并保存。预期：列表／网格和已打开预览中的名称同步更新；正文、格式、生成时间、来源和已发送文件不变。<br><br>**Case 3｜无效重命名。** 操作：分别提交空名称，以及尝试通过名称修改扩展名。预期：保存被拒绝并保留原名称和当前输入，用户可修改后重试。<br><br>**Case 4｜删除 Artifact。** 操作：对未发送中的 Artifact 点击删除，分别取消和确认删除。预期：取消时保留 Artifact；确认后从当前列表移除，若正在预览则关闭预览；不会删除来源 Message／Routine，也不会撤回外部已发送内容。<br><br>**Case 5｜删除发送中的 Artifact。** 操作：在 Artifact 正在发送时打开更多操作。预期：删除项不可用，不能发起删除。 |
| Artifact 预览 | 用户可在右侧只读查看 Artifact 内容、来源和发送结果，并获得预览异常反馈。 | **Case 1｜预览支持的文件。** 操作：依次打开 PDF、MD／DOCX／HTML、TXT、XLSX／CSV、PPTX、图片和代码 Artifact。预期：在右侧只读展示对应完整内容；HTML 不执行文件内脚本，代码不执行。<br><br>**Case 2｜切换 Artifact。** 操作：先打开一个长内容 Artifact，再点击另一个 Artifact。预期：复用同一预览面板，展示新 Artifact 的内容并从顶部开始；不会短暂显示上一个 Artifact 的正文。<br><br>**Case 3｜来源和发送结果。** 操作：打开分别来自 Message 和 Routine 的 Artifact，并查看发送详情。预期：来源可跳转到对应 Message 或 Routine 执行记录；按 Connector 和目标显示未发送、发送中、已发送、部分发送失败、发送失败或结果待确认及失败原因。<br><br>**Case 4｜无法预览或无权限。** 操作：分别打开不支持预览、加载失败、已删除和无权限的 Artifact。预期：明确说明对应原因；不支持预览或加载失败时，文件仍存在则保留“打开所在文件夹”；已删除时关闭失效预览并刷新列表；无权限时不展示正文。 |
