## 0. 当前页面与本期目标（本期目标优先于下方历史细节）

当前页面已经实现三栏 Modal，而不是独立路由：

1. **Connected apps**：当前演示在钉钉、飞书、Teams 三张应用行中直接模拟多项连接、重连和断开；本期必须收敛为同一时间只有一个活动 Connector。选择另一项前先确认切换，旧 Connector 的独立身份保留为非活动；当前没有 Connector 详情页。
2. **General**：群聊 `@所有人`、等待时长、免打扰与语言选择在一个可保存的表单中；不提供通知偏好。
3. **How Friday works for you**：姓名和 @ 别名可编辑；一段可保存的多行 Prompt 统一说明 Friday 的判断、表达和处理边界。此页不单列安全边界，也没有 Memory／Feedback 跳转入口。工作风格后台任务完成后，铃铛通知的“查看个人风格”直接打开此处。

切换不是删除：旧“连接器＋账号”的 Memory、工作风格、后台任务和历史完成通知继续独立保留，不自动合并；它停止作为当前读取和处理来源。后台任务仍可在旧身份下完成，但只有切回该身份时才在时钟或铃铛中显示。下方 Connector 详情页、分层能力卡和 Home 入口是较早的目标描述；当前用户可见页面以本节为准，运行状态只在初始化与 Message 的真实后端能力完成后再展示。

## 1. 背景与目标

### 1.1 背景

Friday 不应成为需要管理大量参数的 AI 后台。用户进入 Settings 的目的，是长期回答几个稳定的问题：

1. Friday 当前在哪一个工作应用中代表我工作？
2. 它应该先等我多久？什么时候保持安静？
3. 它如何识别“我”，以及我希望它如何判断、表达和处理工作？
4. Settings 中哪些项目可配置，哪些不在此页提供？

当天是否处于测试、正式或暂停状态，由 Onboarding／Message 的真实运行能力控制；工作资料与来源属于 Memory；具体反馈属于 Feedback。Settings 只管理这些跨天仍持续生效的偏好和边界。

### 1.2 目标

用户可在一个简洁页面中：

- 选择当前唯一活动的钉钉、飞书或 Teams Connector，并理解切换的后果；
- 调整群聊触发条件和回复节奏；
- 用一段 Prompt 说明 Friday 应如何判断、表达和处理工作；
- 明确知道此页不提供通知偏好或系统执行约束的配置。

### 1.3 成功标准

用户无需帮助文档即可回答：

1. Friday 当前由哪个工作应用代表我工作？
2. 什么情况下 Friday 会在群里回应？
3. Friday 会给我留多久亲自回复？
4. 哪些情况它绝不会自行决定？
5. 为什么某条消息会或不会提醒我？

## 2. 体验原则

1. **设置应当是长期偏好，而非日常操作。** 测试、正式和暂停不在 Settings 管理；当前前端不伪造这些运行状态。
2. **一页完成长期配置。** 当前 General 与个人资料直接显示可编辑项目和保存行动，不再增加二级详情或能力卡。
3. **连接是唯一活动工作身份，不是能力开关。** 同一工作空间只能有一个活动“连接器＋账号”；切换不会合并或删除旧身份。活动 Connector 才能读取和处理新的来源内容。
4. **用户可编辑自己的 Prompt，不看到系统配置。** 该 Prompt 是用户给 Friday 的工作说明；不暴露原始资料、系统 Prompt 或内部风险规则。
5. **风险默认收紧。** “@所有人”默认不处理；免打扰时段默认不正式发送；系统执行约束不在 Settings 配置。

## 4. 信息架构

### 4.1 信息架构

Settings 的一级内容只有三个入口；左侧导航只负责切换右侧内容，不把所有设置堆在一张长页面中。

```text
SETTINGS
  Connected apps
  General
  ─────────────
  How Friday works for you
    └─ 个人资料：姓名、@ 别名、Prompt
```

| 左侧导航项 | 右侧默认内容 | 进一步进入 |
| --- | --- | --- |
| `Connected apps` | 钉钉、飞书的连接状态与主行动 | 某一应用的详情与断开确认。 |
| `General` | 群聊处理条件、工作节奏与语言 | 同一面板中编辑并统一保存。 |
| `How Friday works for you` | 个人资料、@ 别名与一段 Prompt | 同一面板中编辑并保存。 |

### 4.2 设置工作区（Modal Settings Workspace）

Settings 不是替换整个产品工作台的独立页面，而是一个从当前页面上方打开的**居中设置工作区**。这是对参考图中“主界面仍然可见、设置成为专注前景”的交互抽象。

- 用户从全局侧栏点击 `Settings` 后，当前工作台保留在后方；后方内容降低对比度并覆盖一层暖灰遮罩，仍可辨认但不可操作、不可滚动。
- 前景设置工作区使用完整、安静的浅色表面和柔和圆角；通过克制的浮层阴影与后方界面分层，而非毛玻璃、渐变或厚重描边。
- 工作区固定为左右两栏：左栏为局部 Settings 导航，右栏为当前选中内容。切换左栏项目时，只替换右栏内容；全局侧栏与后方页面均不发生跳转。
- 右上角提供低干扰的关闭入口。用户按 `Esc` 或点击遮罩也可关闭；若当前有未保存的改动，先询问用户“放弃更改”或“继续编辑”。关闭后回到打开前的工作台状态。
- General 与个人资料均在**同一个工作区的右栏**直接编辑；不得为 Prompt、安全边界或通知再叠加第二层详情弹窗。
- 工作区再次打开时保留用户上次查看的一级栏目；首次打开默认进入 `Connected apps`，因为连接状态是最具行动性的设置。

### 4.3 视觉与内容排布

整体视觉采用“安静的编辑式设置面板”，以层级、留白和文字建立重点，而不是用大量卡片制造仪表盘感。

#### 4.3.1 分层与底色

- 后方工作台：保留当前页面原有布局，仅以半透明暖灰遮罩退场；不得模糊到无法识别，也不得与前景竞争注意力。
- 前景工作区：使用偏暖的白色主表面。左栏比右栏略深一阶，形成导航区与内容区的自然分界；中间使用一条细分割线，而不是明显边框。
- 内容分组：General 的设置行放入一块低对比度的浅石色容器；容器内用细线划分行。它应像一张整理良好的偏好清单，而不是多张独立卡片。
- 仅使用黑色、暖灰、浅石色作为主色；成功/始终生效可使用极少量深青绿色作为状态提示。危险操作只在确认区域使用克制的警示色。

#### 4.3.2 导航与标题

- 左栏顶部以小号全大写 `SETTINGS` 作为栏目标题；一级导航项依次为 `Connected apps`、`General`、`How Friday works for you`。个人能力详情不额外出现在左栏，避免导航变成设置树。
- 每个导航项使用简洁线性图标、名称和充足的点击区域。当前项以浅米色填充和清晰文字强调，不使用高饱和色块、粗边框或左侧彩色竖线。
- 右栏标题使用克制的编辑式衬线字体表达章节层级，例如 `General`、`Connected apps`、`How Friday works for you`；说明、表单、状态与操作均使用清晰的无衬线字体。衬线字体只用于标题，不能形成营销海报式的大字。
- 标题下只放一句解释当前区域目的的辅助文案；不重复介绍 Friday，也不堆叠产品口号。

#### 4.3.3 三个一级内容的呈现

| 内容 | 右栏呈现方式 | 视觉重点 |
| --- | --- | --- |
| `Connected apps` | 一张连续的应用列表。每行左侧为应用图标和名称，右侧为活动／非活动状态或唯一主行动。 | 仅一个项目显示 `当前使用`；未初始化项目显示 `连接并初始化`，已有保留身份的项目显示 `切换到…`，不使用虚假的活跃数据。 |
| `General` | 一张按细线分隔的设置清单，直接展示群聊条件、节奏和语言选择，并由“保存更改”统一提交。 | 不做统计组件、通知开关或营销 Banner。 |
| `How Friday works for you` | 一张连续的个人资料表单：姓名、@ 别名与一个多行 Prompt。 | Prompt 是唯一的个人化工作说明输入，不再拆分判断、表达和工作边界。 |

#### 4.3.4 控件、反馈与动效

- 行动按钮采用低饱和浅色底或近黑主按钮，文案使用动作词，例如 `连接应用`、`保存更改`、`重新连接`。页面同一时刻只保留一个明确主行动。
- 开关只出现在用户确实可以控制的项目中；开关的开、关状态需要明显区分，且不能仅依赖颜色。当前仅群聊 `@所有人` 与免打扰使用开关。
- 保存成功在相关行附近给出短暂、安静的确认，例如 `已保存`；加载和失败也在原位置反馈，避免全局 Toast 打断阅读。
- 左栏切换和右栏内容更新使用快速、低存在感的淡入或位置过渡；不使用弹跳、缩放、骨架屏大面积闪烁或装饰性动画。

#### 4.3.5 明确避免

- 不做全屏设置页、深层卡片嵌套、渐变背景、玻璃拟态、数据仪表盘、营销横幅或技术状态码。
- 不在默认视图堆叠多组 Toggle，也不将所有设置项做成独立白卡。
- 不将系统 Prompt、原始资料、内部风险分数或实现术语作为“高级设置”暴露给用户；用户可编辑的个人 Prompt 是唯一例外。

### 4.4 页面入口与返回

| 入口 | 到达位置 |
| --- | --- |
| 左侧导航 `Settings` | 打开 Settings 工作区，首次默认到 `Connected apps`。 |
| Message 的连接提示 | 用户可从 Message 的“前往 Settings”入口打开 Settings；当前不伪造真实连接异常。 |
| 首次初始化的 Connector 选择完成后 | 流程继续建立 Memory；连接的后续管理在 Settings 的 `Connected apps` 列表中完成。 |
| Settings 选择新 Connector | 先显示切换确认。确认后关闭 Settings，进入新身份的两步初始化：建立 Memory（第 1 步）→ 设置工作风格（第 2 步）。若该身份已经完成初始化，直接恢复其 Message。 |
| 铃铛的工作风格完成通知 | 打开 Settings 工作区并直接进入 `How Friday works for you` 的个人资料／个人风格位置。仅在后台真实完成后出现，不由前端计时器伪造。 |

## 5. 功能需求

### 5.1 P0：Connected apps

#### 5.1.1 首页列表

当前本地演示展示钉钉、飞书与 Teams；不展示 Slack、Gmail、企业微信或任何未纳入首期的应用。生产可用渠道仍须以真实授权、读取和发送闭环为准。无论可用 Connector 数量，工作空间同一时刻只能绑定一个活动 Connector。

| 状态 | 行内容 | 用户操作 |
| --- | --- | --- |
| 无活动 Connector | 应用图标、名称、`连接并初始化` | 选择一个 Connector 后进入首次三步初始化。 |
| 连接中 | 应用图标、名称、`正在连接…` | 显示不可重复点击的加载状态。 |
| 当前活动 | 应用图标、名称、`当前使用` | 该 Connector 是当前 Message、时钟和铃铛的唯一数据来源。 |
| 已保留、非活动 | 应用图标、名称、`已初始化`与`切换到…` | 点击后先确认切换；若已完成初始化，直接恢复该身份，不重复建立 Memory 或工作风格。 |
| 新的非活动 Connector | 应用图标、名称、`切换并初始化` | 点击后先确认切换；确认后跳过连接选择，进入两步初始化。 |
| 需要处理 | 应用图标、名称、`需要重新连接` | 点击进入详情并执行 `重新连接`。 |

#### 5.1.2 切换活动 Connector

当用户在已有活动 Connector 的情况下选择另一 Connector，必须先展示确认弹窗：

> **切换到飞书？**
>
> Friday 将停止把钉钉作为当前读取和处理来源。钉钉的 Memory、工作风格、历史记录和已提交后台任务会保留并继续独立完成；它们不会合并到飞书。
> `[取消] [切换到飞书]`

- 取消：保持原 Connector、Message、时钟和铃铛状态不变。
- 确认：旧身份变为非活动；新身份成为唯一活动 Connector。
- 新身份从未初始化：关闭 Settings，跳过原 Onboarding 连接选择，进入“建立 Memory → 设置工作风格”的两步流程。
- 新身份已初始化：关闭 Settings，恢复其 Message、Memory、工作风格、后台任务和未读通知；不重新播放初始化或庆祝。
- 旧身份正在运行的后台任务：继续完成；在用户切回前不进入当前身份的时钟、铃铛或 Message。

#### 5.1.3 后续目标：Connector 详情页（当前未实现）

Connector 详情在 Settings 工作区的右栏内打开，左栏保持可见。它不打开第二层弹窗，也不离开当前工作台上下文。页面结构固定如下：

```text
‹ Settings

钉钉                                  已连接
上次验证：刚刚

Friday 会使用钉钉来：
• 处理直接指向你的工作消息
• 阅读已授权的关联资料，以理解上下文
• 将工作对话中形成的事项沉淀到 Friday

工作范围
群聊：仅在同事明确 @ 你时处理
私聊：按当前工作状态处理

数据范围
工作消息与其关联、已授权的资料
已沉淀的 Memory：保留

当前运行状态：正式状态
在 Message 中管理  →

断开钉钉
```

产品规则：

- `Friday 会使用 {应用} 来` 是能力介绍，不提供单项能力开关。
- `工作范围` 解释当前规则；其中 `@所有人` 是否触发，由 General → `群聊处理条件` 统一设置。
- `当前运行状态` 只读，并链接到 Message；详情页不得提供测试、正式或暂停控制。
- 无活动 Connector 时，应用显示同样的能力介绍与 `连接并初始化 {应用}` 主按钮；已保留的非活动身份显示 `切换到 {应用}`。两者都不得显示虚构的授权时间、资料数量或运行记录。
- 连接异常时，以用户语言说明 `Friday 暂时无法继续使用 {应用}。请重新连接后再试。`，主行动为 `重新连接`。

#### 5.1.4 断开连接

用户点击 `断开 {应用}` 后，展示确认弹窗：

> **断开钉钉？**  
> Friday 将停止读取和处理新的钉钉内容。此前从钉钉沉淀的 Memory 会保留；你可以稍后在 Memory 中单独管理它。  
> `[取消] [断开钉钉]`

确认断开后的结果：

- 应用列表立即显示 `连接并初始化`；
- Friday 停止从该应用新增读取、判断和回复；
- 既有 Memory、历史事件、任务与反馈保留；
- 若该应用是唯一已连接应用，Message 显示清楚的连接缺失状态，并引导用户回到 Settings 连接应用；
- 断开不是删除资料。删除资料属于后续 Memory PRD 的独立能力。

### 5.2 P0：General

General 在同一面板直接显示群聊处理条件、工作节奏和语言，并由“保存更改”统一提交；不展示或保存通知偏好。

#### 5.2.1 群聊处理条件

首页摘要默认是 `仅 @ 我`。

详情面板内容：

| 项目 | 默认值 | 规则 |
| --- | --- | --- |
| `群聊中 @ 我` | 始终处理 | 固定开启，不提供关闭开关。Friday 只将明确指向用户的群聊消息作为候选。 |
| `群聊中 @ 所有人` | 不处理 | 用户可切换开启或关闭。 |

首次开启 `@所有人` 时必须二次确认：

> **让 Friday 响应 @ 所有人？**  
> 当群里 @ 所有人时，Friday 无法确认消息是否只针对你。只有明确的工作请求才会被处理。  
> `[取消] [仍然开启]`

开启后的规则：

- 在测试状态下，Friday 仅生成回复，不发送；
- 在正式状态下，Friday 仍须满足服务端发送门禁后才可回复；
- 关闭后不再将新的 `@所有人` 消息纳入处理范围；
- 无论是否开启，普通群聊与非工作系统通知均不应被处理。

#### 5.2.2 工作节奏

首页摘要格式为 `等待 {时长}`，默认 `等待 5 分钟`。

详情面板包含两项：

| 项目 | 默认值 | 用户可选项 | 生效结果 |
| --- | --- | --- | --- |
| `先等我处理` | 5 分钟 | 1 分钟、5 分钟、10 分钟 | 在等待期间，如用户已亲自回复，Friday 不再介入。 |
| `免打扰时段` | 未设置 | 设置开始和结束时间，或关闭 | 仅在正式状态下生效；时段内 Friday 仍可生成回复，但不会自动发送。 |

页面文案：

> **给你留出处理时间**  
> Friday 会先等你亲自回应。你已经回复后，它会保持安静。

免打扰时段跨越午夜时，应以一个连贯的时间段展示，例如 `19:00–09:00`，不要求用户理解日期或时区概念。

### 5.3 P0：User Profile

#### 5.3.1 个人资料与 Prompt

```text
Friday 如何为你工作
用一段 Prompt 告诉 Friday 如何为你工作。

个人资料
姓名                         陈思睿
同事如何 @ 我               @思睿、@CS

Prompt
先看目标与事实；信息不足先追问；不轻易替人承诺。

结论优先，简短直接；复杂事项给出下一步。

涉及关键判断、对外承诺或敏感议题时，必须交由本人确认。

[ 保存身份信息 ]
```

产品规则：

- `姓名` 与 `同事如何 @ 我` 可编辑；别名以标签形式添加和删除。保存后，Friday 用这些信息识别明确指向用户的群聊消息。
- Prompt 是唯一的个人化工作说明输入，用于统一表达判断、表达和处理边界；不再拆分为三项只读蒸馏结果。
- 初始值沿用原有三项文案；用户可直接修改多行内容，并通过“保存身份信息”保存。
- 当前前端仅将该 Prompt 保存到浏览器本地演示设置；它不代表真实模型配置、授权或外发能力已经生效。
- 页面不提供 Memory／Feedback 跳转、安全边界说明或通知偏好。系统执行约束不在此页显示或编辑。
- 不展示原始资料、系统 Prompt 或内部证据。

## 6. 状态模型与跨页面规则

| 状态 | Settings 的呈现 | 其他页面的责任 |
| --- | --- | --- |
| 无活动 Connector | Connectors 提示 `连接并初始化`；General 和个人资料仍可阅读 | 首次初始化引导选择 Connector。 |
| 切换到新 Connector | Settings 先确认切换；确认后新身份成为唯一活动身份 | 未初始化身份走两步初始化；已初始化身份直接恢复。 |
| 非活动身份后台任务完成 | 不在当前身份显示时钟、红点或完成通知 | 切回该身份后恢复其任务记录和未读提醒。 |
| Trial／正式状态 | 当前 Settings 不展示或修改该状态 | 真实能力落地后由 Onboarding／Message 呈现，Settings 保持只读摘要。 |
| 暂停 | 当前前端不提供恢复或暂停操作 | 真实运行能力落地后在 Message／后端控制面处理。 |
| 连接异常 | 当前前端可呈现 `需要重新连接` 和主行动 | 真实异常应在 Message 中以用户语言说明。 |
| 免打扰时段 | 工作节奏显示当前时段 | 真实发送能力落地后由服务端执行，前端不能伪造“未发送”。 |
| 个人 Prompt | 姓名、@ 别名和 Prompt 可编辑并本地保存 | 真实个性化执行、版本与审计由后端能力定义；Settings 不伪造已经生效。 |

## 7. 明确不做

1. 不在 Settings 放置 `测试 / 正式 / 暂停` 开关。
2. 不为消息回复、Memory、任务沉淀等 Connector 既定能力提供单项开关。
3. 不将个人 Prompt 拆回“判断方式／表达方式／工作边界”三项，也不展示 Memory／Feedback 跳转。
4. 不展示或配置系统执行约束、安全边界详情与通知偏好。
5. 不展示模型、系统 Prompt、数据库、扫描频率、重试、工具、日志或其他工程配置。
6. 不展示未纳入首期范围的 Connector。
7. 不在 Settings 放置任务催办、会后跟进或项目管理；它们属于 Message 与 Task 的后续功能设计。
8. 不做回复签名、转交话术、外部反馈链接等低频高级设置；如需开放，应在验证真实用户需求后作为独立迭代。
9. 不允许同时绑定多个活动 Connector，也不在切换时自动合并、复制或删除不同“连接器＋账号”的资料与工作方式。

## 8. P0 验收清单

### Connectors

- [ ] 用户可在 Settings 查看钉钉、飞书、Teams 的无活动、连接中、当前活动、已初始化非活动和需要处理状态。
- [ ] 工作空间任一时刻最多有一个活动 Connector；选择另一个 Connector 前必须确认切换，取消不改变当前身份。
- [ ] 选择从未初始化的 Connector 后，跳过原连接选择并进入两步初始化；选择已初始化身份后直接恢复，不重复初始化。
- [ ] 当前应用在同一列表内完成模拟连接、切换、重连和断开；Connector 详情页不应被误报为已实现。
- [ ] 用户可断开应用，并在确认弹窗中明确知道既有 Memory 会保留。
- [ ] 切换或断开不自动合并或删除工作身份；非活动身份已经提交的后台任务继续完成，且通知只在所属身份中显示。
- [ ] 用户无法在 Connector 详情中打开或关闭单项能力，也无法在此改变测试、正式或暂停状态。

### General

- [ ] General 仅展示“群聊处理条件”“工作节奏”与语言，不展示通知设置或统计摘要。
- [ ] “@所有人”默认关闭，首次开启必须二次确认。
- [ ] 用户可选择 1、5、10 分钟的等待时长；默认值为 5 分钟。
- [ ] 用户可设置或关闭免打扰时段；时段内正式状态不自动发送。

### Personalized capabilities

- [ ] “How Friday works for you”是一张连续的个人资料表单，不出现并列能力卡或独立安全边界区。
- [ ] 用户可编辑姓名、@ 别名与一个多行 Prompt；保存后显示“已保存”。
- [ ] Prompt 的默认内容覆盖原来的判断、表达和工作边界三类说明。
- [ ] User Profile 不展示原始资料、系统 Prompt 或内部证据。
- [ ] 后台工作风格真实完成后的铃铛通知可直接打开 User Profile；Settings 不自行制造完成通知或红点。
- [ ] 页面不提供 Memory／Feedback 跳转、安全边界说明或通知偏好。

### 一致性

- [ ] 用户在 Settings 中始终能找到当前值、修改入口或明确的不可修改说明。
- [ ] 所有修改都有保存成功、加载中或失败反馈；页面不出现无响应状态。
- [ ] 所有状态使用用户语言，不出现技术配置名、内部状态码或开发术语。
- [ ] Settings 与 Message、Memory、Feedback 的职责不重叠，跨页链接去向明确。
