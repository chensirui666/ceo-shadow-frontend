## 1. 背景与目标

### 1.1 背景

Friday 不应成为需要管理大量参数的 AI 后台。用户进入 Settings 的目的，是长期回答几个稳定的问题：

1. Friday 在哪些工作应用中代表我工作？
2. 它应该先等我多久？什么时候保持安静？
3. 它如何识别“我”，以及何时一定把决定交还给我？
4. 出现需要本人处理的情况时，怎样提醒我？

当天是否处于测试、正式或暂停状态，由 Home 控制；工作资料与来源属于 Memory；具体反馈属于 Feedback。Settings 只管理这些跨天仍持续生效的偏好和边界。

### 1.2 目标

用户可在一个简洁页面中：

- 接入、查看和断开钉钉或飞书；
- 调整群聊触发条件、回复节奏和提醒偏好；
- 查看 Friday 当前使用的个人工作画像与不可突破的安全边界；
- 明确知道哪些能力可调整，哪些安全规则始终生效。

### 1.3 成功标准

用户无需帮助文档即可回答：

1. Friday 目前连接了哪些应用？
2. 什么情况下 Friday 会在群里回应？
3. Friday 会给我留多久亲自回复？
4. 哪些情况它绝不会自行决定？
5. 为什么某条消息会或不会提醒我？

## 2. 体验原则

1. **设置应当是长期偏好，而非日常操作。** 测试、正式和暂停只在 Home 管理。
2. **先展示摘要，再按需进入详情。** 主页面只显示当前值；复杂说明和操作进入详情页或轻量面板。
3. **连接是二元关系，不是能力开关。** 用户连接应用后即可获得该应用的既定能力；断开后即停止后续读取和处理。
4. **用户看到规则，不看到 Prompt。** 个人画像和安全边界可读、可验证，但不暴露原始资料、内部 Prompt 或系统配置。
5. **风险默认收紧。** `@所有人` 默认不处理；免打扰时段默认不正式发送；安全边界不可关闭。

## 4. 信息架构

### 4.1 信息架构

Settings 的一级内容只有三个入口；左侧导航只负责切换右侧内容，不把所有设置堆在一张长页面中。

```text
SETTINGS
  Connected apps
  General
  ─────────────
  How Friday works for you
    └─ User Profile / Safety Boundaries（由右侧概览卡进入详情）
```

| 左侧导航项 | 右侧默认内容 | 进一步进入 |
| --- | --- | --- |
| `Connected apps` | 钉钉、飞书的连接状态与主行动 | 某一应用的详情与断开确认。 |
| `General` | 群聊处理条件、工作节奏、通知的当前值 | 对应设置项的编辑内容。 |
| `How Friday works for you` | User Profile 与 Safety Boundaries 两张能力卡 | 单张卡的解释性详情。 |

### 4.2 设置工作区（Modal Settings Workspace）

Settings 不是替换整个产品工作台的独立页面，而是一个从当前页面上方打开的**居中设置工作区**。这是对参考图中“主界面仍然可见、设置成为专注前景”的交互抽象。

- 用户从全局侧栏点击 `Settings` 后，当前工作台保留在后方；后方内容降低对比度并覆盖一层暖灰遮罩，仍可辨认但不可操作、不可滚动。
- 前景设置工作区使用完整、安静的浅色表面和柔和圆角；通过克制的浮层阴影与后方界面分层，而非毛玻璃、渐变或厚重描边。
- 工作区固定为左右两栏：左栏为局部 Settings 导航，右栏为当前选中内容。切换左栏项目时，只替换右栏内容；全局侧栏与后方页面均不发生跳转。
- 右上角提供低干扰的关闭入口。用户按 `Esc` 或点击遮罩也可关闭；若当前有未保存的改动，先询问用户“放弃更改”或“继续编辑”。关闭后回到打开前的工作台状态。
- 应用详情、General 的编辑内容、User Profile 与 Safety Boundaries 的详情均在**同一个工作区的右栏**内打开，使用返回链接回到上一层；不得再叠加第二层弹窗。
- 工作区再次打开时保留用户上次查看的一级栏目；首次打开默认进入 `Connected apps`，因为连接状态是最具行动性的设置。

### 4.3 视觉与内容排布

整体视觉采用“安静的编辑式设置面板”，以层级、留白和文字建立重点，而不是用大量卡片制造仪表盘感。

#### 4.3.1 分层与底色

- 后方工作台：保留当前页面原有布局，仅以半透明暖灰遮罩退场；不得模糊到无法识别，也不得与前景竞争注意力。
- 前景工作区：使用偏暖的白色主表面。左栏比右栏略深一阶，形成导航区与内容区的自然分界；中间使用一条细分割线，而不是明显边框。
- 内容分组：General 的设置行放入一块低对比度的浅石色容器；容器内用细线划分行。它应像一张整理良好的偏好清单，而不是多张独立卡片。
- 仅使用黑色、暖灰、浅石色作为主色；成功/始终生效可使用极少量深青绿色作为状态提示。危险操作只在确认区域使用克制的警示色。

#### 4.3.2 导航与标题

- 左栏顶部以小号全大写 `SETTINGS` 作为栏目标题；一级导航项依次为 `Connected apps`、`General`、`How Friday works for you`。个人能力详情不额外出现在左栏，避免导航变成设置树。
- 每个导航项使用简洁线性图标、名称和充足的点击区域。当前项以浅米色填充和清晰文字强调，不使用高饱和色块、粗边框或左侧彩色竖线。
- 右栏标题使用克制的编辑式衬线字体表达章节层级，例如 `General`、`Connected apps`、`How Friday works for you`；说明、表单、状态与操作均使用清晰的无衬线字体。衬线字体只用于标题，不能形成营销海报式的大字。
- 标题下只放一句解释当前区域目的的辅助文案；不重复介绍 Friday，也不堆叠产品口号。

#### 4.3.3 三个一级内容的呈现

| 内容 | 右栏呈现方式 | 视觉重点 |
| --- | --- | --- |
| `Connected apps` | 一张连续的应用列表。每行左侧为应用图标和名称，右侧为连接状态或唯一主行动。 | 已连接使用文字状态与小型状态点；未连接显示 `连接应用`，不使用虚假的活跃数据。 |
| `General` | 一张按细线分隔的设置清单。每行展示标题、简短说明、当前值或 `Change` 行动。 | 默认页保持摘要，不一次展示所有开关；用户进入具体项后才看到选择控件与保存操作。 |
| `How Friday works for you` | 两张并列但不厚重的能力卡：User Profile、Safety Boundaries。 | 卡片用轻微底色、细边线与简短摘要建立可点击性；不要把它们设计成统计组件或营销 Banner。 |

#### 4.3.4 控件、反馈与动效

- 行动按钮采用低饱和浅色底或近黑主按钮，文案使用动作词，例如 `连接应用`、`保存更改`、`重新连接`。页面同一时刻只保留一个明确主行动。
- 开关只出现在用户确实可以控制的项目中；开关的开、关状态需要明显区分，且不能仅依赖颜色。`Safety Boundaries` 不出现开关。
- 保存成功在相关行附近给出短暂、安静的确认，例如 `已保存`；加载和失败也在原位置反馈，避免全局 Toast 打断阅读。
- 左栏切换和右栏内容更新使用快速、低存在感的淡入或位置过渡；不使用弹跳、缩放、骨架屏大面积闪烁或装饰性动画。

#### 4.3.5 明确避免

- 不做全屏设置页、深层卡片嵌套、渐变背景、玻璃拟态、数据仪表盘、营销横幅或技术状态码。
- 不在默认视图堆叠多组 Toggle，也不将所有设置项做成独立白卡。
- 不将系统 Prompt、原始资料、内部风险分数或实现术语作为“高级设置”暴露给用户。

### 4.4 页面入口与返回

| 入口 | 到达位置 |
| --- | --- |
| 左侧导航 `Settings` | 打开 Settings 工作区，首次默认到 `Connected apps`。 |
| Home 的连接异常提示 | 打开 Settings 工作区中的对应 Connector 详情。 |
| Onboarding 第一步完成后 | 打开 Settings 工作区中的已连接 Connector 详情或 `Connected apps`。 |
| User Profile 的 `去 Memory 查看来源` | Memory 页面。 |
| User Profile 的 `去 Feedback 校准不准确的地方` | Feedback 页面。 |

## 5. 功能需求

### 5.1 P0：Connected apps

#### 5.1.1 首页列表

MVP 只展示钉钉与飞书；不提前展示 Slack、Gmail、企业微信或任何未纳入首期的应用。

| 状态 | 行内容 | 用户操作 |
| --- | --- | --- |
| 未连接 | 应用图标、名称、`连接应用` | 点击进入应用详情，开始连接。 |
| 连接中 | 应用图标、名称、`正在连接…` | 显示不可重复点击的加载状态。 |
| 已连接 | 应用图标、名称、`已连接` | 点击进入应用详情。 |
| 需要处理 | 应用图标、名称、`需要重新连接` | 点击进入详情并执行 `重新连接`。 |

#### 5.1.2 Connector 详情页

Connector 详情在 Settings 工作区的右栏内打开，左栏保持可见。它不打开第二层弹窗，也不离开当前工作台上下文。页面结构固定如下：

```text
‹ Settings

钉钉                                  已连接
上次验证：刚刚

Friday 会使用钉钉来：
• 处理直接指向你的工作消息
• 阅读已授权的关联资料，以理解上下文
• 将工作对话中形成的事项沉淀到 Friday

工作范围
群聊：仅在同事明确 @ 你时处理
私聊：按当前工作状态处理

数据范围
工作消息与其关联、已授权的资料
已沉淀的 Memory：保留

当前运行状态：正式状态
在 Home 中管理  →

断开钉钉
```

产品规则：

- `Friday 会使用 {应用} 来` 是能力介绍，不提供单项能力开关。
- `工作范围` 解释当前规则；其中 `@所有人` 是否触发，由 General → `群聊处理条件` 统一设置。
- `当前运行状态` 只读，并链接到 Home；详情页不得提供测试、正式或暂停控制。
- 未连接应用显示同样的能力介绍与 `连接 {应用}` 主按钮，但不得显示虚构的授权时间、资料数量或运行记录。
- 连接异常时，以用户语言说明 `Friday 暂时无法继续使用 {应用}。请重新连接后再试。`，主行动为 `重新连接`。

#### 5.1.3 断开连接

用户点击 `断开 {应用}` 后，展示确认弹窗：

> **断开钉钉？**  
> Friday 将停止读取和处理新的钉钉内容。此前从钉钉沉淀的 Memory 会保留；你可以稍后在 Memory 中单独管理它。  
> `[取消] [断开钉钉]`

确认断开后的结果：

- 应用列表立即显示 `连接应用`；
- Friday 停止从该应用新增读取、判断和回复；
- 既有 Memory、历史事件、任务与反馈保留；
- 若该应用是唯一已连接应用，Home 显示清楚的连接缺失状态，并引导用户回到 Settings 连接应用；
- 断开不是删除资料。删除资料属于后续 Memory PRD 的独立能力。

### 5.2 P0：General

General 默认只显示三条摘要行。点击任一行后，右栏进入对应编辑内容；用户保存后返回 General 摘要并更新当前值。

#### 5.2.1 群聊处理条件

首页摘要默认是 `仅 @ 我`。

详情面板内容：

| 项目 | 默认值 | 规则 |
| --- | --- | --- |
| `群聊中 @ 我` | 始终处理 | 固定开启，不提供关闭开关。Friday 只将明确指向用户的群聊消息作为候选。 |
| `群聊中 @ 所有人` | 不处理 | 用户可切换开启或关闭。 |

首次开启 `@所有人` 时必须二次确认：

> **让 Friday 响应 @ 所有人？**  
> 当群里 @ 所有人时，Friday 无法确认消息是否只针对你。只有明确的工作请求才会被处理。  
> `[取消] [仍然开启]`

开启后的规则：

- 在测试状态下，Friday 仅生成草稿，不发送；
- 在正式状态下，Friday 可根据其他安全边界决定是否回复；
- 关闭后不再将新的 `@所有人` 消息纳入处理范围；
- 无论是否开启，普通群聊与非工作系统通知均不应被处理。

#### 5.2.2 工作节奏

首页摘要格式为 `等待 {时长}`，默认 `等待 5 分钟`。

详情面板包含两项：

| 项目 | 默认值 | 用户可选项 | 生效结果 |
| --- | --- | --- | --- |
| `先等我处理` | 5 分钟 | 1 分钟、5 分钟、10 分钟 | 在等待期间，如用户已亲自回复，Friday 不再介入。 |
| `免打扰时段` | 未设置 | 设置开始和结束时间，或关闭 | 仅在正式状态下生效；时段内 Friday 仍可生成草稿，但不会自动发送。 |

页面文案：

> **给你留出处理时间**  
> Friday 会先等你亲自回应。你已经回复后，它会保持安静。

免打扰时段跨越午夜时，应以一个连贯的时间段展示，例如 `19:00–09:00`，不要求用户理解日期或时区概念。

#### 5.2.3 通知

首页摘要为 `3 项已开启`，仅统计当前打开的通知数量。

详情面板提供三个独立开关，均默认开启：

| 通知 | 说明 | 关闭后的结果 |
| --- | --- | --- |
| `需要我接管` | Friday 需要用户亲自判断、回复或处理。 | 事项仍进入 Home，但不主动提醒。 |
| `连接需要处理` | 已连接应用需要重新连接或授权。 | 连接状态仍在 Settings 与 Home 显示，但不主动提醒。 |
| `回复未成功发送` | Friday 已产生结果但未能完成正式发送。 | 失败仍保留在 Home 事件中，但不主动提醒。 |

通知不包含营销信息、日常效率统计或重复提醒。通知文案必须包含发生了什么及一个清楚的下一步，例如：`钉钉需要重新连接。前往 Settings 处理。`

### 5.3 P0：User Profile

#### 5.3.1 首页能力卡

卡片内容：

| 区域 | 文案与规则 |
| --- | --- |
| 标题 | `User Profile` |
| 描述 | `Friday 已学习你的判断、表达与工作方式。` |
| 摘要 | 最多三条短标签，例如 `结论优先`、`不轻易承诺`、`信息不足先追问`。没有可用画像时展示 `正在建立你的工作画像。` |
| 元信息 | `已更新 · 今天`；无可用画像时为 `尚未建立`。 |
| 行动 | 整张卡可点击，进入 User Profile 详情页。 |

#### 5.3.2 User Profile 详情页

```text
‹ Settings

User Profile
Friday 如何理解陈思睿

更新于今天 · 来自已授权工作资料、历史回复与反馈

我的工作身份
姓名                         陈思睿              [编辑]
同事如何 @ 我               @思睿、@CS          [编辑]

我的判断方式
先看目标与事实；信息不足先追问；不轻易替人承诺。

我的表达方式
结论优先，简短直接；复杂事项给出下一步。

我的工作边界
涉及关键判断、对外承诺或敏感议题时，必须交由本人确认。

[ 去 Memory 查看来源 ]  [ 去 Feedback 校准不准确的地方 ]
```

产品规则：

- `姓名` 与 `同事如何 @ 我` 可编辑；别名以标签形式添加和删除。保存后，Friday 用这些信息识别明确指向用户的群聊消息。
- 判断方式、表达方式与工作边界是用户可读的蒸馏结果，MVP 不允许用户直接编辑正文。
- 画像由已授权工作资料、历史回复和反馈持续蒸馏得到，并作为 Friday 的个人化工作指导。底层可由 Nuwa 生成 Profile Prompt，但产品页绝不显示原始 Prompt、原始语料或内部证据。
- 用户认为画像不准确时，应从详情页前往 Feedback 或 Memory 校准，不在当前页填写长表单。
- 该页面呈现“Friday 当前如何理解用户”；Memory 页面呈现“这些理解来自哪些资料与主题”。两者职责不可混淆。

### 5.4 P0：Safety Boundaries

#### 5.4.1 首页能力卡

| 区域 | 文案与规则 |
| --- | --- |
| 标题 | `Safety Boundaries` |
| 描述 | `Friday 始终会把关键决定交还给你。` |
| 摘要 | `承诺 · 敏感事项 · 信息不足 · 要求本人` |
| 元信息 | `始终生效` |
| 行动 | 整张卡可点击，进入详情页。 |

#### 5.4.2 Safety Boundaries 详情页

```text
‹ Settings

Safety Boundaries

Friday 不会自行：
• 代表你作出对外承诺、价格、合同或关键决策
• 处理人事、财务、客户等敏感议题
• 在关键信息、材料或对象不明确时猜测
• 在对方明确要求你本人时继续代答

遇到以上情况，Friday 会：
生成清晰的转交说明，并在 Home 通知你处理。

这些规则始终生效。
```

产品规则：

- Safety Boundaries 是始终有效的系统规则，不提供关闭、删除或编辑入口。
- 页面用自然语言说明 Friday 的行为承诺，不出现 `System Prompt`、规则代码或内部风险评分。
- 底层规则由 System Prompt 约束；任何产品内“正式状态”均不得覆盖这组边界。
- 当 Friday 因安全边界不发送或转交用户时，Home 事件应说明可理解的原因，例如 `需要你确认后再回复`，而非展示内部规则名称。

## 6. 状态模型与跨页面规则

| 状态 | Settings 的呈现 | 其他页面的责任 |
| --- | --- | --- |
| 无应用连接 | Connectors 提示 `连接应用`；General 和能力卡仍可阅读 | Home 引导连接应用。 |
| 测试状态 | Connector 详情只读显示 `测试状态`，并链接 Home | Home 生成、展示与收集草稿反馈；不发送。 |
| 正式状态 | Connector 详情只读显示 `正式状态`，并链接 Home | Home 管理正式运行与暂停。 |
| 暂停 | Connector 保持连接；Settings 不提供恢复按钮 | Home 恢复或维持暂停。 |
| 连接异常 | Connector 显示 `需要重新连接` 与主行动 | Home 提醒用户并跳转到对应详情。 |
| 免打扰时段 | 工作节奏显示当前时段 | Home 与事件流将自动回复显示为草稿或未发送。 |

## 7. 明确不做

1. 不在 Settings 放置 `测试 / 正式 / 暂停` 开关。
2. 不为消息回复、Memory、任务沉淀等 Connector 既定能力提供单项开关。
3. 不允许编辑 User Profile 正文；用户通过 Memory 和 Feedback 校准。
4. 不允许关闭或编辑 Safety Boundaries。
5. 不展示模型、Prompt、数据库、扫描频率、重试、工具、日志或其他工程配置。
6. 不展示未纳入首期范围的 Connector。
7. 不在 Settings 放置任务催办、会后跟进或项目管理；它们属于 Home 与 Tasks 的后续功能设计。
8. 不做回复签名、转交话术、外部反馈链接等低频高级设置；如需开放，应在验证真实用户需求后作为独立迭代。

## 8. P0 验收清单

### Connectors

- [ ] 用户可在 Settings 查看钉钉、飞书的未连接、连接中、已连接和需要处理状态。
- [ ] 用户可进入每个应用的独立详情页，看到能力介绍、工作范围、数据范围与运行状态入口。
- [ ] 用户可断开应用，并在确认弹窗中明确知道既有 Memory 会保留。
- [ ] 用户无法在 Connector 详情中打开或关闭单项能力，也无法在此改变测试、正式或暂停状态。

### General

- [ ] 首页仅展示 `群聊处理条件`、`工作节奏`、`通知` 三条摘要，不展开大量开关。
- [ ] `@所有人` 默认关闭，首次开启必须二次确认。
- [ ] 用户可选择 1、5、10 分钟的等待时长；默认值为 5 分钟。
- [ ] 用户可设置或关闭免打扰时段；时段内正式状态不自动发送。
- [ ] 用户可独立开关三种真正需要采取行动的通知。

### Personalized capabilities

- [ ] User Profile 与 Safety Boundaries 以并列能力卡呈现，包含标题、简短描述、摘要和进入详情的入口。
- [ ] User Profile 详情支持编辑姓名和 @ 别名，但不支持编辑蒸馏结果正文。
- [ ] User Profile 不展示原始资料、Prompt 或内部证据。
- [ ] Safety Boundaries 详情清楚说明四类转交情形，且不提供关闭或编辑入口。

### 一致性

- [ ] 用户在 Settings 中始终能找到当前值、修改入口或明确的不可修改说明。
- [ ] 所有修改都有保存成功、加载中或失败反馈；页面不出现无响应状态。
- [ ] 所有状态使用用户语言，不出现技术配置名、内部状态码或开发术语。
- [ ] Settings 与 Home、Memory、Feedback 的职责不重叠，跨页链接去向明确。
