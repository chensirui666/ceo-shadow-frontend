## 1. 一句话定义

**Task 是 Friday 从一条 Message 中识别出的、需要本人在外部工具完成的一件工作。**

Task 页不让用户在 Friday 里写代码、上传交付物或完成实际工作；它提供足够上下文，帮助用户理解该做什么、为什么做、还差什么，然后去 IDE、钉钉或其他正确的工具完成。

## 2. 背景与目标

### 2.1 背景

聊天、会议、审批和文档会带来后续工作。它们若只留在消息流中，很容易被新的信息淹没；但把 Friday 做成另一套项目管理或待办工具，也会偏离“最小注意力、在原工具工作”的定位。

Task 的角色因此是可回溯的工作上下文，不是任务执行环境。它保存 Friday 从来源 Message 提炼的工作说明，用户自行决定并在外部工具完成；第一版不依赖连接器或 Agent 去判断外部世界是否真的完成。

### 2.2 用户目标

用户进入 Task 后，应能：

1. 查看全部历史 Task，而不只看未完成项；
2. 快速扫读 Task 名称、截止时间、紧急程度、发布者和状态；
3. 进入详情，理解背景、具体行动和 Friday 为什么提炼出这件事；
4. 回看来源 Message 的原始问题、判断和回答；
5. 在自己完成外部工作后，手动标记完成或取消，不被缺失的连接器错误阻塞。

### 2.3 成功标准

- 用户不需要翻回群聊或会议记录，也能理解每个 Task 的背景和具体行动。
- Task 卡片适合按时间快速扫描，详情承担完整上下文，不重复堆叠长文本。
- Task 仅由 Friday 从 Message 自动创建；页面没有手动新建或编辑入口。
- 用户可自行完成或取消，不依赖 Friday 推断外部完成证据。
- Task 不被组织成项目、看板或通用协作系统。

## 3. Task 定义与创建规则

### 3.1 定义

Task 是一个需要本人在外部工具完成的工作说明。它可以来自老板在会议上的明确要求、群聊中的后续请求、审批处理要求或文档修改要求。

Task 不是让本人给 Friday 补充材料的表单，也不承诺本人完成后 Friday 会自动继续执行。它的价值是让本人始终知道工作来由、当前处境和下一步。

### 3.2 创建与关联

- Task 只能由 Friday 处理 Message 时自动创建；不支持手动新建。
- 一条 Message 可以创建多个 Task。
- 一条 Task 只关联一条来源 Message；第一版不自动合并来自多个 Message 的相似 Task，避免错误归并。
- Task 创建不改变来源 Message 的状态。Friday 若已完成对原始信息的处理，Message 可以为`已处理`，即使相关 Task 尚待外部完成。

### 3.3 状态

| 状态 | 含义 |
| --- | --- |
| 待完成 | 尚未由用户手动标记完成或取消。 |
| 已完成 | 用户已在 Friday 中标记完成；不代表 Friday 已自动核验外部证据。 |
| 已取消 | 用户确认不再继续这项工作；保留在历史中。 |

完成和取消都是用户的个人状态标记：不触发 Friday、不会自动回写来源 Message、不会要求上传证据，也不提供“重新打开”操作。

## 4. 页面设计

### 4.1 默认视图与筛选

- 页面标题为`Task`。
- 默认展示全部 Task，按创建时间倒序排列，包含已完成和已取消历史。
- 顶部提供筛选：`全部 / 待完成 / 已完成 / 已取消`。
- 不按项目、渠道、发布者或紧急程度另建分组；这些信息仅用于扫读和未来检索，不改变第一版默认列表。

### 4.2 轻量 Task 卡片流

Task 首页采用轻量卡片流，而不是承载完整上下文的长卡片或看板。每条卡片显示：

| 字段 | 规则 |
| --- | --- |
| Task 名称 | Friday 从来源 Message 提炼的用户可读工作名称。 |
| DDL | 原始信息中有明确截止时间才显示；没有则不显示，不猜测。 |
| 紧急程度 | 原始信息有明确优先级或紧急要求才显示；没有则不显示，不猜测。 |
| 发布者 | 在来源 Message 中明确提出／派发这件事的人；无法识别时不显示，不把会议主持人或群主猜成发布者。 |
| 状态 | 待完成、已完成或已取消。 |
| 创建时间 | Friday 建立 Task 的时间。 |
| 操作 | `完成`、`取消`。已完成或已取消不再提供重新打开。 |

点击卡片进入详情。卡片不展开背景、来源全文、AI 推理、交付物或外部完成记录，保证列表用于快速扫读。

### 4.3 详情页

详情固定按以下顺序呈现：

1. **基础信息**：名称、DDL（如有）、紧急程度（如有）、发布者（如有）、状态、创建时间和完成／取消记录；
2. **背景信息**：这件工作所处的业务背景和当前情况；
3. **要做什么**：清楚、可行动的本人工作说明，以及仍缺少的关键条件；
4. **AI 思考**：Friday 为什么从来源 Message 中提炼出这项 Task，包含关键事实和判断边界；
5. **来源 Message**：只读展示原始问题、Friday 当时的判断和回答，帮助用户回到任务产生的完整语境。

`AI 思考`是面向用户的解释，不展示原始 Prompt、模型内部推理、工具调用或技术日志。

### 4.4 操作规则

- 用户在外部工具完成实际工作后，可在卡片或详情点击`完成`。
- 用户决定不再做时，可点击`取消`；取消不要求填写原因。
- 这两个操作只更新 Task 的用户状态。V1 不尝试验证 IDE、GitHub、钉钉、审批或其他外部工具中的真实结果。
- V1 不支持编辑标题、背景、DDL、紧急程度、发布者或 AI 思考，保留 Friday 自动提炼时的可追溯性。

### 4.5 空态与异常态

- 没有 Task 时显示：`Friday 会在处理 Message 时整理需要你完成的工作。`
- Task 列表加载或更新失败时，显示可读错误和`重试`，不把失败伪装成空列表。
- 缺失 DDL、紧急程度或发布者是正常数据状态，不显示`未知`或猜测值。

## 5. 与 Message、Memory、Feedback 的关系

| 对象 | Task 接收什么 | Task 不做什么 |
| --- | --- | --- |
| Message | 自动创建 Task 的来源、原始问题、Friday 判断和回答。 | 不回写或驱动来源 Message 状态；不复制所有处理审计。 |
| Memory | 形成背景与 AI 思考时可能用到的长期资料。 | 不在 Task 中编辑、上传或重复存储 Memory。 |
| Feedback | 对来源 Message 的 Friday 输出所记录的评价。 | 不把 Task 完成／取消当作 AI 质量反馈。 |

## 6. 关键用户流程

### 6.1 从会议产生 Task

1. 本人参会，会议结束后创建 Meeting Message；
2. Friday 识别会议中明确要求本人完成的工作；
3. Friday 完成本次可处理的会议回复或同步，并创建一个或多个 Task；
4. 用户在 Task 页查看名称、DDL、发布者和详情，随后去外部工具完成工作；
5. 用户回到 Friday 手动标记完成或取消。

### 6.2 查看工作来由

1. 用户在列表点击 Task；
2. 在详情依次查看背景、要做什么、AI 思考和来源 Message；
3. 用户不需要在 Friday 内执行工作，也无需阅读技术审计，即可判断下一步。

### 6.3 手动收尾

1. 用户在外部工具完成或放弃工作；
2. 在 Task 卡片或详情点击`完成`或`取消`；
3. Task 保留在历史和相应筛选项中，不支持重新打开，也不触发任何自动外部动作。

## 7. 数据与实现边界

页面应通过可替换的数据服务消费稳定的 Task 数据，至少包括：来源 Message、名称、创建时间、状态、可选 DDL、可选紧急程度、可选发布者、背景、行动说明、AI 思考、完成／取消时间。

当前前端 Projects／Tasks 使用本地 fixture 和浏览器会话状态。后续接入真实服务时，只替换数据服务；UI 不直接连接 IDE、GitHub、钉钉、飞书或其他外部工具，也不假设这些连接器存在。

## 8. 非目标

- 不提供项目、里程碑、看板、负责人分派、多人评论或任务协作；
- 不支持手动新建、编辑、合并或重新打开 Task；
- 不在 Friday 内写代码、提交 PR、上传交付物、处理审批或执行其他外部工作；
- 不自动推断外部完成情况，不要求完成证据；
- 不将 DDL、紧急程度或发布者缺失替换为猜测值。

## 9. 指标、依赖与风险

### 9.1 首期观察指标

首期不把“完成率”误当成外部真实工作完成率，只记录可验证的产品行为：

| 指标 | 定义 |
| --- | --- |
| Task 上下文覆盖 | 自动创建的 Task 中，具备背景、要做什么、AI 思考和来源 Message 的比例。 |
| 来源可追溯性 | 用户打开详情后可查看完整来源 Message 的 Task 比例。 |
| 手动状态可用性 | 用户完成／取消操作成功写入状态并在筛选中可见的比例。 |
| 缺失字段诚实性 | DDL、紧急程度或发布者不明确时，页面未展示猜测值的比例。 |

### 9.2 依赖与风险

| 项目 | 依赖／风险 | 产品处理 |
| --- | --- | --- |
| Task 创建 | 依赖 Friday 从真实 Message 中提炼结构化工作。 | 当前本地演示明确标识；接入真实服务后通过可替换数据层提供。 |
| 外部完成 | IDE、GitHub、钉钉等完成证据在第一版可能不可读。 | 用户自行标记完成／取消；不做自动判断。 |
| 字段质量 | 来源中可能没有 DDL、紧急程度或发布者。 | 字段可缺失且不显示；不推断会议主持人、群主或时间。 |
| 过度任务化 | 错将普通信息转成 Task 会让 Friday 变成待办工具。 | Task 仅由 Friday 自动创建，页面不提供手动创建、分派或项目管理能力。 |

## 10. 验收标准

1. Task 只能由 Friday 从 Message 自动创建；一条 Message 可关联多个 Task，但每条 Task 只保留一个来源 Message。
2. 默认列表展示全部历史，按创建时间倒序；四个状态筛选可用。
3. 卡片只显示名称、可用元信息、状态、创建时间和完成／取消操作，不堆叠完整上下文。
4. DDL、紧急程度和发布者无法从来源明确得到时不显示，绝不猜测。
5. 详情严格按“基础信息 → 背景信息 → 要做什么 → AI 思考 → 来源 Message”呈现，且来源包含原始问题、判断和回答。
6. 完成／取消可从卡片操作，保留历史状态，不要求外部证据、不会触发 Friday，也没有重新打开入口。
7. 页面无手动创建、编辑、项目分组、看板或外部执行入口。
8. 本地演示边界、加载失败和无 Task 状态均清楚可读。
