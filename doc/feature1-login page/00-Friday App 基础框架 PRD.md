## 1. 一句话定义

Friday 是承载多个工作台的 App。数字人分身是 Marketplace 中的一个工作台；用户在 Onboarding 选中它后，Friday 自动加载该工作台，并直接进入数字人分身自己的初始化与日常界面。

## 2. 背景、目标与范围

### 2.1 背景

数字人分身不是 Friday 的通用 Agent 界面，也不是用户先进入一个通用工作区后再打开的功能页。它以独立工作台的形式运行在 Friday App 中。

基础框架的职责是让用户选中正确的工作台、可靠地进入它，并在加载失败时提供明确出口；不定义数字人分身工作台内部的信息架构和业务流程。

### 2.2 目标

- 让用户在 Friday App 的 Onboarding 中识别并选择“数字人分身”。
- 选择后自动加载数字人分身工作台，成功后直接进入其专属界面。
- 用户不经过 Friday 通用 Agent 界面，也不以通用工作台作为默认首页。

### 2.3 不在本 PRD 定义的内容

- Friday 账户的具体登录或认证方式。
- Marketplace 中其他工作台的详情、排序、购买或分发规则。
- 数字人分身工作台内部的 Onboarding、Memory、消息处理、设置和运行规则。

## 3. 核心用户路径

1. 用户下载并打开 Friday App。
2. Friday 按账户状态进入 Onboarding；若用户尚未选择工作台，则展示 Marketplace 的工作台选择。
3. 用户选择“数字人分身”。选择即开始加载，不再要求额外创建通用工作区或进入通用 Agent。
4. 加载成功后，Friday 直接打开数字人分身工作台；此时才开始该工作台自己的 Onboarding，随后进入其日常界面。
5. 用户后续打开 Friday 时，若数字人分身仍是当前工作台，则直接恢复至该工作台，而非进入通用界面。

## 4. 功能需求

### 4.1 P0：工作台选择与加载

| 场景 | 用户可见行为 | 规则 |
| --- | --- | --- |
| 尚未选择工作台 | Onboarding 展示 Marketplace 中可选的工作台；数字人分身以明确名称和用途出现。 | Marketplace 此处是选择入口，不是用户默认停留的通用首页。 |
| 选择数字人分身 | 选择后立即显示加载状态。 | 系统自动加载数字人分身工作台；不进入通用 Agent 或通用五页工作台。 |
| 加载成功 | 直接展示数字人分身工作台。 | 由数字人分身工作台接管之后的 Onboarding 与日常界面。 |
| 加载失败 | 显示“暂时无法加载数字人分身，请重试。” | 提供“重试”和“返回 Marketplace”；不得用通用界面替代工作台。 |
| 已选数字人分身 | 再次打开 Friday 时恢复数字人分身工作台。 | 只有用户明确切换工作台时，才回到 Marketplace。 |

#### 验收

- [ ] 用户可在 Onboarding 中选择数字人分身。
- [ ] 选择数字人分身后，系统自动开始加载并直达其工作台。
- [ ] 成功、失败、重试和返回 Marketplace 的去向明确。
- [ ] 任何上述路径均不向用户展示 Friday 通用 Agent 界面或通用五页工作台。

### 4.2 P0：App 级状态反馈

| 场景 | 页面反馈 | 操作 |
| --- | --- | --- |
| 工作台正在加载 | 显示工作台名称与简洁加载提示。 | 不展示虚构进度或技术日志。 |
| 网络不可用 | `网络连接似乎不可用，请检查后重试。` | `重试`、`返回 Marketplace` |
| 工作台不可用 | `暂时无法加载数字人分身，请重试。` | `重试`、`返回 Marketplace` |
| 账户状态失效 | `你的登录已过期，请重新登录。` | `前往登录`；成功后恢复此前需要进入的工作台。 |

- 状态文案必须说明问题和下一步，不暴露包名、服务地址、内部错误或调试信息。
- 加载或失败状态不得展示数字人分身中的工作内容、Memory 或敏感资料。

### 4.3 P0：平台与工作台的边界

| 层级 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| Friday App | 账户状态、Marketplace 入口、工作台选择、加载、恢复与 App 级错误反馈。 | 数字人分身的具体业务页面和处理逻辑。 |
| 数字人分身工作台 | 自己的 Onboarding、内部导航、Memory、消息处理、设置与日常工作流。 | 承担 Friday 的通用 Agent 首页。 |

Friday App 可以保留用户明确触发的 Marketplace 返回入口，但该入口不应把用户带到一个通用工作界面。

## 5. 体验原则

1. **先选工作台，再开始工作。** 用户只需要选择要使用的产品能力，不需要理解或配置通用 Agent。
2. **选择后直达。** 数字人分身加载完成即进入其界面，不增加通用首页、空工作区或二次跳转。
3. **边界清楚。** App 负责承载和切换；数字人分身负责后续体验。
4. **失败有出口。** 不能加载时可重试或返回 Marketplace，不伪造已加载成功。
5. **不泄露内部复杂度。** 用户不看到模型、安装、运行日志或加载实现细节。

## 6. 非功能体验要求

| 类别 | 要求 |
| --- | --- |
| 一致性 | 工作台选择、加载、失败与重试遵循 Friday App 的统一反馈方式。 |
| 易读性 | 关键信息不能只依赖颜色；按钮、加载和错误状态具备清晰文字。 |
| 隐私 | App 级页面不显示工作台内的业务内容、消息、Memory 或个人敏感资料。 |
| 可恢复性 | 加载中断或失败后，用户始终可重试或返回 Marketplace。 |
