## 1. 背景与目标

### 1.1 背景

Friday 的最终价值发生在五个产品模块和四步 Onboarding 中，但用户需要先拥有一个完整、可信、可持续扩展的 Web 产品框架。

这一阶段不解决“分身如何回复”，而是先让用户能够顺畅进入 Friday、理解产品的整体结构，并在任何页面都不迷路。

### 1.2 目标

交付 Friday 的 Web 端基础产品：用户可以通过邮箱验证码登录，进入统一的五页工作台，并获得一致的加载、空状态、异常提示和账户操作体验。


## 2. 目标用户与核心场景

### 2.1 目标用户

希望让 Friday 协助处理钉钉或飞书工作消息的管理者。他需要一个专业、清晰的工作产品，而不是复杂的配置工具。

### 2.2 核心场景

用户访问 Friday Web 端，完成邮箱验证码登录。登录后进入 Home，并能随时切换到 Tasks、Memory、Feedback、Settings。即使某个模块尚无内容，用户也能理解该模块的用途和下一步去向。

### 2.3 成功标准

用户无需帮助文档即可回答：

1. 我是否已登录 Friday？
2. Friday 有哪些核心能力？
3. 我现在处于哪个页面，下一步可以去哪里？

## 3. 体验原则

1. **先给产品感，再给功能复杂度。** Web 端打开即是完整工作台，不是一个堆满入口的设置页。
2. **五个一级页面，职责不重叠。** Home、Tasks、Memory、Feedback、Settings 是唯一一级导航。
3. **没有内容也要有方向。** 空状态说明“这里将帮助你做什么”，并指向正确下一步。
4. **状态可理解。** 加载、失败、权限失效等状态使用用户语言表达，不出现技术术语。
5. **默认桌面优先。** 首版为管理者在桌面浏览器中的工作界面；移动端仅保证可阅读，不承诺完整操作。

## 4. 功能需求

### 4.1 P0：访问与登录

#### 页面目的

让首次用户以最低认知成本进入 Friday；同一页面不区分“注册”和“登录”。

#### 页面内容与文案

| 区域 | 内容 | 行为 |
| --- | --- | --- |
| 品牌区 | Friday 标识；一句说明：`让你的工作分身先理解，再协助处理。` | 无跳转。 |
| 标题 | `登录 Friday` | 首次登录同样使用此标题。 |
| 邮箱输入 | 标签：`工作邮箱`；占位：`name@company.com` | 填写有效邮箱后可提交。 |
| 主按钮 | `获取验证码` | 成功发送后进入验证码状态。 |
| 验证码状态 | 标题：`输入验证码`；说明：`验证码已发送至 {邮箱}` | 输入六位验证码后自动登录。 |
| 次要操作 | `返回修改邮箱`、`重新发送` | 重新发送处于倒计时期间不可点击。 |

#### 状态与文案

| 状态 | 页面反馈 |
| --- | --- |
| 邮箱格式不正确 | `请输入有效的工作邮箱。` |
| 验证码错误/过期 | `验证码不正确或已过期，请重新获取。` |
| 暂时无法发送 | `暂时无法发送验证码，请稍后重试。` |
| 登录成功 | 自动进入 Home；不弹出多余成功提示。 |

#### 验收

- [ ] 首次用户和回访用户均可通过邮箱验证码进入产品。
- [ ] 页面不要求设置密码、填写公司信息或选择复杂套餐。
- [ ] 用户始终能修改邮箱、重新发送验证码或返回上一状态。

### 4.2 P0：全局工作台框架

#### 页面布局

登录后进入统一工作台。布局固定为：左侧导航、顶部个人区、主内容区。

| 区域 | 内容 | 规则 |
| --- | --- | --- |
| 左侧导航 | Friday 标识；Home、Tasks、Memory、Feedback、Settings | 五项固定排序，不增加 `History`、`Avatar` 或独立聊天入口。 |
| 当前页面 | 明确高亮当前导航项 | 用户始终知道自己在哪里。 |
| 顶部个人区 | 用户头像/姓名、通知入口 | 用户菜单仅包含 `退出登录`；其他账户能力后续再定义。 |
| 主内容区 | 页面标题、页面说明、模块内容 | 宽度稳定，避免页面间反复跳动。 |

#### 五个模块的基础空态

本阶段不展示假数据；每个模块先提供准确的用途说明。

| 页面 | 标题 | 空状态文案 | 主行动 |
| --- | --- | --- | --- |
| Home | `欢迎来到 Friday` | `你的工作分身将在这里汇总今天的处理结果和需要你确认的事项。` | `前往 Settings 开始设置` |
| Tasks | `Tasks` | `Friday 会从工作消息和会议中整理项目、待办与下一步。` | `返回 Home` |
| Memory | `Memory` | `这里会呈现 Friday 已理解的工作资料和你的工作方式。` | `查看设置` |
| Feedback | `Feedback` | `你和同事对回复的反馈，会在这里帮助 Friday 持续校准。` | `返回 Home` |
| Settings | `Settings` | `在这里连接工作应用，并管理分身的处理范围与运行状态。` | `查看可连接应用` |

#### 验收

- [ ] 用户登录后默认进入 Home。
- [ ] 五个一级导航可完整切换，当前页面有清晰选中态。
- [ ] 页面刷新或重新进入产品后，返回上次所在的合法页面；首次登录仍进入 Home。
- [ ] 所有空状态都说明该模块的价值，且不显示虚构消息、数字或任务。

### 4.3 P0：全局状态反馈

#### 加载状态

- 首次进入页面时使用简洁的骨架屏或加载占位，不能出现整页空白。
- 加载超过短暂等待时显示：`正在加载…`。
- 用户切换导航时，不清空已稳定显示的页面框架。

#### 异常状态

| 场景 | 文案 | 操作 |
| --- | --- | --- |
| 页面信息暂不可用 | `暂时无法加载此页面，请重试。` | `重试`、`返回 Home` |
| 网络不可用 | `网络连接似乎不可用，请检查后重试。` | `重试` |
| 登录状态失效 | `你的登录已过期，请重新登录。` | `前往登录` |
| 没有访问权限 | `你暂时没有访问此内容的权限。` | `返回 Home` |

#### 统一反馈规范

- 成功操作使用短提示，例如 `已保存`；提示出现后自动消失。
- 可撤销操作使用明确的确认弹窗；弹窗文案和按钮在全站一致。
- 错误信息描述问题和下一步，不责怪用户，不出现代码或系统术语。

### 4.4 P0：账户与退出

| 场景 | 内容与行为 |
| --- | --- |
| 查看账户菜单 | 点击头像显示当前邮箱与 `退出登录`。 |
| 退出登录 | 点击后弹窗确认：`确认退出 Friday？`；说明：`退出后需要通过邮箱验证码重新登录。` |
| 确认退出 | 返回登录页，不保留任何个人内容在页面上。 |
| 取消退出 | 关闭弹窗，停留当前页面。 |
 |

## 5. 非功能体验要求

| 类别 | 要求 |
| --- | --- |
| 设备范围 | 桌面浏览器优先；首版最小内容宽度为 1280px。 |
| 易读性 | 关键信息不能只依赖颜色；导航、按钮、提示具备清晰文字。 |
| 一致性 | 同类按钮、空状态、弹窗、加载和错误提示全站一致。 |
| 隐私感知 | 页面不在标题、提示或空状态中泄露工作消息、资料或个人敏感内容。 |
| 响应反馈 | 用户点击按钮后应立即得到加载、成功或失败反馈，不允许无响应。 |


## 7. 版本节奏

| 阶段 | 交付内容 | 用户得到的结果 |
| --- | --- | --- |
| 00A | 邮箱验证码登录、统一工作台、五页导航、空状态 | 用户可正常进入并理解 Friday 的结构。 |
| 00B | 全局加载、异常、退出登录和统一反馈 | 用户可稳定浏览产品，不会遇到无出口的空白或错误。 |
| 下一阶段 | Settings：钉钉/飞书连接、处理范围、Trial/Active | 用户可开始连接至少一个真实工作应用。 |

## 8. 风险与产品约束

| 风险 | 产品约束 |
| --- | --- |
| 为了看起来“完整”而填充假数据 | 未接入真实内容前只使用说明性空状态。 |
| 导航过多，用户不知道从哪里开始 | 一级导航严格限定为五项；首次行动统一指向 Settings，四步引导上线后再由 Onboarding 接管。 |
| 空状态只是“暂无数据”，没有价值说明 | 每个模块必须解释它未来会帮用户完成什么。 |
| 过早在基础框架加入复杂操作 | 本阶段只提供访问、登录、导航与状态体验；连接、Memory、任务和反馈均由模块 PRD 负责。 |

## 9. 上线验收清单

- [ ] 用户可从 Web 端完成邮箱验证码登录。
- [ ] 登录后进入 Home，并可切换五个固定一级页面。
- [ ] 每页具有符合模块职责的标题、说明和空状态。
- [ ] 用户可退出登录，也能在异常状态中重试或返回 Home。
- [ ] 全站不出现技术术语、工程配置、运行信息或虚构业务数据。
- [ ] 桌面浏览器下导航、正文与状态提示可稳定阅读和操作。

## 10. 与后续 PRD 的关系

| 后续 PRD | 本 PRD 已提供 | 后续 PRD 决定 |
| --- | --- | --- |
| Settings | Settings 页面容器、账户状态、统一确认弹窗 | 钉钉/飞书连接、至少连接一个应用、处理范围、Trial/Active。 |
| Memory | Memory 页面容器、空/异常状态 | 资料读取、Memory、工作画像、历史对话迁移入口。 |

| Feedback | Feedback 页面容器、统一状态提示 | 回复反馈、处理闭环与工作风格校准。 |
