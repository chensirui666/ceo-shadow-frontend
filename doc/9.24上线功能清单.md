## 2. 背景

本期上线 Routine 与 Library，形成“配置重复工作 → 定时生成正式 Artifact → 可选发送 → 集中管理结果”的完整闭环。用户可以为一项重复工作选择核心 Recipe、设置执行时间和交付对象，避免每次手动整理、生成和分发。

Routine 正式生成的 Artifact 及 Message 产生的正式 Artifact 统一进入 Library。用户不必回到原消息或执行记录逐条寻找结果，可以集中查找、预览、打开所在文件夹和管理，并查看其来源与发送结果。

本清单描述研发需交付的真实产品能力；当前前端原型仅用于验证页面与交互，不限制定时执行、生成、归档、发送等服务端能力的实现。

## 3. 功能清单

### 3.1 Routine

| 功能 | 功能说明 |
| --- | --- |
| Routine 创建与管理 | 1. 从推荐入口创建独立 Routine。<br>2. 在“我的日程”查看已有 Routine。<br>3. 修改设置、开启、关闭或删除；关闭和删除停止后续自动执行，删除不影响已归档的 Artifact。 |
| 核心 Recipe | 1. 每条 Routine 必须且只能选择一个 Friday 内置 Recipe。<br>2. 用户可查看详情、添加或更换，但不能编辑或创建 Recipe。 |
| 执行与交付配置 | 1. 设置每周执行星期、开始生成时间和创建时区。<br>2. 选择已连接 Connector 下的群聊或个人作为可选收件人；未配置收件人时只生成并归档，配置后在生成完成后发送。<br>3. 选择文件格式（PDF、MD、Word）；PDF 与 Word 支持预设视觉样式，MD 不支持。 |
| 试运行与保存 | 1. 按当前草稿试运行并查看预览。<br>2. 试运行不发送、不改变正式配置、不写入 Recent Sessions，也不进入 Library。<br>3. 保存后，新的 Recipe、日程和交付配置才用于后续正式执行；离开未保存的配置时可选择保存或放弃修改。 |
| 定时执行与 Recent Sessions | 1. 到计划时间后，系统按已保存配置开始生成正式 Artifact。<br>2. 正式 Artifact 自动归档至 Library；配置了收件人时再发送。<br>3. Recent Sessions 按时间记录生成中、已生成、已发送、发送失败和生成失败。<br>4. 用户可查看详情，并仅对失败的发送目标重试，不重复生成或向已成功目标重复发送。 |

### 3.2 Library

| 功能 | 功能说明 |
| --- | --- |
| Artifact 列表页 | 1. 集中展示 Message 和 Routine 正式生成的 Artifact；试运行预览和 Connector 原始资料不收录。<br>2. 展示本周成果。<br>3. 支持按名称搜索、按来源和类型筛选、列表／网格切换；默认按生成时间倒序排列。<br>4. 提供空态、加载中和加载失败状态。 |
| Artifact 操作 | 1. 打开所在文件夹；点击后在 Finder 中打开该 Artifact 所在文件夹，并定位对应文件。<br>2. 原位重命名；不改变扩展名、正文、来源或已发送文件。<br>3. 删除前二次确认；不撤回外部已发送内容，发送中的 Artifact 禁止删除。 |
| Artifact 预览 | 1. 在当前页右侧只读预览常见文档、表格、演示、图片和代码文件；切换 Artifact 时展示对应完整内容。<br>2. 查看来源跳转。<br>3. 查看各 Connector／目标的发送结果和失败原因。<br>4. 无法预览、加载失败、文件已删除或无权限时明确提示，并在可用时保留“打开所在文件夹”入口。 |
