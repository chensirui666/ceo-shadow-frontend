# Supermemory 怎么收费（人话版）

> 核验日期：2026-08-21
>
> 这篇只回答三件事：用户每月先付什么钱、每个动作会扣什么钱、一段真实对话最后会花多少钱。

## 一句话结论

Supermemory 就像一张“预付费余额卡”：

1. 先付月费，得到当月可用的美元余额；
2. 往里面放新内容、搜索内容、做一些额外处理时，从余额扣钱；
3. 同一份内容再传一次，不会重复扣；只有真正新增的内容扣钱。

它不是按硬盘空间收费，也不是按你给 OpenAI / Claude 发了多少 token 收费。

## 先看月费：用户先买的是余额

| 套餐 | 每月付费 | 当月大约可用余额 | 用完后 |
|---|---:|---:|---|
| Free | $0 | $5 | 暂停，不能继续按量付费 |
| Pro | $19 | $20 | 可以自动充值 |
| Max | $100 | $130 | 可以自动充值 |
| Scale | $399 | $600 | 可以自动充值，也能设置“最多花到这里就停” |
| Enterprise | 定制 | 定制 | 定制 |

可以把 Pro 理解成：每月花 `$19`，账户里每月有大约 `$20` 专门用来支付 Supermemory 的写入、搜索等费用。

- 当月套餐送的余额，月底清零；
- 自己额外充值的余额，不会过期；
- 系统会先花当月套餐余额，再花充值余额；
- Pro / Max / Scale 开了自动充值后，余额低时会自动补钱，避免服务停掉。

## 用户实际会碰到的 6 种收费

### 1. 想让系统“长期记住”：Memory

例如你告诉分身：

> 我不喜欢临时电话；重要事情先发文字给我。

把这类内容写进 **Memory** 后，Supermemory 会把它变成“用户偏好”“当前状态”“人与事的关系”等长期记忆。

| 放进去的东西 | 单价 |
|---|---:|
| 聊天、文字、笔记、Markdown、代码 | $0.005 / 1K SM Tokens |
| PDF、图片、音频、视频等 | $0.010 / 1K SM Tokens |

一句人话：**你希望它以后“懂这个人”，就用 Memory。**

### 2. 只想以后找得到：SuperRAG

例如你上传一份 50 页的项目复盘，只希望以后问“当时有哪些风险”时能找出来，不希望它把整份文档里的话都当成你的个人偏好。

这时用 **SuperRAG**。

| 放进去的东西 | 单价 |
|---|---:|
| 聊天、文字、笔记、Markdown、代码 | $0.001 / 1K SM Tokens |
| PDF、图片、音频、视频等 | $0.002 / 1K SM Tokens |

一句人话：**只要能搜到，不需要“记住并理解”，就用 SuperRAG。**

它比 Memory 便宜 5 倍，因为它只把内容整理好、方便以后找；不会额外生成用户画像、长期偏好和关系图。

### 3. 搜一次内容：Search

例如分身在回复前问：

> 用户之前对这个客户说过什么？

或者：

> 这份复盘里提到的最大风险是什么？

每实际搜索一次，记 1 次 query。

```text
$0.005 / 1,000 次搜索
```

这非常便宜：搜索 1,000 次才 `$0.005`；搜索 10 万次才 `$0.50`。

### 4. 让系统立刻把一段内容变成长期记忆：Operation

默认情况下，Supermemory 会先把相关内容放在一起，再慢慢整理成长期记忆。

如果你要求“这段对话现在就必须记住”，可以用 `dreaming: "instant"`。这会额外收 1 个 Operation。

```text
$0.10 / 1,000 个 Operations
= 每次大约 $0.0001
```

它也把“重新给结果排序”“把多个结果合并”“把问题改写得更好搜”等额外处理，归到 Operations。

这里不要误解：**普通搜索默认只扣 Search，不会因为搜索一次就自动再扣一次 Operation。** 官方没有公开所有动作分别会扣多少 Operation；能确定的是，立即记忆会每份文档加 1 个。

## 最容易搞混的一件事：Memory 和 SuperRAG 不会叠加收费

一段新内容写入时，你要选一种方式：

```text
这段内容是“需要长期记住的事” → Memory
这段内容是“以后可能要查的资料” → SuperRAG
```

不是先按 Memory 收 `$0.005`，再按 SuperRAG 收 `$0.001`。

比如一轮新对话有 1,000 个新增 SM Tokens：

| 你怎么存 | 这轮要花多少钱 | 会发生什么 |
|---|---:|---|
| 用 Memory 存 | $0.005 | 能搜索，也会尝试整理成长期记忆 |
| 用 SuperRAG 存 | $0.001 | 能搜索，但不会形成长期记忆 |

即使你把这轮对话写进 Memory 后，系统最后只觉得其中一句话值得长期记住，仍然按 1,000 个新增 token 收费。因为它必须先读完、整理和判断，才知道哪些内容值得记。

## “新增内容”到底怎么算

拿一个聊天 session 举例。

第一次，用户和分身已经聊了 10 轮，一共 18,000 个 SM Tokens：

```text
session ID = chat_001
第一次写入：18,000 个新增 SM Tokens
```

第二天又聊了一轮，多出 1,200 个 SM Tokens。只要仍然使用同一个 `session ID`（在 Supermemory 里叫 `customId`）：

```text
第二次写入：旧的 18,000 不再收费，只算新加的 1,200
```

所以“新增内容”就是：**这份对话/文件里，上次没有交给 Supermemory 处理过的部分。**

它不是：

- 最后拆成了多少段；
- 最后形成了多少条长期记忆；
- ChatGPT / Claude 这次回答时带了多少上下文；
- PDF 文件有多少 MB。

如果你每次都换一个新的 `customId`，系统会把它当新文件，历史内容会重新收费。实际接入时，聊天必须一直用同一个 session ID；邮件用同一个 thread ID；云盘文件用同一个文件 ID。

## 什么算纯文本，什么算富内容

| 内容 | 怎么算 | 原因 |
|---|---|---|
| 对话、笔记、日志、普通文字 | 纯文本 | 直接读文字 |
| Markdown、代码 | 纯文本 | 也是直接读文字 |
| PDF、Word、PPT、表格文件 | 富内容 | 需要解析文件、表格或版式 |
| 扫描版 PDF、图片 | 富内容 | 要 OCR 识别图片里的字 |
| 音频、视频 | 富内容 | 要先转写 |
| 网页 URL | 建议按富内容预估 | 要抓网页、去广告和导航，再提取正文 |

富内容是“处理更麻烦的文件”，不是排版好看的文字。它价格是纯文本的 2 倍。

## 一个完整的业务案例：工作分身怎么花钱

下面是一个产品里很常见的情况：用户让工作分身帮忙复盘项目，并上传一份 PDF。

### 场景 1：把重要的对话长期记住

10 轮对话一共 18,000 个新增纯文本 SM Tokens。里面有用户的工作习惯、已经确认的决策，也有闲聊。

因为这些内容应该影响分身以后怎么做事，所以用 Memory：

```text
18,000 ÷ 1,000 × $0.005 = $0.0900
```

即使最后只沉淀出两三条真正有用的偏好，也是 `$0.0900`。收费对象是“读懂这 18,000 token”，不是“最终写下几条偏好”。

### 场景 2：第二天多聊一轮

又新增 1,200 个 token，仍然用同一个 `chat_001`：

```text
1,200 ÷ 1,000 × $0.005 = $0.0060
```

前一天的 18,000 个不会再收一次。

### 场景 3：上传 PDF，只希望以后能查到

PDF 处理后有 30,000 个新增富内容 SM Tokens。它是项目资料，不该直接改变用户画像，所以用 SuperRAG：

```text
30,000 ÷ 1,000 × $0.002 = $0.0600
```

### 场景 4：分身查询资料并立即记住对话

```text
搜索 PDF 和历史记忆 20 次：20 ÷ 1,000 × $0.005 = $0.0001
要求立刻记住第一段对话：1 个 Operation = $0.0001
```

### 这次一共花多少

```text
长期记忆对话      $0.0900
新的一轮对话      $0.0060
PDF 检索资料      $0.0600
20 次搜索         $0.0001
立即记住          $0.0001
-------------------------
总计              $0.1562
```

如果用户是 Pro，每月约有 `$20` 可用余额。这个案例花了 `$0.1562`，还剩约 `$19.8438`；不会触发自动充值。

## 对 Friday 最实用的做法

不用让最终用户理解 SM Token。内部按下面做就够了：

| 内容 | Friday 内部应该怎么存 |
|---|---|
| 用户确认过的工作习惯、偏好、关系变化、长期状态 | Memory |
| 历史对话、会议纪要、邮件正文、项目文档 | SuperRAG |
| 每次同步会话、邮件、云盘文件 | 固定使用同一个 source ID，避免历史重复收费 |
| 用户需要“这件事现在就要记住” | 才用 instant；默认不用 |
