## 1. 背景与目标

### 1.1 背景

项目进展、待办和关键结论往往分散在工作消息、会议纪要和资料中。管理者真正需要的不是另一套手工协作工具，而是能快速回答：

1. 目前有哪些项目；
2. 每个项目进展到哪里、由谁负责、还有哪些待办；
3. 项目为什么处于当前状态，哪些结论已经达成；
4. 一条结论或最近变化来自哪里。

Friday 已具备从工作对话、会议和资料中沉淀项目与待办的能力方向。本页面将这些信息组织为项目视图，不把它做成钉钉 Todo、Linear 或通用项目管理软件的替代品。

### 1.2 用户目标

用户进入 Tasks 后，应能：

1. 从项目列表中迅速找到正在关心的项目；
2. 一眼了解自己参与项目与待办的总体负荷，并知道是否有需要处理的异常；
3. 看清项目当前状态、负责人、完成进展和待办；
4. 在详情中理解项目目标、背景、阻塞与下一步；
5. 完成或取消一项内部 TODO；
6. 查看项目已确认的重要结论，并在当前页面追溯其消息或会议来源；
7. 看见项目最近发生的关键变化，而不是翻阅完整操作流水。

### 1.3 成功标准

- 项目列表只用五个业务字段完成扫读：项目、当前状态、负责人、进展、TODO。
- 用户可在列表上方快速看见自己参与项目数、名下未完成 TODO 数和需要关注的项目数，无需阅读一段解释文字。
- 用户进入项目详情后，能回答“项目做什么、现在怎样、卡在哪里、下一步谁做什么”。
- 每条结论都能在当前详情页展开来源摘录，分清其来自工作消息还是会议。
- 完成或取消 TODO 后，TODO 状态、完成时间、项目进展和最近变化立即一致更新。
- 用户不会误以为页面会创建钉钉 Todo、提醒负责人或向任何外部应用写入数据。

## 2. 本期范围与边界

### 2.1 P0 范围

1. 以项目为主的、跟随当前账号的列表页与独立项目详情页。
2. 当前账号的工作仪表盘：参与项目、我的 TODO 和需要关注。
3. 默认按项目中最近生成的 TODO 时间倒序排列。
4. 项目详情中的基本信息、细节信息、TODO、结论和最近变化。
5. TODO 的内部“完成”与“取消”操作。
6. 结论和最近变化的只读来源摘录展开。
7. 加载、失败和无项目等前端演示状态。

### 2.2 明确不做

1. 不新建、编辑、拖拽、批量处理项目或 TODO。
2. 不做钉钉 Todo 创建、同步、提醒、重试或同步状态展示。
3. 不替负责人发送催办消息，也不修改负责人。
4. 不做通用甘特图、项目管理看板、评论区、多人协作、分页或跨天历史库。
5. 不展示内部 ID、审计 JSON、置信度、模型判断过程、工具调用或技术错误。
6. 不提供完整“更新”时间线；本期只展示一条最近变化。
7. 不访问 CEO 服务、不会向后端写入数据；刷新页面后演示数据恢复初始状态。

## 3. 产品模型与状态

### 3.1 Tasks 的责任

Tasks 是工作项目的行动视图：将工作材料中已经沉淀出的项目、待办和结论组织起来，帮助用户识别下一步。

| 页面 | 负责的问题 | 不负责的问题 |
| --- | --- | --- |
| Home | 今天发生了什么、Friday 如何处理消息 | 项目全貌和长期待办管理 |
| Tasks | 项目现在怎样、下一步是什么、结论来自哪里 | 消息审计、外部提醒、通用项目协作 |
| Memory | Friday 使用哪些工作资料和画像 | 项目行动与 TODO 操作 |
| Settings | 长期规则、连接与边界 | 项目与待办管理 |

### 3.2 项目

每个项目包含以下用户可读信息：

| 信息 | 含义 |
| --- | --- |
| 项目启动时间 | 项目在 Friday 中首次被记录的时间。 |
| 负责人 | 对项目整体负责的人。 |
| 参与人 | 与项目相关的主要协作人。 |
| 重要程度 | 项目的业务优先级，用于详情识别。 |
| 当前状态 | 未开始、进行中、已逾期或已完成。它是项目状态，不等同于某条 TODO 的状态。 |
| 项目目标 | 希望达成的可读结果。 |
| 背景 | 当前项目为什么出现、已知的必要上下文。 |
| 当前进展 | 对当前进度的业务描述。 |
| 阻塞点 | 暂时阻碍项目推进的事实；没有则明确显示“暂无”。 |
| 下一步 | 当前最明确、可执行的后续动作。 |
| 最近变化 | 最近一次影响项目理解或进展的业务变化，并可追溯来源。 |

项目不会因为一条 TODO 被完成或取消就自动改为“已完成”。项目状态仍需由明确的项目事实决定，避免 Friday 替用户做项目结论。

### 3.3 TODO

TODO 是项目下可执行的事项，包含负责人、事项、状态、DDL、生成时间、完成时间和来源。

| TODO 状态 | 用户可见含义 | 可用操作 |
| --- | --- | --- |
| 待处理 | 事项尚未完成，也未被取消。 | 完成、取消 |
| 已完成 | 已在 Friday 内部标记完成。 | 无 |
| 已取消 | 该事项不再继续。 | 无 |

- 点击“完成”后，系统写入完成时间。
- 点击“取消”前必须二次确认，避免误操作。
- 项目进展显示为“已完成 TODO 数 / 未取消 TODO 总数”及对应百分比；已取消 TODO 不计入进展分母。
- TODO 的操作只更新当前前端演示会话；不创建钉钉 Todo，不触发外部同步。

### 3.4 结论与来源

结论是项目中已经达成一致、可影响后续行动的事实，不是 AI 的推测或内部判断。

每条结论包含：

| 字段 | 内容 |
| --- | --- |
| 描述 | 用自然语言说明已达成的一致结论。 |
| 来源 | 消息或会议的来源名称与类型。 |
| 创建时间 | Friday 记录这条结论的时间。 |

点击来源后，在当前项目详情内展开只读摘录：来源类型、来源名称、发生时间和支撑该结论的消息／会议内容。摘录不跳转 Home，不展示审计字段、内部引用编号或无关原文。

### 3.5 最近变化

最近变化不是独立的更新流水。它只说明最近一次影响项目状态、进展或下一步的业务事实，例如：

> 8 月 8 日会后，项目负责人确认先完成现场演示，再根据结果决定是否推进试用。

最近变化可以来自会议、工作消息或 TODO 完成／取消，并同样支持展开只读来源摘录。页面不提供完整的变化时间线。

## 4. 页面信息架构

### 4.1 项目列表页

页面标题为 `Tasks`。页面跟随当前登录账号，只展示该账号担任负责人或参与人的项目；不提供负责人、状态、分类、优先级、关键词筛选或团队切换。

#### 4.1.1 我的工作仪表盘

项目列表上方提供「我的工作」仪表盘。它的目的不是汇总所有管理数据，而是让用户在进入页面时用最少文字判断自己的工作负荷和异常。

仪表盘需表达以下三项信息：

| 信息 | 口径 | 用户要得到的判断 |
| --- | --- | --- |
| 参与项目 | 当前账号是负责人或参与人的项目总数；可补充其中负责的项目数。 | 我当前横跨多少项目。 |
| 我的 TODO | 负责人为当前账号、状态为待处理的 TODO 数量。 | 我手上还有多少可执行事项。 |
| 需要关注 | 当前账号参与的项目中，存在逾期待处理 TODO 或明确阻塞点的项目数。 | 哪些项目不应被忽略。 |

仪表盘应以图形化、低文字压力的方式传达上述信息，不能把项目列表替换为一堆统计说明。其中「我的 TODO」使用拱桥型图表：图表中心突出显示未完成 TODO 数量，拱桥用于建立视觉焦点，不额外制造健康分、趋势或 AI 风险判断。整体希望以克制的绿色营造稳定感，但颜色不能成为理解信息的唯一方式。

除上述意图外，本 PRD 不规定仪表盘的卡片数量、图表组合、布局或装饰细节，由视觉设计在保证扫读效率的前提下决定。

#### 4.1.2 列表字段

列表是清晰的项目表格，不堆叠卡片。每行可点击进入项目详情，按项目最近生成的 TODO 时间倒序排列；没有 TODO 的项目排在其后，再按项目记录时间倒序排列。

| 字段 | 显示规则 |
| --- | --- |
| 项目 | 项目名称；必要时在下一行以低强调文字显示项目分类。 |
| 当前状态 | 未开始、进行中、已逾期或已完成的紧凑文字状态。 |
| 负责人 | 项目负责人姓名；没有负责人时显示“待确认”。 |
| 进展 | 已完成 / 未取消 TODO 数量与百分比。 |
| TODO | 最近生成的一条待办摘要与开放待办数量；没有待办时显示“暂无待办”。 |

项目分类和重要程度保留在项目数据与详情中，不增加为列表列，避免列表变成字段堆叠。

#### 4.1.3 列表状态

| 场景 | 页面内容 | 行动 |
| --- | --- | --- |
| 加载中 | 显示紧凑加载提示。 | 无 |
| 加载失败 | `暂时无法加载项目，请重试。` | `重试` |
| 没有我的项目 | `暂时没有沉淀出与你相关的工作事项。Friday 会在处理消息和会议后持续整理。` | 无 |

### 4.2 项目详情页

项目详情页通过 `返回 Tasks` 回到原列表，并保留滚动位置。按以下顺序阅读：

1. **项目抬头**：项目名称、当前状态、项目分类与重要程度；右侧为返回入口。
2. **基本信息**：项目启动时间、负责人、参与人、重要程度、当前状态。
3. **细节信息**：项目目标、背景、当前进展、阻塞点、下一步，以及一条最近变化。
4. **TODO**：负责人、事项、进度、DDL、完成时间；待处理事项可完成或取消。
5. **结论**：描述、来源、创建时间；来源可在当前页展开只读摘录。

详情以正常文本、留白和细分隔线组织内容；不使用审计台式的大量信息卡、数据面板或内部字段表。

### 4.3 TODO 区

TODO 使用紧凑表格或分隔行，而非待办看板。每项显示：

```text
负责人 · 事项 · 当前进度 · DDL · 完成时间 · 可用操作
```

用户可只对待处理事项执行“完成”或“取消”。完成后行内显示完成时间；取消后显示“已取消”，不再出现操作按钮。

### 4.4 来源摘录

来源展开区在结论或最近变化下方原位出现，不覆盖当前页面。它包含：

```text
来源类型 · 来源名称 · 发生时间
支撑该结论或变化的只读消息／会议摘录
```

同一时刻只展开一条来源，便于保持阅读焦点。关闭后回到原内容位置。

## 5. 功能需求

### 5.1 P0：浏览我的项目与工作负荷

- 页面自动展示当前账号参与的项目，按项目最近生成 TODO 的时间倒序；无 TODO 的项目排在其后。
- 页面顶部展示当前账号的参与项目、我的 TODO、需要关注三项仪表盘信息，口径见 4.1.1。
- 用户点击项目行进入详情；浏览器返回、`返回 Tasks` 均回到原列表位置。
- 不提供手动排序控件；默认排序是唯一排序规则。
- 不提供页面筛选、搜索或人员切换；用户只能查看与当前账号相关的项目。

### 5.2 P0：查看项目细节

- 用户能在一个详情页理解项目整体信息、细节信息、TODO 和结论。
- 阻塞点为空时显示“暂无阻塞”，下一步为空时显示“待明确下一步”，不能留空白字段。
- 最近变化只显示一条；没有变化时显示“暂无新的项目变化”。

### 5.3 P0：完成或取消 TODO

- 用户点击“完成”后，当前 TODO 变为已完成并写入完成时间。
- 用户点击“取消”后，先看到确认说明；确认后 TODO 变为已取消。
- 两种操作均即时刷新项目进展与最近变化。
- 任何操作都不调用外部服务、不生成钉钉任务、不发送通知。

### 5.4 P0：查看结论与最近变化的来源

- 每条结论都必须包含描述、来源和创建时间。
- 用户可在当前详情页展开来源摘录，了解该结论或变化来自哪条消息或哪次会议。
- 来源信息仅用于解释事实，不允许编辑、删除或跳转到内部审计记录。

## 6. 前端演示规则

### 6.1 演示数据

演示数据至少覆盖：

1. 进行中项目：含多个待处理 TODO、会议结论和最近变化；
2. 已逾期项目：含一条过期待处理 TODO 与明确阻塞；
3. 已完成项目：展示完整进展和已完成时间；
4. 无 TODO 项目：仍能展示项目细节、结论与来源；
5. 消息来源与会议来源两种可展开摘录；
6. 当前账号既作为项目负责人，也作为不同项目的参与人，用于验证「我参与的项目」范围与仪表盘口径；
7. 当前账号名下包含待处理、已完成、逾期和取消 TODO，用于验证「我的 TODO」及需要关注的计算。

### 6.2 演示边界

- 数据只在当前浏览器会话内变化，刷新后恢复 fixture 初始状态。
- 不读取或写入真实项目、工作 TODO、钉钉 Todo 或负责人账户。
- 页面须在可见位置使用低干扰说明：`演示数据仅在此页面内更新，不会同步到外部应用。`

## 7. 视觉与交互规则

1. **项目优先。** 列表首先是项目，不把每条 TODO 摊平成独立首页列表。
2. **先判断负荷，再扫读项目。** 我的工作仪表盘只呈现参与项目、我的 TODO、需要关注；它减少阅读压力，不替代下方项目表。
3. **表格用于扫读，详情用于理解。** 列表字段固定为五列；长文本、来源和操作只在详情出现。
4. **清晰但不喧宾夺主。** 状态为紧凑文字标签；整体希望使用克制绿色建立稳定感，不使用大面积红黄绿背景，也不以颜色作为唯一判断方式。
5. **业务语言。** 使用“项目目标”“阻塞点”“结论”“最近变化”；不出现 source ID、confidence、Work Item、JSON 或“同步失败详情”等工程语言。
6. **来源可读而克制。** 只展开支撑当前事实的摘录；不将 Tasks 变成原始聊天记录浏览器。
7. **桌面优先。** 宽屏保持五列扫读；窄屏按项目 → 当前状态 → 负责人 → 进展 → TODO 的阅读顺序折叠显示。
8. **可键盘访问。** 项目行、TODO 操作和来源展开入口均可聚焦并有可见焦点。

## 8. 验收清单

### 我的项目与仪表盘

- [ ] 列表仅展示项目、当前状态、负责人、进展、TODO 五类业务信息。
- [ ] 列表只展示当前账号作为负责人或参与人的项目，不显示筛选、搜索或人员切换。
- [ ] 仪表盘准确展示当前账号的参与项目数、名下未完成 TODO 数和需要关注项目数。
- [ ] 我的 TODO 采用拱桥型图表，并以数字明确表达未完成 TODO 数量。
- [ ] 默认按项目最近生成 TODO 的时间倒序，不展示“需要关注优先”排序。
- [ ] 无项目和加载失败均有明确、可理解的状态。

### 项目详情

- [ ] 用户能看到项目启动时间、负责人、参与人、重要程度和当前状态。
- [ ] 用户能读到项目目标、背景、当前进展、阻塞点、下一步和最近变化。
- [ ] 项目详情不提供独立更新流水或内部审计表。
- [ ] TODO 显示负责人、事项、进度、DDL 和完成时间。

### 操作与来源

- [ ] 待处理 TODO 可以完成或取消；取消需要确认。
- [ ] 完成／取消后，项目进展、完成时间和最近变化一致更新。
- [ ] 结论包含描述、来源和创建时间，来源能在当前页展开只读摘录。
- [ ] 所有操作仅更新前端演示数据，不推送钉钉、不写入 CEO 服务、不通知负责人。

| 优先级 | 方向 | 前提 |
| --- | --- | --- |
| P1 | 接入真实 Friday 内部项目与 TODO 数据。 | 稳定、面向产品的数据合同可用。 |
