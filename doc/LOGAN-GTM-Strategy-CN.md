# LOGAN 全球市场进入与商业拓展策略

## 从一位用户到全公司网络效应

## 使命与愿景

**使命：** 让人们摆脱占用时间、却不需要其天赋的运营性工作。

**愿景：** 构建一个世界，让每个人都有一个 Second Shift——当人转向其他重要事项时，仍能持续推动工作的 AI。

## 1. 品类论点

LOGAN 是每个人的 Second Shift：人完成“first shift”，并专注于需要判断、创造力、关系与决策的高价值工作；LOGAN 完成“second shift”，接手人们不愿投入时间的低价值运营工作，包括上下文恢复、协调、跟进、周期性分析、文档和执行。

Second Shift 指 LOGAN 在人的“first shift”之外，接手用户不想亲自完成的低价值运营工作，而不是要求人增加第二份工作。

市场进入策略遵循一个核心原则：不逐个获取用户，而是先服务一位高杠杆用户，让他的真实工作自然将同事和组织带入系统。

> 一位用户 → 一项被委托的工作 → 持续价值 → 共享工作 → 同事参与 → 团队采用 → 组织记忆 → 企业扩展

LOGAN 的目标不是更多邀请，而是让每一个有价值的工作单元，至少创造一次让他人体验产品价值的机会。

## 2. 以高杠杆用户为切入点

LOGAN 不以“服务所有人”为起点，而是优先服务工作天然连接多人、多个系统和多个决策的节点型操作者。

| 优先级 | 初始 ICP | 作为种子用户的原因 |
|---|---|---|
| 1 | 创始人 / CEO | 上下文密度最高，覆盖销售、招聘、交付和管理 |
| 2 | Chief of Staff / 运营负责人 | 跨团队协调，能够自然带动多个工作流 |
| 3 | 销售负责人 | 掌握高价值客户信息、承诺与跟进事项 |
| 4 | 项目 / 项目群负责人 | 依赖多位协作者、多个截止节点和状态输入 |
| 5 | 合伙人、投资人或专业服务负责人 | 专家工作重复度高，信息与关系密度大 |

初始目标公司具有以下特征：

- 10—200 人的组织；
- 分布式或跨境团队；
- 重度使用 Slack、Teams、飞书 / Lark、钉钉、WhatsApp 等协作工具；
- 会议和消息量大；
- 资深人员仍在手动协调关键工作；
- 大量重复工作流依赖个人上下文与专家判断。

全球市场采取“先形成密度，再扩大覆盖”的顺序：

| 阶段 | 重点区域 |
|---|---|
| Wave 1 | 美国、英国、以英语协作的欧洲团队及跨境亚洲团队 |
| Wave 2 | DACH、法国、日本、韩国与本地化专业社群 |
| Wave 3 | 通过生态伙伴、渠道伙伴和企业客户扩大覆盖 |

目标不是尽快覆盖所有地区，而是在每一类高匹配组织中形成能自然扩散的用户密度。

## 3. 将“委托一项周期工作”定义为激活

注册不是激活，连接 Slack 不是激活，与 LOGAN 聊天也不是激活。

**激活事件：** 新用户在前 72 小时内，将至少一项会重复运行的周期性工作委托给 LOGAN。

首个被委托的工作流可以包括：

- CEO 周度管理简报；
- 会议 → 行动项 → 负责人 → 截止日期；
- 客户账户记忆与跟进；
- 项目风险与承诺追踪；
- 提案 / RFP 准备；
- 投资人与投资组合监控；
- 跨群日报或周报。

北极星激活指标是 **Delegated Workflow Activation Rate**：符合条件的新用户中，在 72 小时内委托至少一项周期工作的人数占比。

产品 onboarding 不应从空白聊天框开始。连接经过批准的上下文后，LOGAN 应主动提出：“基于你的工作，我可以接手以下三项工作。” 产品要尽快创造首次“这件事以后不需要我亲自做”的体验。

## 4. 将团队病毒式增长构建进产品

LOGAN 的核心增长机制是协作，而不是泛化推荐奖励。每个有价值的工作流都应自然要求或受益于另一位同事的查看、补充、审批或行动。

| 增长机制 | 工作方式 | 增长效果 |
|---|---|---|
| 行动负责人闭环 | 对话被转为行动项后，系统向负责人发送可执行消息；对方无需先完成复杂注册 | 每个工作流持续产生高意图邀请 |
| 共享 Recipe | 用户将高价值工作流沉淀为可复用 Recipe；同事可一键克隆并在自己的项目中运行 | 专家工作方法成为分发对象 |
| 协作审批 | 对定价例外、客户方案、法务语言、交付时间和管理者沟通直接请求审批 | 决策者先在真实工作中体验价值 |
| 管理者简报闭环 | 系统收集缺失更新、整合内容并生成团队状态报告 | 一位管理者可自然带动整个团队参与 |
| Twin-to-Twin 交接 | 在授权范围内，不同用户的 LOGAN 传递上下文、请求信息、协调行动并升级决策 | 工作依赖成为激活新用户的理由 |
| 共享团队 Memory | 汇聚项目历史、决策、承诺、客户关系、负责人、依赖和未解决风险 | 不完整的组织上下文形成自然扩展需求 |
| 角色化扩展 | 系统识别销售、交付等重复依赖角色，并推荐预配置的角色 Recipe 包 | 产品识别账户内的下一个高价值用户 |
| 可分享工作产物 | 周报、客户计划、项目健康报告、决策备忘录和行动追踪器可受控分享 | 工作结果成为组织外的获客入口 |
| 团队影响力看板 | 展示已委托工作流、已完成交付、已闭环事项、已执行跟进与协作成果 | 扩张与可量化运营价值绑定 |
| 内部 Recipe 市场 | 组织沉淀专家方法；成熟后可选择对外发布高价值 Recipe | 每位专家都可成为创作者和分发者 |

其中，团队 Memory 应清晰揭示上下文缺口，例如：“当前工作流仅具备 42% 的必要上下文；连接销售与交付团队后可补全。” 这让扩张成为产品建议，而不是销售推销。

## 5. 核心增长闭环

LOGAN 的目标增长闭环为：

1. 节点型用户加入；
2. LOGAN 理解已批准的工作上下文；
3. 用户委托一项周期工作；
4. LOGAN 产生可见的真实成果；
5. 成果需要同事查看、审批、补充或执行；
6. 同事在注册前体验产品价值；
7. 同事激活自己的 LOGAN；
8. 共享 Memory 与 Recipe 让每位用户的 LOGAN 更有价值；
9. 更多工作流进入系统；
10. 工作空间成为组织的执行基础设施；
11. 客户成功成为进入下一家组织的证明与分发渠道。

增长的复利逻辑是：更多用户带来更多上下文；更多上下文带来更好的执行；更好的执行带来更多共享工作；更多共享工作又带来更多用户。

## 6. 分阶段 GTM 计划

### Phase I：0—100 位用户

**目标：** 找到用户会形成依赖的少数高价值工作流。

**市场动作：** 创始人主导销售、暖介绍、现有客户与投资人网络、精选设计伙伴、礼宾式 onboarding 和每日产品反馈。此阶段聚焦高质量学习，而非广泛付费获客。

**客户策略：** 先招募 30 位高上下文节点型用户作为设计伙伴，每位用户都必须完成至少一个真实工作流；再通过暖介绍、客户网络和自然同事扩张，将已验证样本扩展至 70+ 位合格用户。

**验证门槛：**

- 70+ 位合格用户；
- 50%+ 连接真实工作来源；
- 30%+ 委托至少一项周期工作；
- 10+ 位周度依赖用户；
- 5+ 位用户自愿分享 Recipe 或工作产物；
- 3+ 家公司出现自然的同事采用。

最关键的证明是：用户在没有销售推动的情况下，主动将同事带入工作流。

### Phase II：100—1,000 位用户

**目标：** 让首次激活与内部扩张变得可重复。

**产品建设：** 角色化 Recipe 包、共享 Recipe、行动负责人邀请、协作审批、团队 Memory、一键同事激活、每周影响报告，以及邀请归因和病毒式增长分析。

**进入下一阶段的条件：** 首次委托、周期工作流留存和同事激活可在多个高匹配账户中重复出现。

**主要渠道：**

1. LinkedIn：专业背书和角色化案例；
2. YouTube：深度工作流演示；
3. 创始人主导的 X 内容：产品发布与公开构建；
4. 专业社群：RevOps、Agency Owner、Chief of Staff、PMO 与创始人；
5. 用户自然分享：仅在真实价值被验证之后触发。

内容始终展示具体链条：**痛苦工作 → 混乱上下文 → LOGAN 执行 → 专业结果 → 人工审批 → LOGAN 记住。**

### Phase III：1,000—10,000 位用户

**目标：** 让客户成为主要获客渠道。

**产品增长：** 公开或内部 Recipe 分享、嵌入工作流的团队邀请、可分享输出页面、Twin-to-Twin 协作、组织级 Memory、角色化扩展建议、客户创建模板与轻量外部访客参与。

**创作者引擎：** 招募真正使用 LOGAN 完成工作的实践型创作者，而非泛 AI 影响者。优先覆盖创始人 / 运营者、RevOps、Chief of Staff、项目管理、B2B 销售、Agency 运营、投资人与分析师、AI 自动化教育者。衡量标准是已激活工作流和留存用户，而不是浏览量。

**社群：** 使用 Discord 或同类产品承接 onboarding、Recipe 分享、支持、创作者协作、客户反馈与产品倡导者。社群承担留存和倡导作用。

**进入下一阶段的条件：** 活跃客户持续通过工作产物、Recipe 或协作邀请带来新的已激活用户。

### Phase IV：10,000—100,000 位用户

**目标：** 围绕已验证的产品市场匹配建立全球分发系统。

**产品主导分发：** 团队扩张、共享 Recipe、公开工作产物、邀请闭环、跨公司协作和 Recipe 市场。

**搜索分发：** 围绕高意图任务建立可直接进入相应 Recipe 的页面，例如 AI CEO 周报、AI 销售跟进、AI 项目状态报告、AI RFP 助手、AI Chief of Staff、AI 客户记忆和 AI 投资尽调。

**生态与渠道：** 优先与 Slack、Microsoft Teams、飞书 / Lark、钉钉、WhatsApp、Discord 及新兴协作平台合作。渠道伙伴包括协作平台顾问、AI 实施公司、RevOps Agency、MSP、专业服务网络、VC 与加速器生态。每个伙伴分发的是已验证的工作流，而不是抽象平台。

每项定制集成均需具备明确的分发承诺：应用市场曝光、试点客户、联合营销或伙伴驱动需求。

**进入下一阶段的条件：** 产品主导扩张、搜索、生态和渠道能够形成稳定、可归因的获客组合。

### Phase V：100,000—100 万+ 用户

**目标：** 成为组织运行的执行层。

企业采用路径为：Individual Second Shift → Team Second Shift → Business Unit → Enterprise。企业销售从员工已证明的工作价值开始。

企业产品包括组织 Memory、治理、权限、审计轨迹、人工审批策略、企业 Recipe 库、私有部署、模型选择、数据边界、分析能力、管理员控制台以及 API / 开发者平台。

这一阶段，LOGAN 销售的不再只是效率工具，而是组织执行基础设施。

**进入下一阶段的条件：** 组织级 Memory、治理与审计能力能够支持跨团队关键工作流的持续采用。

## 7. 商业化与账户扩展

| 产品层级 | 核心能力 | 商业目的 |
|---|---|---|
| Free | 一位 LOGAN、一个主工作流、有限 Memory 与执行额度 | 获得首次委托与分享 |
| Pro | 更多 Memory、Recipe、集成与执行容量 | 建立个人依赖 |
| Team | 共享 Recipe、共享 Memory、审批、分析与协作 | 推动工作空间扩张 |
| Enterprise | 治理、安全、审计、私有部署与组织智能 | 推动组织级长期采用 |

商业旅程从个人价值开始，经过协作价值，最终进入组织价值。计费单位由订阅层级与执行额度共同构成；用户在需要更多 Memory、Recipe、集成、执行容量或团队协作能力时升级。定价以设计伙伴和高匹配客户的付费意愿、使用深度和单位执行成本持续验证。**Work DNA** 指用户可查看、可修改的个人工作标准与偏好系统。随着组织使用深度增加，LOGAN 也可通过 API 和开发者平台进入第三方 SaaS、CRM、项目管理工具和企业内部系统，将上下文理解、Memory、任务执行和 Work DNA 能力嵌入外部工作流。

## 8. 全球增长指标

### 激活

- 首次委托任务所需时间；
- Delegated Workflow Activation Rate；
- 首周完成工作流数量；
- Day-7 / Day-30 工作流留存。

### 病毒式协作

- 活跃用户让同事体验 LOGAN 的比例；
- 同事邀请转化率；
- 共享 Recipe 克隆率；
- 共享产物到注册的转化率；
- 协作审批到激活的转化率；
- 每位活跃用户带来的新增已激活用户数。

### 团队扩张

- 每个工作空间的用户数；
- 30 天团队渗透率；
- 从第 1 位到第 3 位、再到第 10 位用户的时间；
- 跨职能工作流数量；
- 工作空间扩张率。

### 商业化

- 付费工作空间转化率；
- 扩张收入；
- 净收入留存；
- 获客回收周期；
- 每工作空间收入；
- 企业扩张速度。

长期北极星指标为 **Workspace Viral Coefficient**：每位已激活种子用户带来的已激活同事数。高匹配组织中，该数值超过 1.0 时，LOGAN 将形成复利式的工作空间扩张。

### 指标口径

- **合格用户：** 符合目标角色与公司画像、并完成基本工作空间配置的用户。
- **真实工作来源：** 经用户批准、包含生产环境消息、日历、文件或任务数据的 Connector；演示数据不计入。
- **周期工作流：** 被配置为按固定频率或由明确事件重复运行的工作流。
- **周度依赖用户：** 在连续一周内查看、使用或依赖 LOGAN 完成至少一项工作产物的用户。
- **同事触达：** 非用户同事通过任务、审批、共享产物或更新请求，实际接触到 LOGAN 产出的工作内容。
- **Workspace Viral Coefficient：** 在种子用户激活后的 30 天归因窗口内，由其工作流带来的已激活同事数；该指标按高匹配账户分组追踪。

## 9. 执行原则

- 聚焦高上下文用户和具体高价值工作流；
- 先验证工作流留存与协作价值，再扩大分发；
- 将工作成果、Recipe、审批和同事协作设计为增长入口；
- 让生态集成绑定明确的客户与渠道分发；
- 以实践型专家和客户工作成果建立可信内容；
- 以个人 → 团队 → 组织 Memory → 企业执行层的路径扩大客户价值。

## 10. 投资人 / 评审摘要

LOGAN 从 10—200 人组织内的高上下文操作者切入，让每位新用户在 72 小时内委托一项周期工作。产品通过任务负责人、协作审批、共享 Recipe、可分享工作产物和团队 Memory，让真实工作自然触达同事；同事在注册前先体验价值，再激活自己的 LOGAN。

随着更多工作进入系统，组织上下文、专家方法、客户关系、历史决策与反馈持续累积，带来更好的执行与更高的组织沉淀价值。LOGAN 因此能够沿着个人价值 → 团队协作 → 组织 Memory → 企业执行基础设施的路径增长。

> 通往百万用户的最快路径，不是获得一百万个独立用户，而是让一家公司中的一位用户足够有价值，以至于另外 99 位用户自然需要加入。
