# CEO Agent 功能清单

> 本文以当前代码为准，按产品功能说明已存在的业务能力；不将设计稿、页面演示或尚未落地的设想写入功能清单。

## 一、基本信息

- 核验时间：2026-08-10
- 代码版本：当前本地开发工作区（未发现独立的产品版本号）
- 核验范围：CEO Agent Service 主仓及关联 worktree
- 产品定位：帮助企业管理者在现有钉钉、微信工作流中处理消息、工作事项和管理协同的本地优先 Agent 服务
- 状态说明：以下为当前源码已实现的功能；真实账号授权、服务进程和外部系统配置未在本次文档中验证

## 二、背景和结论

管理者的工作信息分散在消息、文档、审批、日程和会议中。CEO Agent Service 将这些信息接入同一个可审计的本地工作流：先识别需要本人处理的事项，再结合上下文给出受约束的处理结果，并保留人工接管和回看入口。

当前代码已覆盖钉钉消息处理、工作画像、事项跟进、会后对齐、审计与恢复等能力；微信通道也已有受范围和人工确认约束的处理代码。所有外发动作都受试运行和正式发送门禁控制。

## 三、功能清单

### 3.1 接收和理解钉钉消息

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 找到需要处理的消息 | 系统定时查看未读消息、明确点名消息和配置机器人私聊，找出需要管理者关注的事情。 | 群聊必须明确 @ 管理者；私聊可直接进入判断。 |
| 识别消息是什么情况 | 系统区分私聊、群聊、文档、图片、审批、日程邀请、会议权限和系统通知，再按情况处理。 | 普通群消息和系统通知不会被自动回复。 |
| 把有关消息放在一起 | 将同一个人连续发来的相关消息合并成一件事，避免重复回复或漏掉上下文。 | 每件事都会进入本地处理队列。 |
| 补齐判断所需资料 | 在权限允许时读取聊天记录、钉钉文档、文件、图片和本地工作资料，帮助系统了解完整情况。 | 资料不足或读取失败时，系统会等待补齐或稍后重试。 |

### 3.2 判断并处理消息

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 判断该怎么处理消息 | 系统会把每条消息分为：直接回复、先追问、无需回复、交给本人，或停止处理。 | 每次判断都会记录原因和处理摘要。 |
| 生成回复内容 | 系统根据消息和已读取的资料生成回复，并检查是否泄露本地路径、令牌等敏感信息。 | 过长的回复会按钉钉限制分段发送。 |
| 交给本人处理 | 需要本人承诺、决策，或对方明确要求找真人时，系统会把事情交回管理者。 | 接管后自动回复暂停，直到检测到管理者本人回复。 |
| 先问清楚再处理 | 关键事实不足时，系统会先向对方追问，不会编造结论。 | 追问后可根据补充信息继续处理。 |

### 3.3 回复、审批和日程

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 回复钉钉消息 | 将已通过检查的回复发送到群聊原消息或私聊，并记录是否发送成功。 | 真实发送前仍需通过正式发送门禁。 |
| 处理审批请求 | 读取审批详情、流程、附件和工作规则后，给出审批处理、补充说明或交给本人。 | 资料或规则不充分时，不会把猜测当作审批决定。 |
| 回复日程邀请 | 读取日程信息和冲突情况后，按判断结果回应日程邀请。 | 日程操作与消息回复分别留下记录。 |

### 3.4 学习管理者的工作方式

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 整理管理者的工作方式 | 从本地工作文档、AI 听记、历史发送样例和可读钉钉知识库中，整理管理者的判断重点、表达方式和工作边界。 | 需要主动构建，后续处理消息时会作为参考。 |
| 说明工作方式从哪里来 | 每条工作习惯都保留对应的证据来源，方便管理者回看依据。 | 没有来源的信息不会直接被当作管理者偏好。 |
| 记住以后还会用的信息 | 将经过处理的信息写入长期记忆，帮助后续任务回忆过去的决定和偏好。 | 需要已配置并授权的 Memory Connector。 |

### 3.5 把消息变成待办并跟进

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 从消息中找出待办 | 从已处理对话、AI 听记和工作资料中找出项目、待办、下一步和重要事实。 | 待办保存在本地工作项目中。 |
| 更新待办进度 | 为待办记录负责人、优先级、截止时间、风险、完成情况和来源。 | 可在审计页面查看项目和待办详情。 |
| 同步到钉钉待办 | 将符合条件的内部待办同步到钉钉，并同步回收钉钉里的完成状态。 | 内部待办是主记录，钉钉待办用于执行和提醒。 |
| 到期时继续跟进 | 为重要事项准备跟进内容；到期时检查是否已完成、过期或不适合发送。 | 已失效、已完成或高风险的事项会跳过或延后。 |

### 3.6 会后和 OKR 协同

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 会后整理共识和待办 | 对符合规则的已结束会议，整理需要统一的观点、下一步和责任人。 | 仅在有观点分歧或需要管理者观点解读时生成内容。 |
| 把会后信息发给相关人 | 根据会议类型和参会情况选择群聊或私聊，只点名相关参会人。 | 发送前仍受同一套外发门禁控制。 |
| 帮忙审核 OKR | 识别 OKR 审核请求，读取配置的实时 OKR 数据后生成审核结论。 | 需要配置可用的实时数据源。 |

### 3.7 管理台：查看和复核处理记录

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 查看处理总览 | 首页展示最近 24 小时的处理量图表和处理记录概览。 | 页面会自动刷新，便于查看服务当前状态。 |
| 查看回复消息列表 | 集中查看消息回复、会议和待办等处理记录。 | 支持搜索、按状态和对象类型筛选、分页查看。 |
| 查看单条消息的处理详情 | 打开一条记录后查看原消息、系统判断、参考资料、生成回复、发送结果和错误原因。 | 可从详情进入相关会话或查看关联记录。 |
| 查看项目和待办进展 | 在审计工作台查看项目、待办、跟进内容及其来源和处理状态。 | 可按状态、类别等信息查看。 |
| 查看错误和运行日志 | 单独查看处理失败、运行日志和当前处理状态，帮助定位问题。 | 支持按类型搜索和分页查看。 |
| 查看智能处理过程 | 查看每个对话关联的 Codex 会话，以及对应的消息或会议处理记录。 | 本地会话文件不存在时仍保留关联记录。 |
| 人工检查和补救 | 可以对历史处理补充反馈、重新运行一次处理，或撤回可撤回的已发送消息。 | 每次操作的结果都会保留在记录中。 |
| 收集对回复的反馈 | 记录管理者或对话方对回复的评价和处理状态，便于后续人工复核。 | 外部点赞/踩反馈链接需要单独部署反馈服务。 |
| 调整服务规则和提示词 | 在配置页查看和修改系统配置、微信配置、Developer Prompt 和 User Prompt，并预览提示词效果。 | 修改的是本机服务配置。 |
| 引导完成服务配置 | 通过安装引导页检查组件、运行可执行操作并记录每一步的完成状态。 | 登录授权、系统权限和正式发送确认仍需使用者本人完成。 |
| 接收浏览器通知 | 在浏览器允许通知后，服务可以推送提醒；点击提醒可打开对应钉钉会话。 | 依赖浏览器通知权限。 |

### 3.8 安全发送和异常恢复

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 先试运行，再决定发送 | 试运行只记录系统判断，不向外发送；正式发送还需打开明确确认开关。 | 由服务端统一控制。 |
| 防止同一件事被处理两次 | 记录已发现消息、处理事项和已发送回复，避免重复处理或重复发送。 | 本地队列使用 SQLite 保存。 |
| 失败后继续处理 | 遇到可恢复的外部错误会按间隔重试；服务启动和定时检查会找出卡住或未完成的事项。 | 外部状态不明确时交给人工，避免盲目重发。 |
| 发送前做好安全检查 | 发送前检查敏感信息、工作规则、权限和 SOP 要求。 | 用于降低风险，不代表所有消息都会自动处理。 |

### 3.9 处理微信消息

| 功能 | 功能说明 | 备注 |
| --- | --- | --- |
| 选择要处理的微信会话 | 识别本机微信账号，并由使用者选择允许处理的私聊或群聊。 | 需要本机 Reader 和 macOS 辅助功能权限。 |
| 找到需要回复的微信消息 | 在已选会话中，私聊处理收到的文本消息；群聊只处理明确 @ 当前账号的消息。 | 微信消息使用独立队列，不会重复创建待处理事项。 |
| 生成待确认的微信回复 | 系统根据消息上下文生成回复，并保存为待发送记录。 | 在确认模式下，生成回复不会立即发送。 |
| 确认后发给正确的人 | 只向已验证、没有歧义的会话对象发送；使用者可批准或拒绝每一条待发回复。 | 发送后记录成功、失败或状态不明确；状态不明确不会自动重发。 |
