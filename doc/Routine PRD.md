## 1. 背景与目标

用户从推荐区创建 Routine，为它选择一个核心 Skill，再配置执行星期、开始生成时间、交付对象、文件格式和视觉样式。正式能力按日程生成结果，将正式生成的文件收录至 Library；配置了推送对象时，再发送到指定群聊或个人。未选择对象时只生成并归档。当前前端交付使用示例数据体验流程，见 3.1 节。

用户只需管理“用什么能力生成、何时生成、发送给谁、如何呈现”。内容理解与生成逻辑由 Skill 承担；Routine 负责执行与交付。本 PRD 不定义 Agent 内部检索、工具调用、调度实现或推理策略，也不将规划能力描述成已实现能力。

## 2. 依据与术语

### 2.1 产品依据

- 用户在本次讨论中确认的规则优先于旧 PRD 的冲突内容。
- 已于 2026-09-12 拉取钉钉原文：[Message](https://alidocs.dingtalk.com/i/nodes/m9bN7RYPWdbednwAijXE2v45JZd1wyK0)、[Onboarding](https://alidocs.dingtalk.com/i/nodes/mExel2BLV5xpQm0wsp3z7jQRWgk9rpMq)、[Settings](https://alidocs.dingtalk.com/i/nodes/P7QG4Yx2JpEnpRkgiqXmPPaG89dEq3XD)。原文与差异见[同步记录](sources/dingtalk-2026-09-12/README.md)。
- 竞品截图仅作为布局参考。竞品的 Webhook、分享链接、团队复制、邮件专属配置等不纳入本期；本期 Skill 规则以本文为准。
- 本文标注“建议”的内容尚未经单独确认，其余为已确认规则或对已确认交互的具体展开。

### 2.2 核心对象

| 名称 | 含义 | 关系 |
| --- | --- | --- |
| Skill（能力） | Friday 提供的、用于理解已连接工作资料并生成结果的能力 | V1 每条 Routine 必须且只能选择一个核心 Skill |
| Routine（日程实例） | 用户创建的独立自动化，拥有自己的 Skill、时间、推送、格式和 Style 配置 | 修改或删除一个实例不影响其他实例 |
| Style（样式） | 控制同一份内容的视觉呈现 | 不改变 Skill 的内容逻辑；仅 PDF 可用，不支持用户上传背景 |
| Session（执行记录） | 一次正式执行的生成与发送结果 | 由 Recent Sessions 展示；不等同于外部输入 Message |

Skill 是内容控制的唯一入口，替代旧的“内容模板、主题总结、详细 Prompt”三套并行设置。首期通过星期多选设置执行日，暂不支持每月执行。

### 2.3 Connector 与内容边界

- 同一 Friday 用户可同时连接多个不同 Connector，每种 Connector 只连接一个账号；各自的 Routine 可以同时运行。
- 内容由核心 Skill 决定，并按需要召回当前用户有权使用的 Memory，不按 Connector 划分取材范围。
- Connector 在 Routine 推送配置中用于选择渠道和收件人；推送渠道不限制内容来源。
- 一个日程可跨多个已连接 Connector，选择多个群聊和个人。
- 同一日程的所有收件人共用相同文件格式；选择 PDF 时共用相同样式模板。
- 定时生成记录由 Recent Sessions 承载，不因定时触发而自动创建一条外部输入 Message。

### 3.1 本次前端交付边界

- 本次只实现 Routine 前端，沿用当前应用 UI 设计语言；不建设 Library 页面，不接入真实调度、内容生成或消息发送。
- 使用明确标注的示例数据，让用户完整体验创建、编辑、收件人选择、试运行预览和执行记录。示例收件人不代表真实通讯录，示例文章不代表已召回用户资料，演示发送状态不代表真实投递。
- 保留服务接口及 Routine 所需的文件查看、Library 跳转接口，供后续接入真实能力。没有可用目标地址时不得提供失效跳转，不能将预留接口标记为已接入。
- 首次空态及未执行记录按产品规则保留，演示数据与真实记录必须可区分。
- 本文关于正式生成、归档及发送的规则是产品行为约定，不作为本次后端能力完成的证明。

## 4. 页面信息架构与布局

### 4.1 全局入口

Routine 作为 Friday 工作区导航入口，与现有页面共用应用侧栏。本次不建设 Library 页面，只保留 Routine 所需的文件查看和 Library 跳转接口。沿用 Friday 全局 Settings，不新增独立的账号或 Connector 管理入口。UI 使用 HeroUI 的表单、选择、Tab、弹窗、折叠区与按钮等组件；仅针对页面布局和文档样式编写定制排版。

页面采用已确认的 V2 布局：浅色应用侧栏、白色主画布、黑灰文字、轻边框和细分隔线。卡片负责展示摘要，完整配置和结果在对应详情中查看。主区不堆叠说明、标签与状态，不为了单屏展示压缩字段或字号。

### 4.2 Routine 首页

页面顺序为标题与一句简介 → 推荐 → 我的日程。

```text
应用侧栏 │ Routine
         │ 让重复的工作，按时完成。
         │
         │ 推荐
         │ ┌ 创建 Routine ─────┐
         │ │ 图标              │
         │ │ 名称              │
         │ │ 两行能力简介      │
         │ │ [添加 / Add]      │
         │ └───────────────────┘
         │
         │ 我的日程
         │ ┌ 项目周报 ─── ⋯ ┐ ┌ 今日工作简报 ─ ⋯ ┐
         │ │ 一句内容摘要    │ │ 一句内容摘要      │
         │ │ 每周五 18:00    │ │ 每天 09:00        │
         │ └─────────────────┘ └───────────────────┘
```

- 推荐采用独立竖向白色卡片：顶部图标、名称、两行简介，底部固定宽度主按钮。不做横跨页面的 Banner。
- 首发只放一张“创建 Routine”卡片，剩余位置留白，不复制卡片凑数。用户可重复创建 Routine；个性化推荐算法不属于本 PRD。
- 我的日程采用较低的摘要卡片网格，宽屏一行可放三张，随可用宽度换行。
- 日程卡片只展示名称、核心 Skill 的一句描述、执行星期与开始生成时间、右上角更多菜单；不展示主题标签组、下次执行时间、推送对象数量、渠道或文件格式，也不常驻“修改设置”按钮。
- 点击卡片进入 Recent Sessions；更多菜单提供“修改设置”“开启／关闭 Routine”和“删除”。Routine 开启与关闭互斥；关闭后停止后续自动执行。
- 首次无日程时显示“还没有日程，从上方添加一个开始”，不展示模拟执行记录。

### 4.3 创建 Routine

点击推荐卡片的“添加”后，直接进入一条新的 Routine 的 Settings。新建 Routine 默认没有核心 Skill；用户先在“核心能力”中完成选择，再保存配置。

- 名称可编辑，默认“早间简报”；重复添加使用数字后缀“早间简报 2、早间简报 3”等。
- 默认星期一至星期日全选、开始生成时间为 09:00；不预选推送对象。
- 默认格式为 PDF，默认 Style 为第一款“刊物（Edition）”；可在 Style Tab 切换其他 PDF 样式。
- 未选择核心 Skill 时，保存和试运行均提示先选择一个核心能力；不创建可运行的空 Routine。
- 新 Routine 保存后形成独立实例；不会因为创建或保存动作立即生成或发送，按下一次计划时间执行。

### 4.4 日程详情页

三个详情 Tab 共用同一布局：顶部面包屑，左侧固定视觉卡片与操作，右侧标题、简短说明和 Tab 内容。卡片比例、标题起点、Tab 高度和按钮位置在三个页面中保持一致。

```text
Routine > 项目周报

┌ 左侧视觉卡片 ────┐   项目周报
│ 封面             │   每周整理重点工作。
│                  │
│ 实例名称         │   Recent Sessions | Settings | Style
│ 两行简介         │   ─────────────────────────────────────
└──────────────────┘   当前 Tab 内容
   ▶ 试运行
  [  保存  ]
     删除
```

- 左栏为固定比例的视觉封面＋名称＋简短说明，不再重复展示时间、时区、渠道、人数或格式。配置统一留在 Settings。
- 卡片下方纵向提供试运行、保存、删除。保存是唯一实心主按钮，试运行是轻量次操作，删除采用文字操作；不在按钮下堆叠规则说明。
- 保存作用于整个实例的草稿，包括名称、核心 Skill、日程、目标、格式和样式，不只作用于当前 Tab。
- 在三个 Tab 间切换保留草稿，不视为离开详情。
- 左侧操作的可点击范围与封面卡片同宽；不因按钮文字较短而缩小可用范围。
- 长内容自然滚动，左侧卡片与操作在桌面窗口中保持可访问；窄窗口可上下排列，不强行缩小字体。

### 4.5 核心 Skill 的视觉语言

- Routine 左侧封面使用无文字的高级纯视觉图片，暖黄与光影为主；不把 Skill 信息写进封面图。
- Skills 采用与 Routine 一致的紧凑卡片语言：图标、标题、创建者、描述；不使用大幅图片卡片。
- Skill 图标是实色圆角色块与暖白线框图标，线框约占色块的三分之二。首期能力色：早间简报为橙色 `#FF9F0A`，项目周报为蓝色 `#3B82F6`，风险与阻塞为紫色 `#6366F1`。
- 黑色是主要操作色。“更换”等核心操作使用黑底暖白字；“更换”与核心能力模块右边界对齐，不占用已选 Skill 卡片内部空间。
- 红、绿、天蓝等色保留给未来具有明确语义的 Skill，不为补齐色板提前引入未使用的能力。

## 5. Settings 功能与字段

Settings 采用可自然滚动的单列长页，顺序为核心能力 → 执行安排 → 发送到 → 格式。模块之间用留白及细分隔线区分，不为每个字段嵌套卡片。

- 核心能力使用完整行宽的选中卡片或空状态，不并排堆叠其他内容控制项。
- 执行安排只提供两个选择控件：星期多选和开始生成时间单选，各占一行。标签和必要的一句说明在左，控件在右；不再提供每天／每周／每月频率下拉框或每月日期控件。固定时区以说明文字展示。
- 推送区按 Connector 展示简短的已选对象摘要，通过“编辑”打开对象选择弹窗，不常驻逐人表格。
- 格式采用单选下拉框，三个选项为 PDF、MD、Word，不展开成大卡片。
- 实例名称保留可编辑能力；点击详情标题进入名称编辑，不再单独占据常驻表单首行。
- Settings 允许纵向滚动，不要求所有字段同时出现在一个桌面视口内。

### 5.1 核心能力

核心 Skill 决定这条 Routine 如何理解已连接的工作资料并生成结果。它是内容逻辑的唯一控制入口；不再同时展示或维护内容模板、主题总结和详细 Prompt。

```text
核心能力                                                  [更换]
决定这条 Routine 如何理解工作资料并生成结果。

┌ [图标] 项目周报能力                                      ┐
│        Friday 创建                                       │
│        汇总本周成果、项目进展、风险与下周重点。          │
└─────────────────────────────────────────────────────────┘
```

- 未选择时显示“选择核心能力”空位；点击后从右侧打开 Skills 侧边栏。
- 侧边栏只展示适配当前 Routine 的内置 Skill 卡片。卡片包含图标、标题、创建者和描述；点击卡片进入详情，不在列表中直接添加。
- 详情页展示能力说明、输入、产出与编辑边界。当前 Skill 只读，用户不能编辑或创建自定义 Skill。
- 用户在详情页点击 Add 后，侧边栏关闭，Skill 加载为当前 Routine 的核心能力。
- 已选择的 Skill 卡片可再次点击查看详情；“更换”位于核心能力模块右上角，用于重新打开选择侧边栏。
- V1 一条 Routine 只能选择一个核心 Skill。未来若有真实的多能力需求，再设计选择顺序、依赖和组合规则。

首期提供三项 Friday 内置 Skill：

| Skill | 作用 |
| --- | --- |
| 早间简报能力 | 整理当天重点、待办与需要关注的事项 |
| 项目周报能力 | 汇总本周成果、项目进展、风险与下周重点 |
| 风险与阻塞复盘 | 识别当前风险、阻塞与待确认的依赖 |

### 5.2 日程设置

执行星期采用 HeroUI 多选下拉框。收起时展示已选择的星期；展开后列出周一至周日，选中项显示勾选标记，未选项不显示勾选标记。

| 字段 | 行为 |
| --- | --- |
| 执行星期 | 星期一至星期日，支持多选；每个选中的星期均在所选时间执行一次，每周重复。全选即每天执行 |
| 开始生成时间 | 单选下拉框；00:00–23:30，每半小时一档，共 48 个选项。所有选中星期共用一个时间；含义为开始生成，不承诺在该时间送达 |
| 默认值 | 新建时星期一至星期日全选，时间为 09:00；用户可修改 |
| 时间说明 | 到所选时间开始生成；配置了推送对象时，生成完成后发送 |
| 时区 | 使用并固定创建日程时的用户时区，显示具体时区；之后设备时区变化不改变该日程时区 |

不提供每月执行或每月日期设置。例如选择星期一、三、五及 09:00，即每周一、三、五 09:00 各开始生成一次。

- 不提供独立的取材时间范围字段；资料如何被 Skill 使用由该 Skill 的只读定义决定。
- 更换核心 Skill 不自动改变已选星期和时间。
- 新配置从下一次执行生效；已经开始的执行保持启动时配置。
- 未保存草稿不影响原日程，它仍按上次保存配置执行。

### 5.3 发送到

先选择已连接 Connector，再弹窗选择发送对象。

```text
发送到
                                                [添加]

钉钉   项目组、陈思睿                    [编辑]
Teams  产品组                            [编辑]
```

收件人弹窗布局：

```text
选择发送对象                                      ×
[搜索人员或群聊]
□ 名称               可用的组织／成员等辅助信息
□ 名称               可用的辅助信息
已选择：若干对象
                                    [取消] [确认选择]
```

- 先从已连接的 Connector 中添加渠道；未添加的已连接渠道紧接在“添加”按钮下方出现。
- 选择渠道后，在同一个搜索入口中查找群聊或个人并多选，不拆分群聊／个人 Tab。
- 名称相同的对象展示可供辨认的辅助信息，不让用户凭名字猜测。
- 确认选择后汇总到 Settings，以渠道名称和对象摘要展示；点击“编辑”重新打开选择弹窗，可增删该渠道的群聊和个人，也可继续添加其他 Connector。
- 同一 Connector 下的同一目标去重；跨 Connector 的对象分别显示。
- 真实目标列表加载失败提供重试，不以模拟对象冒充真实查询结果；取消弹窗不修改原有目标。前端演示可使用明确标注的示例对象，见 3.1 节。
- 无已连接 Connector 时提示可去 Friday 全局设置连接；用户仍可不配置推送，继续添加或保存。
- 发送是可选项，正式添加、保存及试运行均不要求推送目标。无目标时正式日程只生成并归档，不执行发送；有目标时向所选对象发送。
- 多目标共用格式和 PDF 样式；需要不同格式时，重复添加一个独立日程。

### 5.4 文件格式

- 单选 PDF、MD、Word；Word 指可下载的 `.docx` 文件，MD 指 `.md` 文件。暂不支持 PNG。
- 格式作用于同一次正式生成及其全部推送目标。
- 默认 PDF；用户选择其他格式时保留其内容配置。

## 6. Style Tab

- Style 只控制同一份内容的视觉呈现，不控制内容结构、Skill 或执行时间。
- 右侧默认只展示“选择 PDF 样式”、一句说明和样式缩略图网格；宽屏一行展示三款，更多样式自然换行。
- 每款样式只显示文档缩略图、名称和选中状态，不常驻大幅预览、格式徽标或重复的“已选择”说明。
- 选择样式更新草稿选中态；缩略图预览入口在页面内部右上区域打开按需放大的预览层，关闭后回到样式列表。预览不等于保存，正式生效仍通过左侧保存。
- 非 PDF 时用提示和“切换为 PDF”按钮替代整个样式选择区；PDF 状态下不再同时显示该提示。

- PDF 格式下展示系统预设样式缩略图、样式名称、预览与选中状态。
- 样式不改变 Skill 的内容逻辑或执行时间。
- 不支持上传背景或自定义模板编辑器。
- 默认选中第一款“刊物（Edition）”样式。
- 非 PDF 时显示“切换为 PDF 后可使用样式模板”，提供“切换为 PDF”按钮；切换写入草稿，保存后才正式生效。
- 从 PDF 切换其他格式时，保留原样式选择但不应用；切回 PDF 后恢复选择。
- 首期三款样式已确认，详见 6.1 节；确认设计不代表文件生成服务已经上线。

### 6.1 已确认的三款 PDF 样式

| 样式 | 视觉方向 | 默认状态 |
| --- | --- | --- |
| 刊物（Edition） | 暖白纸面、衬线标题、侧栏与细分隔线组织正文 | 默认选中 |
| 简讯（Signal） | 白色纸面、无衬线标题、蓝紫色小面积强调与清晰的分区 | 可切换 |
| 画册（Folio） | 深墨色页首、浅色正文、衬线标题和克制的分栏 | 可切换 |

以用户确认的[三款正文排版样稿](design/routine-pdf-approved/three-styles.png)为实现依据，实际模板应展示正文排版而非只有封面。本次采用自设计样式，不采用此前检索的 Quill 模板。样稿用于确定视觉，不能将样稿图片本身冒充可用的 PDF 模板。

## 7. 试运行、保存与离开

### 7.1 试运行

1. 使用当前草稿的核心 Skill、格式与 Style 生成预览，无须先保存正式配置。
2. 点击后展示生成中状态，防止重复提交。
3. 完成后打开预览层，显示生成文章内容；关闭后回到详情并保留草稿。
4. 不发送给任何对象，不改变日程，不纳入 Library。它是正式文件全收录规则的例外。
5. 生成失败或资料不足时显示原因并允许返回修改；不展示空白文件为成功结果。
6. Recent Sessions 仅列正式执行，试运行结果只保留在当前预览中，不写入执行记录。

### 7.2 保存

- 保存整个实例配置，包括核心 Skill、日程、收件人、格式和 Style。
- 保存成功后草稿成为正式配置，后续执行使用新配置。
- 保存失败保留草稿及原正式配置，用户可重试。
- 已经开始的执行不受本次保存影响。

### 7.3 有未保存修改时离开

仅在用户准备离开详情时弹出，不在每次字段修改时打断。

```text
有未保存的修改                                     ×
保存后，后续日程才会使用当前配置；
未保存时仍按原配置执行。

                              [取消保存] [保存]
```

| 操作 | 结果 |
| --- | --- |
| 取消保存 | 放弃本次全部未保存修改，恢复原配置，并继续原定离开动作 |
| 保存 | 保存成功后继续离开；校验或保存失败则保留草稿，停留详情 |
| × | 关闭弹窗，留在编辑页面，保留未保存修改 |

返回首页、切换到 Library／Message 等页面属于离开；切换详情内部 Tab 不属于离开。应用关闭是否能拦截取决于宿主能力，不承诺无法实现的关闭保护。

## 8. Recent Sessions

### 8.1 列表

Recent Sessions 标题下显示“查看每次生成与发送结果。”的说明。列表按开始生成时间倒序展示正式执行记录；它是执行历史，不是配置页。

- 每行只展示相对时间、Routine 名称、状态标签和右侧更多操作，不展示左侧状态 Icon、正文、文件块、收件人或失败原因。
- 当天执行显示时分；跨天执行只显示日期，不显示完整年月日时分。
- 状态标签统一置于行的右侧，使用固定宽度、有颜色边框的外框区分状态；不以前置图标区分。
- 列表不使用横向分隔线；行间距紧凑。鼠标 hover 或键盘聚焦时，整行显示圆角选中框。
- 每条记录右侧均为更多操作按钮。点击后才出现可用操作，不在行内直接摆放“查看详情”或“重试”。

V1 的列表状态收敛为五种：

| 状态 | 含义 | 更多操作 |
| --- | --- | --- |
| 生成中 | 正在生成，尚未有可查看结果 | 无 |
| 已生成 | 已生成文件，尚未发送 | 查看详情 |
| 已发送 | 已向目标完成发送 | 查看详情 |
| 发送失败 | 已生成文件但发送未完成 | 查看详情、重试发送 |
| 生成失败 | 未生成可查看文件 | 重试 |

未执行过时显示“日程执行后，你可以在这里查看生成内容和发送结果”。

### 8.2 单次记录详情

- 顶部：日程名称、本次开始时间、触发类型和结果摘要。
- 正文：生成内容预览或文件入口；正式文件可跳转 Library 查看。
- 推送结果：按 Connector 分组，逐个显示群聊／个人及其结果。
- 发送失败详情提供可读原因和适用的重试操作；生成失败没有详情入口，只可从更多操作中重试。

| 情况 | 显示与操作 | Library |
| --- | --- | --- |
| 生成中 | 无详情入口 | 未形成文件前无条目 |
| 已生成 | 展示文件入口 | 已收录 |
| 已发送 | 展示文件及各目标结果 | 保留文件 |
| 发送失败 | 展示文件、失败原因及失败目标；允许仅重试失败目标 | 保留原文件 |
| 生成失败 | 没有详情入口；在更多操作中重试 | 未生成文件则不新增 |

- 重试发送复用原文件，不能重新生成或再次发送给已成功的目标。
- 发送结果未知时应明确显示“结果待确认”，不能直接视为失败而重复发送；处理方式留给执行能力定义。
- 同一次生成向多个目标发送只对应同一个文件，不因目标数或重试次数重复收录。

## 9. 删除日程

- 首页更多菜单和详情左侧删除按钮指向同一操作。
- 删除前显示确认弹窗：“删除此日程后将停止后续执行，Library 中已有文件会保留。”
- 确认删除后从我的日程移除，不影响同一模板创建的其他实例。
- Library 已生成文件保留，来源标注“原日程已删除”。
- 删除时若已有执行正在进行，其继续生成／发送还是终止尚未确认；本版不将停止后续执行等同于撤销已经开始的动作。

## 10. 关键完整流程

### 添加并正式执行

打开 Routine → 推荐卡片 Add → 进入新 Routine 的 Settings → 在核心能力空位中选择 Skill → 配置执行星期、开始时间、格式和可选推送对象 → 保存 → 我的日程出现实例 → 到所选星期和时间开始生成 → 正式文件进入 Library → 配置了对象则发送，未配置则不发送 → Recent Sessions 记录生成与发送结果。此为正式能力流程；本次仅按 3.1 节交付前端演示。

### 修改与试运行

我的日程卡片更多菜单 → 修改设置 → 查看或更换核心 Skill → 调整执行与交付配置 → 试运行 → 查看预览 → 返回继续修改 → 保存 → 下一次执行使用新配置。试运行不发送、不归档。

### 部分发送失败

文件生成并归档 → 部分对象发送失败 → 查看本次执行详情 → 重试失败目标 → 复用原文件 → 更新失败目标结果，已成功目标不重复发送。

## 11. 尚待确认的细节

以下规则尚未逐项确认，不因本次同步而成为已定案行为：

- 已经开始的执行在删除日程后如何处理（真实执行服务范围）。
- 应用不在线时的执行规则。
- 全局免打扰是否影响 Routine 推送；已确认的开始时间含义保持不变。
- 全局完成通知入口：云端 Onboarding 的时钟／铃铛规则仍有冲突。本版以 Recent Sessions 承载执行结果，不自行扩展通知约定。

涉及当前前端落地的待定项，每次仅向用户提出一个简短决策问题；不将批量粘贴的方案视为用户确认。
