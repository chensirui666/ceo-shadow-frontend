# Friday 成本与计费口径

> 版本：2026-09-08
> 目的：先统一 Friday 每次使用真正花在哪里，以及 Free / Pro 的费用归属。这里不设订阅价格、不设用户额度数量；这两项在成本数据跑出来后再定。

## 1. 结论：Friday 的总成本公式

Friday 的成本仍按四个账本看。Memory 的“写入”账本不只有内容处理，还包含存储和可能发生的 Embedding 调用。

```text
当期总成本（USD）
= 工具调用成本
+ 模型 Token 成本
+ Memory 写入成本（内容处理 + Embedding + 存储）
+ Memory 召回成本
```

拆开写：

```text
总成本
= 外部工具调用次数 × $0.008
+ 模型输入 / 输出 Token × 当前模型供应商单价
+ 纯文本写入 Token / 1,000 × $0.0005（使用deepseek的模型）
+ 富文本写入 Token / 1,000 × $0.001
+ Embedding Token × Embedding 模型供应商单价（仅启用 Embedding 的方式）
+ Memory 实际占用存储 GB × 存储供应商单价 × 存储时长
+ Memory 搜索次数 / 1,000 × $0.005
```

三个原则：

1. **工具成本、模型成本、Memory 成本分开记账。** 不能把一次「回复消息」粗暴按固定条数收费。
2. **用户使用自己的 API Key 时，只有模型成本转移给用户。** 搜索和 Memory 仍是 Friday 的服务成本，仍需从 Friday 额度或订阅中覆盖。
3. **所有成本先换算成美元记账。** 用户日后购买的是 Friday 的统一余额；具体卖价、赠送额度和折扣另行确定，不在这里假设。

## 2. 每一项的真实逻辑

### 2.1 工具：外部工具调用

| 动作 | 计费单位 | 价格 |
| --- | --- | --- |
| 外部工具调用 | 请求次数 | **$0.008 / 次** |

对用户不暴露 Friday 底层接入了哪个第三方服务；统一按“外部工具调用”记账。

### 2.2 模型：用户自带 Key 或 Friday 代付

| 使用方式 | 谁付模型供应商 | Friday 的模型成本 |
| --- | --- | --- |
| 用户自己的 API Key | 用户直接向 OpenAI、DeepSeek 等模型供应商付费 | $0 |
| Friday 提供模型 | Friday 向当前接入的模型供应商付费 | 按实际输入、缓存、输出 Token 单价扣除 |

当前 Memory 写入链路主要采用 DeepSeek。普通对话 / Agent 的模型成本也按实际所选模型结算，不能用一个固定的「每条消息价格」覆盖。

### 2.3 Memory：写入、存储与召回是三件事

根据俊杰的评估，Memory 写入成本约 90% 来自模型调用。原来的“写入价格”只覆盖内容处理；实际 Memory 成本还要加上持久化存储，以及启用 Embedding 时的模型调用和向量存储。

| 动作 | 计费单位 | 价格 |
| --- | --- | ---: |
| 写入纯文本 Memory | 新增并处理的纯文本 Token | **$0.0005 / 1K Token** |
| 写入富文本 Memory | 新增并处理的富内容 Token | **$0.001 / 1K Token** |
| Memory 召回 | 搜索请求 | **$0.005 / 1,000 次** |

Memory 写入有四种方式；它们不是四个面向用户单独售卖的产品，而是同一份内容可选择的处理深度：

| 写入方式 | 会产生什么成本 |
| --- | --- |
| 只存文档 | 原始文档的持久化存储 |
| 存文档 + BM25 检索 | 原始文档存储 + BM25 索引存储 / 构建 |
| 存文档 + Embedding + BM25 | 原始文档存储 + BM25 索引 + Embedding 模型调用 + 向量存储 |
| Graph Memory | 原始文档存储 + 图谱抽取的模型调用 + 图数据存储；若同时启用 BM25 或 Embedding，则叠加对应成本 |

因此，Memory 的完整成本公式是：

```text
Memory 成本
= 内容写入 / 理解成本
+ Embedding 模型调用成本（仅 Embedding 路径）
+ 文档、索引、向量和图数据的存储成本
+ 召回成本
```

对用户的容量上限，建议只统计“用户保存的原始内容大小”，不要把 BM25、向量和图谱等派生索引也折算成用户的 GB。否则同一份文档仅仅因为换了检索方式就会突然变大，用户无法理解；这些派生数据的真实成本由 Friday 在写入方式和统一余额中覆盖。

这意味着：

```text
写一段 10K 纯文本到 Memory       → $0.005
写一段 10K 富文本到 Memory       → $0.010
进行 1 次 Memory 搜索            → $0.000005
```

纯文本与富文本的区分沿用 Supermemory 的产品口径：直接的文字、Markdown、代码、聊天记录按纯文本；需要解析文件、OCR、转写或多模态理解的 PDF、图片、音视频、Office 文件等按富文本。

### 2.4 存储额度降级：不自动删除，先停止新增写入

例如，Plus 给 5GB，用户已使用 3GB；用户降级到 1GB 的 Free 后，不能自动删除其中 2GB。正确做法是将账户标为“超出 Memory 容量”：

1. 已存的 3GB 保留，用户始终可以查看、导出和删除；
2. 停止新的文档写入、BM25 / Embedding 建索引和 Graph 更新；
3. 已存内容仍可在 Free 的智能体额度内被召回；用户删到 1GB 以内或重新升级后，自动恢复写入；
4. 不做静默自动删除。若以后需要控制长期超额成本，应另行设计“归档提醒 + 用户确认”的规则，不能把删数据当成默认降级动作。

Apple iCloud+ 采用相近原则：用户降级后若已用空间超过新套餐，iCloud 会停止同步、更新和备份；用户删出空间或升级后才恢复，而不是自动删除内容。详见 [Apple 官方说明](https://support.apple.com/en-us/108318)。

### 2.5 一次真实任务如何扣账

例如，用户让 Friday「搜索一篇海外文章，结合个人记忆写一封邮件，并把新的偏好写进 Memory」。

```text
1. 外部工具调用 1 次
   → 工具成本 $0.008

2. Friday 使用平台提供的模型生成邮件
   → 按这次输入 / 输出 Token 的模型实际成本扣除

3. 搜索个人 Memory 2 次
   → 2 × $0.000005 = $0.00001

4. 新增 2K 纯文本偏好写入 Memory
   → 内容处理成本：2 × $0.0005 = $0.001
   → 若该工作台启用 Embedding / Graph，还会增加 Embedding 或图谱抽取成本，以及后续存储成本

本次即时成本 = $0.00901 + 这次模型 Token 成本 +（如启用）Embedding / 图谱抽取成本
后续持续成本 = 该条 Memory 占用的文档、索引、向量、图数据存储成本
```

如果用户在第 2 步使用自己的 API Key，则模型成本从 Friday 的账本移走；这次 Friday 的成本只剩：

```text
$0.008 搜索 + $0.00001 召回 + $0.001 内容处理 +（如启用）Embedding / 图谱抽取成本
```

## 3. Free 与 Pro：区别不是功能数量，而是谁承担成本

| 项目 | Free | Pro |
| --- | --- | --- |
| Friday 提供的模型 | 有，但只有少量试用额度 | 有；从套餐内额度或用户充值余额扣除 |
| 用户输入自己的 API Key | **不支持** | **支持** |
| 使用用户自己的 Key 时的模型费 | 不适用 | 用户直接支付给模型供应商，Friday 不承担该项 |
| 外部工具调用 | 从 Free 的少量 Friday 试用额度中覆盖 | 从 Pro 套餐额度或充值余额中覆盖 |
| Memory 写入 / 召回 | 从 Free 的少量 Friday 试用额度中覆盖 | 从 Pro 套餐额度或充值余额中覆盖 |
| 额度用完后 | 引导升级 Pro；不设计为无限免费使用 | 充值 Friday 余额，或对模型部分改用自己的 API Key |

一句话说明：

```text
Free：让用户试用 Friday 代付的全部能力，但额度很小，也不能接自己的模型。
Pro：模型可以自己付，也可以让 Friday 代付；搜索和 Memory 始终由 Friday 的统一余额覆盖。
```

- Pro 的订阅价格；
- Friday 余额的售价与成本加价率；
- DeepSeek 以外的模型清单和各模型的实时 Token 单价。
- 文档、BM25 索引、向量和图数据各自的存储供应商单价，以及 Embedding 模型的实际单价。

这些是「卖多少钱」的决策，不影响上面的成本记账公式。
