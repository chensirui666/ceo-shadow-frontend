## 1. 背景与目的

Library 集中管理 Message 和 Routine 正式生成的文件，让用户无需返回原消息或执行记录逐条寻找，即可查找、预览、打开所在文件夹和管理工作成果。

文件生成与发送分别记录：正式文件生成成功即收录，尚未发送或发送失败都不影响文件保留。Library 通过来源关联帮助用户返回具体消息或 Routine 执行记录，不替代来源模块的处理流程。

当前不包含日常对话页面；不自动复制 Connector 原始资料。本文不定义 Agent 内容生成、内部存储或统计算法。

## 2. 功能模块概览

| 模块 | 内容 |
| --- | --- |
| Library 首页 | 本周成果、名称搜索、来源与类型筛选、列表／网格切换、文件信息与空态 |
| 首页文件操作 | 打开所在文件夹、原位重命名、删除确认；发送中禁止删除 |
| 文件预览 | 只读查看常见格式、切换文件、打开所在文件夹、来源跳转与发送结果 |
| 共通规则 | 正式文件收录、去重、来源关联、权限与跨模块边界 |

不提供文件夹、Collections、外部资料聚合、视频／音频管理或手动新增文件功能；不提供分享链接、分享权限、正文编辑、Prompt 改写或另存版本功能。

## 3. Library 首页

首页顺序为：**标题与说明 → 本周成果横幅 → 搜索、筛选和视图切换 → 文件区域**。

主内容整体滚动，标题、横幅与工具栏随文件区域一起上移，不只滚动文件行。应用导航保持固定；打开文件后，右侧预览正文独立滚动。

使用 HeroUI 控件，标题与正文沿用现有应用字号，Library 标题不单独放大。格式、日期和分区标题保持次级层级。

### 3.1 本周成果

展示当前用户本周生成的 Library 文件总量及分类数量。数字根据本周文件计算，不写死；具体计算与数据接入由研发实现。

横幅文案依次为 `THIS WEEK WITH FRIDAY`、`12 things created`、`5 docs • 3 reports • 4 files`，数字仅为呈现形式示例，不提供 View activity 入口。

横幅采用深暖色柔焦摄影背景与浅色文字。上下两行字号一致，与中间重点文字的距离紧凑且对称，外侧上下留白一致；中间采用轻盈的艺术衬线字体，可搭配斜体。文案叠加在背景上，保留英文。

### 3.2 搜索与筛选

| 控件 | 功能与规则 |
| --- | --- |
| 搜索 | 只搜索当前用户有权查看的文件名称，不搜索正文或图片文字 |
| 来源 | 全部、Message、Routine；表示生成文件的用户流程，不是文件引用的 Connector |
| 类型 | 全部、文档、表格、演示、图片、代码、其他；类型与具体扩展名分开，分类不等于预览能力承诺 |
| 清除筛选 | 同时清空关键词和筛选，恢复全部文件 |

- 名称搜索、来源与类型筛选取交集。单独清空关键词时保留来源和类型筛选。
- 不增加具体 Routine 实例筛选。
- 搜索框白底、无阴影、无占位文案，常规宽度 360–480px；来源与类型筛选紧跟右侧。
- 工具栏控件统一高度、字号、字重、内边距与较小圆角，文字和箭头垂直居中、整排对齐；空间不足时允许换行，下拉选项保持紧凑。

### 3.3 文件列表与网格

工具栏右侧提供列表／网格切换，默认列表。两种视图展示同一批文件，切换保留搜索、筛选和当前文件状态，提供相同的文件操作。

| 视图 | 内容组织 |
| --- | --- |
| 列表 | 格式图标、文件名称、留白、实际格式、完整日期、更多操作；采用轻量行和细水平分隔线 |
| 网格 | 上方浅色展示区和居中格式图标，下方文件名称、日期；保留格式标签和更多操作，卡片尺寸及间距统一 |

- 默认按完整生成时间倒序。同名文件允许存在，重命名不改变排序时间。
- 文件名称为主信息，过长截断；日期按用户时区以 `YYYY-MM-DD` 展示。
- 格式标签固定宽高、文字居中，不随字符数伸缩；文字及外框与格式图标颜色呼应。
- 图标按格式区分，颜色清晰鲜亮，配小面积浅色背景。配色方向：PDF 珊瑚色、DOCX 灰蓝、XLSX 鼠尾草绿、PPTX 浅杏、图片淡紫、Markdown 石墨灰，不使用 Office 品牌图标。
- 来源与发送状态只在预览中展示，不放进文件列表或卡片。
- 点击文件打开右侧预览，当前文件有明确选中态。打开所在文件夹、重命名和删除收在更多菜单中；菜单入口支持悬停、键盘聚焦及触屏访问。

### 3.4 文件操作

**打开所在文件夹**

- 在列表、网格或预览中点击“打开所在文件夹”后，系统文件管理器打开该 Artifact 所在文件夹，并定位对应文件。

**重命名**

- 在文件原位编辑，预填现有名称，提供保存与取消。
- 名称不能为空；允许同名，不允许通过修改扩展名改变格式。
- 只修改 Library 文件名称，不修改正文、格式、生成时间或来源关联，也不修改已发送到外部的文件名称、消息或内容。
- 成功后同步更新文件区和预览标题；失败保留原状态及用户输入，允许重试。

**删除**

删除使用确认弹窗，说明：“文件将从 Library 中移除，不会撤回已发送到群聊或个人的内容。”

- 删除操作为红色；文件正在发送时禁止删除，删除项置灰。
- 成功后移除条目，若正在预览该文件则关闭预览；失败保留原文件及预览，允许重试。
- 删除文件不删除原 Routine 或 Message 记录，不停止 Routine 后续执行。
- 删除后的空结果按当前筛选条件展示对应空态。回收站、恢复及保留策略尚未确认，不承诺可恢复或立即物理清除。

### 3.5 首页状态

| 状态 | 展示与操作 |
| --- | --- |
| 尚无文件 | 明确为空库，说明生成文件会保存在这里 |
| 筛选无结果 | 说明无匹配文件，提供清除筛选 |
| 加载中 | 保持页面框架并提供加载反馈 |
| 加载失败 | 说明失败并允许重试，不冒充空库 |

## 4. Library 文件预览

点击列表或网格中的文件，在当前页右侧打开只读预览，不跳转页面、不使用居中遮罩；保留主内容可操作，正文占主要空间。

### 4.1 内容与支持格式

预览展示完整文件内容，不能用摘要替代原文件；转换后应保持原内容语义。

| 文件类型 | 支持格式 | 展示方式 |
| --- | --- | --- |
| 文档 | PDF、MD、TXT、DOCX、HTML | PDF 展示文件页面，MD／DOCX／HTML 展示排版内容，TXT 展示原文 |
| 表格 | XLSX、CSV | 展示单元格内容，多工作表文件支持切换 |
| 演示 | PPTX | 展示演示页面内容 |
| 图片 | PNG、JPG、WebP、GIF、SVG | 展示图片并适配预览区域 |
| 代码 | JSON、Python、JavaScript 等文本代码文件 | 只读展示源文本，不执行代码 |

- HTML 等可包含脚本的文件只展示内容，不执行文件内脚本。
- 面板展示文件名称、格式和生成时间，来源及发送详情按需展开，底部提供“打开所在文件夹”。重命名和删除继续从首页更多菜单操作，不在预览重复堆叠。
- 切换文件复用同一面板，新文件正文从顶部展示；不得将上一文件正文显示为新文件内容。
- 关闭预览保留搜索、筛选及主内容滚动位置。长文件在预览内独立滚动，不把主页面无限撑高。

### 4.2 来源跳转

| 信息展示 | 来源情况 | 行为 |
| --- | --- | --- |
| 来源 | Message 文件 | 返回对应消息 |
|  | Routine 文件 | 返回具体执行记录 |
| 应用 | 钉钉 | 保留原来源名称及已删除状态，文件仍可查看和管理 |
| 推送人/负责人 | 来源不存在或不可访问 | 不提供无效跳转，不影响读取仍有权限访问的文件 |

### 4.3 发送结果

文件已生成不等于发送成功。预览中可按 Connector 和目标查看结果，包括失败对象及原因。

| 发送结果 | 含义 |
| --- | --- |
| 未发送 | 文件已生成，尚未推送 |
| 发送中 | 投递尚未完成，可查看已返回的目标结果 |
| 已发送 | 全部目标发送成功 |
| 部分发送失败 | 部分目标失败，保留失败对象和原因 |
| 发送失败 | 全部目标失败，文件仍保留 |
| 结果待确认 | 结果未知，不标记为已发送 |

Routine 发送失败的重试在 Recent Sessions 处理，Library 提供来源跳转，不重复建设发送配置功能。Message 后续处理沿用其来源流程。

### 4.4 预览异常

| 状态 | 展示与操作 |
| --- | --- |
| 不支持预览 | 明确说明；文件仍存在时保留“打开所在文件夹” |
| 加载失败 | 保留元信息并允许重试；文件仍存在时保留“打开所在文件夹” |
| 文件不存在／已删除 | 说明原因，关闭失效预览并刷新对应条目 |
| 无权限 | 不暴露文件正文，说明无法访问 |

## 5. 共通规则

### 5.1 文件收录

| 内容 | 收录规则 |
| --- | --- |
| Message 处理生成的正式文件 | 收录，关联具体消息 |
| Routine 正式执行生成的文件 | 收录，关联日程及本次执行 |
| 已生成但未发送、部分或全部发送失败 | 收录，独立记录实际发送结果 |
| Routine 试运行预览 | 不收录 |
| 普通文本回答 | 不收录 |
| Connector 原始资料 | 不收录 |

- 同一文件发送至多个目标或重试发送，只保留一个条目；重试更新原文件的发送结果。
- 新一次正式生成的文件独立收录，不覆盖历史文件；一次生成多个文件时分别收录，关联同一来源。
- 记录文件名称、实际格式、完整生成时间、文件内容、来源关联及各目标的发送结果。
- 收录不受预览格式限制：暂不支持预览的正式文件仍支持打开所在文件夹、重命名和删除。

### 5.2 权限与关联边界

- 文件查找和读取受用户访问权限约束；来源是否存在与文件是否仍可访问分别判断。
- 与 [Routine PRD](https://alidocs.dingtalk.com/i/nodes/amweZ92PV6xpLPY5sqd4zqzD8xEKBD6p) 共用文件、来源和发送状态定义；[Message](https://alidocs.dingtalk.com/i/nodes/m9bN7RYPWdbednwAijXE2v45JZd1wyK0) 保留原消息及处理结果，两者通过来源关联。
- 遵循 [Onboarding](https://alidocs.dingtalk.com/i/nodes/mExel2BLV5xpQm0wsp3z7jQRWgk9rpMq) 的资料边界：不自动复制 Connector 原始聊天、会议或文档，不建立原始资料镜像。
