# Library PRD

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.2，已同步确认的 V2 页面布局 |
| 日期 | 2026-09-12 |
| 产品 | Friday |
| 关联模块 | [Routine](Routine%20PRD.md)、日常对话、Message |
| 文档范围 | 功能、页面布局、字段、交互、流程与异常状态；本版不包含验收标准 |

## 1. 背景与目标

Library 是用户集中查看 Agent 所生成文件的地方。它统一收录日常对话、Message 和 Routine 正式生成的 artifacts，提供查找、预览、下载、重命名和删除。

生成文件与推送文件是两件独立的事：只要正式文件生成成功，即使尚未发送或发送失败，也应进入 Library。用户无需为了寻找文件回到原会话逐条翻查。

本 PRD 不定义 Agent 如何生成内容或内部如何存储文件，不将规划功能描述成已实现能力。

## 2. 产品依据与边界

- 用户本次确认的规则为准，与 [Routine PRD](Routine%20PRD.md) 共用文件、来源和发送状态定义。
- 已同步的钉钉 [Onboarding](https://alidocs.dingtalk.com/i/nodes/mExel2BLV5xpQm0wsp3z7jQRWgk9rpMq) 规定不建立原始资料长期副本；Library 收录 Agent 生成的成果物，不自动复制 Connector 中的原始聊天、会议或文档。
- [Message](https://alidocs.dingtalk.com/i/nodes/m9bN7RYPWdbednwAijXE2v45JZd1wyK0) 保留原始工作信息及处理结果，Library 负责文件集中管理，两者通过来源关联。
- 参考竞品截图的搜索、类型筛选和文件列表，不引入 Collections、文件夹、外部资料聚合或视频／音频管理。
- 标注“建议”的细节尚未经单独确认。

## 3. 收录规则

| 内容 | 是否收录 | 说明 |
| --- | --- | --- |
| 日常对话生成的正式文件 | 是 | 来源为对话 |
| Message 处理生成的正式文件 | 是 | 来源为 Message，可追溯关联消息 |
| Routine 正式执行生成的文件 | 是 | 来源为 Routine，可追溯日程与本次执行 |
| 已生成，未推送 | 是 | 生成与发送分别记录 |
| 已生成，部分或全部发送失败 | 是 | 保留文件并展示实际发送状态 |
| Routine 试运行预览 | 否 | 用户明确确认的例外 |
| 资料不足而跳过生成 | 否 | 没有文件，不创建空条目 |
| 生成失败且没有可用文件 | 否 | 错误留在原执行或会话中 |
| 普通文本回答，没有生成文件 | 否 | 不把每条聊天回答包装成文件 |
| Connector 中的原始资料 | 不自动收录 | Library 不作为原始资料镜像 |

- 同一个文件向多个目标发送只形成一个条目。
- 发送重试复用原文件，不新增重复条目。
- 新一次正式生成的新文件独立收录，不覆盖历史文件。
- 如果一次生成多个独立文件，每个文件分别收录，并关联同一来源。
- 本期明确的展示格式为 PDF、MD、Word（.docx）、PNG。若其他 Agent 已能生成这些以外的文件，如何在“全部收录”原则下展示需要补齐；不得静默丢弃，亦不在本版承诺尚未确认的其他格式预览能力。

## 4. 页面布局

### 4.1 Library 首页

采用应用侧栏＋单主区域，依次展示标题、一句说明、搜索框、来源／格式筛选、文件列表。采用已确认的 V2 布局，不做文件夹或 Collections 区域。

```text
应用侧栏 │ Library
         │ 你与 Friday 完成的工作
         │ [搜索文件……                              ]
         │ [来源：全部 ▾] [格式：全部 ▾]
         │
         │ 文件图标  项目周报 · 9月11日      9月11日  ⋯
         │           Routine · 项目周报
         │ ──────────────────────────────────────────
         │ 文件图标  客户跟进记录             9月10日  ⋯
         │           Message
         │ ──────────────────────────────────────────
         │ 文件图标  AI 行业洞察              9月10日  ⋯
         │           对话
```

- 文件列表使用平铺的轻量行和细水平分隔线，不使用粗表头、纵向分栏、外层表格边框或装饰卡片。
- 文件名称是视觉主信息，来源置于名称下方作为小号灰色文字，日期与更多操作位于右侧。
- 搜索与筛选紧邻，不添加独立统计卡片、显眼文件计数或网格切换。存在筛选条件时提供清除入口。
- 不在列表显示单独格式列、发送状态徽标或逐目标结果；这些信息进入文件预览后查看。格式筛选继续保留。
- 下载、重命名和删除收在行尾更多菜单中，不常驻展开。

### 4.2 文件列表字段

| 字段 | 展示规则 |
| --- | --- |
| 文件图标与名称 | 使用低对比度、统一风格的文件图标，不以大面积彩色格式图标抢占注意力；标题过长截断，点击打开预览 |
| 次级来源 | 名称下方显示对话／Message／Routine，可附原会话或日程名称；原日程已删除时仍显示对应标注 |
| 生成日期 | 位于行右侧，按用户时区展示；默认仍按完整生成时间倒序，精确时间在预览中查看 |
| 更多操作 | 行尾“⋯”提供下载、重命名、删除；指针悬停或键盘聚焦可显现，触屏保持可访问 |

- 同名文件允许存在，用生成日期和来源区分；重命名不改变排序时间。
- 来源 Connector 与文件生成来源不同：一个跨渠道内容的文件仍可属于同一个 Routine；不把钉钉／Teams 作为本期“来源”筛选的主分类。
- 文件格式及发送结果继续记录，只从首页收起，不移除功能。
- 默认列表即可，本期不提供列表／网格切换。

### 4.3 文件预览

建议点击文件后打开宽预览层，保留关闭入口；正文占主要宽度，右侧或顶部显示简短元信息。

```text
项目周报                                         [下载] [⋯] ×
Routine · 项目周报日程 · 2026-09-12 18:03 · PDF
───────────────────────────────────────────────────────────
                         文件内容预览
───────────────────────────────────────────────────────────
发送情况：钉钉项目组 已发送；Teams 产品组 发送失败
[查看来源／本次执行]
```

- PDF 展示实际文件页面；PNG 展示图片并支持适配窗口查看。
- MD 展示排版后的正文；Word 提供只读预览，无法预览时仍应允许下载原文件并说明原因。
- 预览不得将内容摘要冒充完整文件；转换后的预览应保持原内容语义。
- 不提供正文编辑、通过 Prompt 改写或另存版本功能。
- 关闭预览回到原列表，保留搜索、筛选和滚动位置。

## 5. 搜索与筛选

### 5.1 搜索

- 搜索作用于当前用户有权查看的 Library 文件。
- 建议支持文件名称及可提取的正文内容，多个筛选条件同时生效。
- PNG 图片文字检索未确认，本期不承诺 OCR 搜索；若先只实现名称搜索，应将占位文案明确改为“搜索文件名称”。
- 清空关键词后保留来源／格式筛选；无搜索结果显示当前条件和清除入口。

### 5.2 来源筛选

选项为全部、对话、Message、Routine。来源表示文件由哪类用户流程生成，不限制文件内容引用了哪个 Connector 的 Memory。

按具体 Routine 实例进一步筛选尚未单独确认，本版不增加该层筛选。

### 5.3 格式筛选

选项为全部、PDF、MD、Word、PNG。来源筛选、格式筛选与搜索取交集；“清除筛选”建议同时清空搜索和筛选，并恢复默认列表。

## 6. 文件操作

| 操作 | 行为 |
| --- | --- |
| 预览 | 打开只读文件预览，显示来源、时间及发送结果 |
| 下载 | 下载对应实际格式的文件；失败提示并允许重试 |
| 重命名 | 修改 Library 文件名称，不修改文件正文 |
| 删除 | 删除 Library 中的文件，不撤回已发送内容 |

### 6.1 重命名

- 建议使用小弹窗，预填现有名称，提供取消与保存。
- 名称不能为空；格式扩展名不可通过重命名改成其他格式。
- 失败时保留输入；成功后更新列表与预览标题。
- 不修改已经发送到外部群聊或个人的文件名称、消息或内容。

### 6.2 删除

建议使用确认弹窗：

```text
删除此文件？
文件将从 Library 中移除，不会撤回已发送到群聊或个人的内容。
                                      [取消] [删除]
```

- 删除后文件从列表消失；如果已无当前筛选结果，展示对应空态。
- 删除文件不删除原 Routine，不停止后续执行，不删除 Message 或对话记录。
- 建议来源记录保留“文件已删除”提示，不继续提供失效预览或下载入口。
- 本期未确认回收站、恢复期限及底层清理时间，不向用户承诺可恢复或立即物理清除。
- 文件仍在发送中时是否允许删除尚待确认，不能因 Library 删除导致无法解释的部分投递。

## 7. 来源与推送结果

### 7.1 来源追溯

- 对话产物可返回对应对话；Message 产物可返回对应消息；Routine 产物可查看日程或本次执行。
- 原日程删除后文件继续保留，来源显示原名称及“原日程已删除”。
- 原来源不存在或不可访问时，不显示无效跳转；来源缺失不应阻止用户读取仍有权限访问的文件。

### 7.2 生成与发送分别记录

Library 的条目代表文件已经生成，不等于已经发送成功。首页不展示发送状态列；以下状态仅在文件预览／详情中展示，可按 Connector 和目标查看结果。

| 发送结果 | Library 展示 |
| --- | --- |
| 未推送 | 未发送，文件可预览与下载 |
| 正在发送 | 发送中，可查看已返回的目标结果 |
| 全部成功 | 已发送 |
| 部分失败 | 部分发送失败，显示失败对象和原因 |
| 全部失败 | 发送失败，文件仍保留 |
| 结果未知 | 结果待确认，不标成已发送 |

Routine 失败发送的重试放在 Recent Sessions，Library 提供跳转到本次执行的入口，不重复建设发送配置界面。对话与 Message 的后续处理沿用各自来源流程。

## 8. 页面状态

| 状态 | 页面表现 |
| --- | --- |
| 尚无文件 | “Friday 生成的文件会保存在这里”，可提供前往 Routine 的入口 |
| 有筛选但无结果 | “没有找到符合条件的文件”，提供清除筛选 |
| 列表加载中 | 保持页面框架，显示明确加载状态 |
| 列表加载失败 | 显示可读原因及重试，不冒充空库 |
| 预览加载失败 | 保留元信息，提供重试；文件可下载时保留下载 |
| 文件不存在／已删除 | 明确说明，返回列表并刷新对应条目 |
| 无权限 | 不显示文件正文，说明无法访问 |
| 重命名／删除失败 | 保持原状态，提示失败并允许重试 |

## 9. 关键用户流程

### 查看 Routine 正式产物

Routine 正式生成文件 → 自动收录 → 用户打开 Library → 来源选择 Routine → 打开文件 → 查看内容和发送结果 → 按需下载或返回本次执行。

### 查找历史文件

打开 Library → 输入关键词 → 选择来源／格式 → 查看结果 → 预览 → 关闭后保留筛选和列表位置。

### 删除日程后的文件

用户删除 Routine → 后续日程停止 → 历史文件继续显示 → 文件来源标注原日程已删除 → 用户仍可预览、下载、重命名或删除文件。

## 10. 尚待确认的细节

- 搜索首期是否包含可提取正文，还是只搜索文件名称。
- 四种格式以外的 Agent 文件如何显示，及不支持预览时的处理范围。
- 文件发送中删除的行为、删除后的恢复与保留策略。
- 正式文件大小、存储容量和保留期限；本版不虚构配额或保存时长。

以上不改变已确认的核心范围：全部正式文件收录、试运行例外、搜索与来源／格式筛选、只读预览及下载／重命名／删除。
