## 一、功能需求

### 1. 定位与范围

Library 集中管理 Message 和 Routine 正式生成的文件，支持查找、预览、下载、重命名、删除和来源追溯。文件生成成功即收录，是否发送成功不影响收录。

- 当前来源为 Message 和 Routine，不包含日常对话。
- 与 [Routine PRD](Routine%20PRD.md) 共用文件、来源和发送状态定义；[Message](https://alidocs.dingtalk.com/i/nodes/m9bN7RYPWdbednwAijXE2v45JZd1wyK0) 保留原消息及处理结果，两者通过来源关联。
- 遵循 [Onboarding](https://alidocs.dingtalk.com/i/nodes/mExel2BLV5xpQm0wsp3z7jQRWgk9rpMq) 的资料边界：不自动复制 Connector 的原始聊天、会议或文档，不建立原始资料镜像。
- 不提供文件夹、Collections、外部资料聚合、视频／音频管理或手动新增文件功能。
- 不提供分享链接、分享权限、正文编辑、Prompt 改写或另存版本功能。
- 本文不定义 Agent 内容生成方式、内部存储方案或统计算法。

### 2. 文件收录与信息

| 内容 | 收录规则 |
| --- | --- |
| Message 处理生成的正式文件 | 收录，关联具体消息 |
| Routine 正式执行生成的文件 | 收录，关联日程及本次执行 |
| 已生成但未发送、部分或全部发送失败 | 收录，独立记录实际发送结果 |
| Routine 试运行预览 | 不收录 |
| 资料不足而跳过生成、生成失败且无可用文件 | 不创建空条目，错误保留在原处理流程 |
| 普通文本回答 | 不包装成文件收录 |
| Connector 原始资料 | 不自动收录 |

- 同一文件发送至多个目标或重试发送，只保留一个条目；重试更新原文件的发送结果。
- 新一次正式生成的文件独立收录，不覆盖历史文件；一次生成多个文件时分别收录，关联同一来源。
- 记录文件名称、实际格式、完整生成时间、文件内容、来源关联及各目标的发送结果。同名文件允许存在。
- 默认按完整生成时间倒序；重命名不改变排序时间。
- 收录不受预览格式限制：暂不支持预览的正式文件仍支持下载、重命名和删除。

### 3. 搜索、筛选与视图

- 只搜索当前用户有权查看的文件名称，不搜索正文或图片文字。
- 来源筛选：全部、Message、Routine。来源指生成文件的用户流程，不是文件引用的 Connector；不增加具体 Routine 实例筛选。
- 类型筛选：全部、文档、表格、演示、图片、代码、其他。类型分类与实际扩展名分开，归入某类不代表所有该类格式都支持预览。
- 名称搜索、来源与类型筛选取交集。单独清空关键词保留筛选；“清除筛选”同时清空关键词和筛选，恢复全部文件。
- 支持列表与网格两种视图，默认列表。切换视图保留搜索、筛选和当前文件状态，两种视图提供相同的文件操作。

### 4. 本周成果统计

展示当前用户本周生成的 Library 文件总量和分类数量。总量与分类数量根据本周文件计算，不使用固定数字；具体计算与数据接入由研发实现。

展示文案示例为 `12 things created`、`5 docs • 3 reports • 4 files`，数字仅用于说明呈现形式。

### 5. 文件预览与下载

预览为只读，展示完整文件内容，不能用摘要替代原文件；转换后应保持原内容语义。

| 文件类型 | 支持格式 | 能力 |
| --- | --- | --- |
| 文档 | PDF、MD、TXT、DOCX、HTML | PDF 展示文件页面，MD／DOCX／HTML 展示排版内容，TXT 展示原文 |
| 表格 | XLSX、CSV | 展示单元格内容，多工作表文件支持切换 |
| 演示 | PPTX | 展示演示页面内容 |
| 图片 | PNG、JPG、WebP、GIF、SVG | 展示图片并适配预览区域 |
| 代码 | JSON、Python、JavaScript 等文本代码文件 | 只读展示源文本，不执行代码 |

- HTML 等可包含脚本的文件只展示内容，不执行文件内脚本。
- 不支持预览或预览失败时说明原因，文件仍可访问时保留原文件下载。
- 下载实际文件及对应格式；失败时明确提示并允许重试。
- 切换文件时不得将上一文件正文显示为新文件内容。

### 6. 重命名与删除

**重命名**

- 只修改 Library 文件名称，不修改正文、格式、生成时间或来源关联。
- 名称不能为空，不能通过修改扩展名改变格式；允许同名文件。
- 成功后同步更新文件区与预览标题；失败保留原状态和用户输入，允许重试。
- 不修改已经发送到外部群聊或个人的文件名称、消息或内容。

**删除**

- 文件正在发送时禁止删除。
- 删除前需要用户确认，并说明不会撤回已经发送的内容。
- 删除成功后移除文件条目；当前正在预览该文件时关闭预览。删除失败保留原文件及预览，允许重试。
- 删除文件不删除原 Routine 或 Message 记录，不停止 Routine 后续执行。
- 删除后的空结果按当前筛选条件展示相应空态。
- 尚未确认回收站、恢复期限及底层清理时间，不承诺可恢复或立即物理清除。

### 7. 来源追溯与发送结果

- Message 文件可返回对应消息；Routine 文件可返回具体执行记录。
- 原日程删除后，文件仍保留且可管理；保留原来源名称和已删除状态。
- 来源不存在或不可访问时，不提供无效跳转；来源缺失不影响用户读取仍有权限访问的文件。
- 文件已生成不等于已发送成功。按 Connector 和目标记录发送结果，支持查看失败对象与原因。

| 发送结果 | 含义 |
| --- | --- |
| 未发送 | 文件已生成，尚未推送 |
| 发送中 | 投递尚未完成，可查看已返回的目标结果 |
| 已发送 | 全部目标发送成功 |
| 部分发送失败 | 部分目标失败，保留失败对象与原因 |
| 发送失败 | 全部目标失败，文件仍保留 |
| 结果待确认 | 结果未知，不标记为已发送 |

Routine 发送失败的重试在 Recent Sessions 处理，Library 提供来源跳转，不重复建设发送配置功能。Message 后续处理沿用其来源流程。

### 8. 空态与异常处理

| 状态 | 功能处理 |
| --- | --- |
| 尚无文件 | 明确为空库，说明生成文件会保存在这里 |
| 筛选无结果 | 说明无匹配文件，提供清除筛选 |
| 文件列表加载中 | 提供加载反馈 |
| 文件列表加载失败 | 说明失败并允许重试，不冒充空库 |
| 预览加载失败 | 保留元信息并允许重试；文件可下载时保留下载 |
| 文件不存在／已删除 | 说明原因，关闭失效预览并刷新对应条目 |
| 无权限 | 不暴露文件正文，说明无法访问 |
| 重命名／删除失败 | 保持原状态，提示失败并允许重试 |

### 9. 待确认事项

- 删除后的恢复与保留策略，文件大小、存储容量和保留期限。
- 原有建议“来源记录保留文件已删除提示”尚未单独确认，不作为已确定需求。

## 二、UI 与交互设计

### 1. 页面结构与滚动

主内容依次为：**Library 标题与说明 → 本周成果横幅 → 搜索、筛选及视图切换工具栏 → 文件区域**。

标题、横幅、工具栏和文件区域整体滚动，不仅滚动文件行。应用导航保持固定；打开文件后，右侧预览正文独立滚动。

### 2. 本周成果横幅

- 柔焦摄影背景，深暖色与柔和光影，浅色文字、大圆角；文案叠加在图片上。
- 三层文案：`THIS WEEK WITH FRIDAY`、成果总量、分类数量。上下两行字号一致，与中间重点文字的间距紧凑且对称，外侧上下留白一致。
- 重点文字采用轻盈的艺术衬线字体，可搭配斜体。保留英文文案，不提供 View activity 入口。

### 3. 搜索与筛选工具栏

- 搜索框白底、无阴影、无占位文案，常规宽度 360–480px；来源、类型筛选紧跟右侧，列表／网格切换置于工具栏右侧。
- 控件统一高度、字号、字重、内边距与较小圆角；文字及箭头垂直居中，整排平整对齐。空间不足时允许换行，下拉选项保持紧凑。

### 4. 文件区域

| 视图 | 设计要求 |
| --- | --- |
| 列表 | 格式图标、文件名称、留白、实际格式、完整日期、更多操作；轻量行与细水平分隔线 |
| 网格 | 上方浅色展示区与居中格式图标，下方文件名称、日期；保留格式标签及更多操作，卡片尺寸和间距统一 |

- 文件名称为主信息，过长截断；日期按用户时区以 `YYYY-MM-DD` 展示。
- 格式标签固定宽高、文字居中，不随字符数伸缩；文字和外框与格式图标颜色呼应。
- 图标按格式区分，颜色清晰鲜亮，配小面积浅色背景。配色方向：PDF 珊瑚色、DOCX 灰蓝、XLSX 鼠尾草绿、PPTX 浅杏、图片淡紫、Markdown 石墨灰；不用 Office 品牌图标。
- 来源与发送状态不放入文件列表或卡片，只在预览中展示。

### 5. 预览与操作方式

- 点击文件，在当前页右侧打开只读预览，不跳转页面或使用居中遮罩；保留文件区可操作，当前文件有选中态。
- 切换文件复用同一面板，新文件正文从顶部展示；关闭预览保留搜索、筛选与主内容滚动位置。
- 面板展示名称、格式和生成时间，来源与发送详情按需展开，底部提供下载。
- 下载、重命名和删除收在文件的更多菜单中，不在预览重复堆叠。菜单入口支持悬停、键盘聚焦及触屏访问。
- 重命名在原位完成，预填现有名称，提供保存与取消；删除使用确认弹窗，说明“文件将从 Library 中移除，不会撤回已发送到群聊或个人的内容”。
- 删除操作为红色；发送中的文件删除项置灰禁用。

### 6. 通用视觉规范

控件使用 HeroUI，标题与正文沿用现有应用字号规范，Library 标题不单独放大；格式、日期和分区标题保持次级层级。具体视觉参数由设计统一，不在功能需求中混入实现尺寸。
