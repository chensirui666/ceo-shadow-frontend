# 迭代后的完整用户旅程

### 0. 看到真实体验

用户刷到一位管理者博主的视频。

视频里，博主展示：同事在钉钉中 @ 他询问项目进度；Friday 读取已有工作资料，生成一条有项目背景、像博主本人风格的回复。博主给出一句“太长了，直接说结论”的反馈，Friday 立刻生成更合适的版本。

用户觉得这正是自己需要的，点击视频链接。

### 1. 进入 Friday 宣传页并下载

Friday 宣传页展示真实工作场景和实际回复结果，而不是泛泛介绍 AI。

页面只有一个清楚的行动：

> 连接钉钉，三分钟建立工作分身  
`下载 Friday`

用户下载、安装 Friday，用邮箱验证码登录。

### 2. 登录后进入 Home

用户登录后直接进入 Friday 产品内的 Home 页面。

Home 处于首次设置状态，顶部横向显示四步：

`1 连接应用 → 2 建立 Memory → 3 确认工作风格 → 4 Dry Run 并启用`

用户不需要先理解复杂模块，只需要完成当前高亮的一步。

### 3. 第一步：连接应用

用户登录 Friday 后直接进入产品内的 Home 页面。Home 处于首次设置状态，顶部横向展示四步：

`1 连接工作应用 → 2 建立本地 Memory → 3 确认工作风格 → 4 Dry Run 并启用`

当前高亮第一步。页面文案为：

> **连接你的工作应用**  
先连接一个你常用的工作应用即可开始。之后可以随时补充更多应用。

页面展示可连接的应用卡片：

| 应用 | 卡片说明 |
| --- | --- |
| 企业微信 | 连接工作消息与文档 |
| 钉钉 | 连接工作消息、文件与知识库 |
| 飞书 | 连接消息、文档与会议资料 |
| Gmail | 连接工作邮件与邮件线程 |
| Slack | 连接频道消息与讨论线程 |

每张卡片都有 `连接` 按钮。用户可以只连接一个，也可以连续连接多个；不要求首次一次配完。

页面右侧展示简短的信任说明：

> **你始终掌控授权范围**  
Friday 只读取你明确授权的资料。  
每个应用的读取范围会在授权前清楚展示，之后可随时在 `Settings → Connectors` 中修改或移除。

例如用户点击“连接钉钉”：

1.  Friday 打开钉钉官方授权页或二维码；
    
2.  用户扫码并确认授权；
    
3.  授权完成后自动回到 Friday；
    
4.  钉钉卡片变为“已连接”，展示账号和当前读取范围。
    

例如：

> **钉钉已连接**  
将读取你授权范围内的工作消息、文件与知识库资料。

用户还可以继续连接飞书、企业微信、Gmail 或 Slack；也可以点击主按钮：

> `继续，已连接 1 个应用`

随后进入“建立本地 Memory”。

这样，用户先决定“分身接入哪些工作入口”，再决定 Friday 如何沉淀和使用这些资料；Connector 仍归属 `Settings → Connectors`，但首次引导把它直接放在 Home 中完成。

### 4. 第二步：建立本地 Memory

Friday 告诉用户：

> 我们会读取你授权范围内的钉钉工作资料和文档内容，沉淀为本地 Memory。  
这些内容只保存在你的本地 Friday 中。

用户点击“确认并建立”。

Friday 快速处理已授权资料，完成后显示：

> Memory 已建立  
`预览 Memory`　`继续`

点击“预览 Memory”时，用户会直接跳转到memory的界面，看到一张由散点连线组成的一张图；不点击也可直接继续。

历史 AI 对话不在这里要求上传。用户后续可在 `Memory → 迁移历史对话` 中自行补充 Claude Code、Codex、ChatGPT 的工作记录。

### 5. 第三步：形成并确认工作风格

Friday 基于本地 Memory 生成一个初始工作风格。

用户点击“生成我的工作风格”，看到结果预览：

*   回复是结论优先还是解释优先；
    
*   语气是直接、友好还是更正式；
    
*   哪些事情应该自行回复；
    
*   哪些敏感或重要事项必须先交给本人确认。
    

用户可选择“确认使用”。确认后进入下一步。

### 6. 第四步：Dry Run

在 测试阶段 支持用户发送消息，然后用户可以看到 agent 生成的回答和过程。

用户看到：

*   自己发的消息消息；
    
*   Friday 理解到的相关工作背景；
    
*   分身生成的回复草稿；
    
*   草稿不会被发送。
    

用户对真实草稿给出反馈，例如“更简短”“更像我”“这里不要替我承诺”“这个回复不错”。

Friday 根据这些反馈调整工作风格，并生成新的版本。

用户满意后点击【正式启用】。

### 7. 分身正式开始工作

正式试用后，Friday 有一个完成的动效提醒，并且支持用户选择通知自己的某某同时，来说明你的数字人分身已经开始工作。

然后数字人分身正式开始工作，并按照已确认的工作风格生成和发送回复。

首页开始展示：

*   今天处理了哪些消息；
    
*   哪些回复需要自己确认；
    
*   产生了哪些任务；
    
*   收到了哪些反馈。
    

### 8. 用户长期使用 Friday

产品固定保留五个一级页面：

| 页面 | 日常作用 |
| --- | --- |
| **Home** | 看今日处理结果、待确认事项和最近活动。 |
| **Tasks** | 看消息、会议和项目中整理出的待办。 |
| **Memory** | 看本地 Memory；补充资料或迁移历史对话。 |
| **Feedback** | 看用户对真实回复的反馈，并持续调整分身风格。 |
| **Settings** | 管理回复规则、语言、权限和 `Connectors`。 |

这样用户的首次体验就变成：

> **看到真实效果 → 连上钉钉 → 一键建立本地 Memory → 看真实草稿并反馈 → 正式启用。**

## 当前产品状态下的 Onboarding 调整（2026-08-09）

本节是当前 Web 端 Onboarding 的有效设计，覆盖上文中与当前产品状态不一致的部分。原文保留为完整愿景与迭代记录。

### 1. 本次要达成的结果

首次登录的用户不需要先学会配置 Friday。完成引导后，他至少应明白三件事：

1. Friday 已连接到哪些工作应用，并会按 Settings 中的规则工作；
2. Friday 对自己的工作风格有什么理解；
3. 输入一条问题后，Friday 能给出怎样的回复；Trial 中不会向同事发送任何消息。

用户可以在确认工作风格后直接正式运行，不把「必须先完成一次 Trial」设为阻断条件。正式运行前仍必须由用户明确确认。

### 2. Home 中的引导形态

Onboarding 不使用独立向导页，而是嵌在 Home 顶部的四步引导。页面采用上下结构：

```text
四步 Onboarding
────────────────
最近 24 小时轴与事件区
```

引导尚未完成时，下面的 24 小时轴和事件区仍然存在；新用户尚未产生事件时，它保持为空。引导结束后，四步区域整体消失，Home 只保留日常的 24 小时事件流。

当前前端 Mock 的账号规则：

| 登录账号 | 进入后的状态 |
| --- | --- |
| `sirui.chen@stardust.ai` | 视为已完成 Onboarding，直接进入有示例事件的正常 Home。 |
| 其他任意账号 | 每次登录都从 Onboarding 开始。 |

真实后端接入后，Onboarding 完成状态应按账号持久保存；用户完成一次后不再重复展示。

### 3. 四步流程

#### 第一步：连接应用

页面展示三个可连接的应用：钉钉、飞书、Teams。每个应用只有一个 `Connect` 主行动；点击后直接进入对应授权／连接流程，完成后返回同一页面并显示已连接。

- 用户可连续连接多个应用；
- 至少成功连接一个应用后才可以继续；
- 首次引导不进入连接器详情页；连接后的长期管理仍在 Settings；
- 消息处理范围、每个应用的规则和其他偏好都只在 Settings 配置，不在 Onboarding 重复要求选择。

#### 第二步：建立 Memory

页面列出已连接应用及其读取范围。用户一次确认后，Friday 建立第一版 Memory；不要求逐项勾选消息、文档或会议资料。

完成后只给出简短结果和 `查看 Memory` 行动。点击后跳转到 Memory 页面查看细节；返回 Home 后，第二步仍保持完成，用户可继续第三步。

#### 第三步：确认工作风格

页面先以易读摘要展示 Friday 对用户工作方式的理解，包含：

- 表达方式：结论、语气、篇幅与承诺尺度；
- 判断顺序：先确认什么，资料不足时如何处理；
- 场景规则：不同工作事项的处理偏好；
- 必须交还本人：审批、人事、财务、法律与关键客户承诺。

用户可按需打开「个人工作风格 Prompt 原文」。该 Prompt 是蒸馏出的个人工作风格，不展示原始资料、内部运行指令或安全路由。摘要与 Prompt 在本期均为只读；用户点击 `确认使用` 后进入第四步。

#### 第四步：Trial

第四步的唯一视觉重点是让用户快速体验一条回复：

```text
点选示例问题，或输入自己的问题
→ 发送给 Friday
→ 看回复并给出反馈
```

页面默认提供几个可点击的问题。点击后，问题写入同一个输入区；用户也可以自行输入。点击 `发送给 Friday` 后，Friday 走完整的理解背景与生成回复流程。

Trial 页面明确说明：`消息只发送给 Friday，不会发给同事。` 不在这个页面展示「等待真实消息」或已连接应用列表。真实版本中，已连接应用收到的消息仍按 Trial 规则处理；用户无需在首次体验中理解这条后台路径。

生成结果写入 Home，成为一条普通事件，状态明确标注为 `Trial`，并计入当前 24 小时事件流。引导结束后，这条记录保留在当前会话中。

用户可以选择：

- `符合我`：记录本次回复符合预期；
- `需要调整`：输入一句调整要求，Friday 立即按这句话重新生成**当前** Trial 回复。

「需要调整」会被记录为后续微调工作风格的材料，但不会立即改写长期工作风格、个人 Prompt 或任何其他回复。

`正式运行`始终可选，不因用户是否发送或完成 Trial 而被禁用。点击后进入一次明确的启用确认。

### 4. 两种运行状态

产品只保留两种运行状态：

| 状态 | 用户可做什么 | 对外行为 |
| --- | --- | --- |
| `Trial` | 输入测试问题、接收真实消息、查看回复、给出调整意见。 | 不向同事或外部应用发送回复。 |
| `正式运行` | 按 Settings 中的长期规则处理工作消息。 | 满足既定规则时才可向外发送；需要本人判断的事项仍交还用户。 |

不保留独立的「暂停」状态；从正式运行切回 Trial 即停止对外发送。

### 5. 正式运行后的完成体验

用户确认正式运行后，先出现明确、短暂的完成动效，给用户完成配置并开始工作的成就感。以下联系人通知描述的是接入后端后的真实产品行为。

动效结束后弹出联系人列表弹窗，询问是否通知某位联系人。联系人范围仅包括：已连接应用中、与当前用户有过真实工作互动的人。

用户可以：

1. 选择一位联系人；
2. 点击 `通知`；
3. 由 Agent 基于当前背景生成一条自然、简短的通知；
4. 发送成功后关闭弹窗，或直接关闭弹窗而不通知任何人。

用户不编辑通知文案；没有选择联系人、没有点击 `通知` 时，系统不得自动发送。

### 6. 当前前端 Mock 的边界

本期前端 Mock 必须复现上述产品状态和交互顺序，但不得伪装外部能力已经真实发生：

- 连接应用、建立 Memory、生成 Trial 回复和联系人通知均为本地演示；
- 不发起真实授权，不读取外部资料，不向联系人或外部应用发送消息；
- 在可能被误解为真实外部动作的位置，使用低干扰说明明确「演示中不会写入外部应用」；
- Trial、连接、Memory 建立和通知失败时，保留用户当前输入与进度，说明失败并提供 `重试`；不得自动跳步、静默重试或伪造成功。

### 7. 验收标准

- 默认账号直接进入正常 Home；其他账号从四步 Onboarding 开始。
- Onboarding 期间，Home 下方仍有空的 24 小时轴与事件区；完成后四步区域消失。
- 钉钉、飞书、Teams 均有 `Connect` 行动；至少一个连接完成后才可进入第二步。
- 建立 Memory 前能看见已连接应用与读取范围；查看 Memory 返回后进度不丢失。
- 用户能查看工作风格摘要和只读的个人工作风格 Prompt 原文。
- 示例问题可写入输入区；发送后生成 Trial 事件并保留在当前会话的 Home 中。
- 调整要求只重生成当前 Trial 回复，并作为后续风格微调材料记录。
- 正式运行不被 Trial 行为阻断，但启用前必须确认。
- 启用成功后依次出现完成动效与可关闭的联系人通知弹窗；只有用户选择联系人并点击 `通知` 才触发模拟通知。
