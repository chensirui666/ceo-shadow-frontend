## 1. 背景与目标

### 1.1 背景

Friday 在工作应用中接收消息、理解工作背景并回复。用户每天真正需要确认的不是复杂的系统日志，而是：今天收到了什么、Friday 是否已经处理、是否有极少数情况需要自己决定。

现有服务已经能记录原消息、生成回复、实际发送结果、失败原因和两类反馈。Home 需要将这些能力转成用户能快速扫读的工作事件，而不是复制一套审计后台。

### 1.2 用户目标

用户打开 Home 后，应能在短时间内确认：

1. Friday 当前是试运行、正式运行还是暂停；
2. 最近 24 小时中，每个小时有多少消息已处理、待处理或发送失败；
3. 最近 24 小时内每条工作消息的处理结果；
4. 一条已处理的消息是已发送、已取消还是无需回复；
5. 少数需要本人判断的消息是什么，并在独立详情页完成处理；
6. 对一次回复给出内部反馈，或查看未来可收集的收件人反馈。

### 1.3 成功标准

- 列表中每条事件都能看清来源、对象、时间、状态、原消息摘要和回复/处理结果。
- 用户能从 24 小时总览中看清各小时的已处理、待处理和发送失败数量。
- 正式运行的常规路径清楚呈现为 `已处理`；是否外发作为处理结果呈现，不把 `待你确认`塑造成常态。
- 试运行中的任何回复均明确标识为未发送。
- 用户无需理解模型、Prompt、风险等级、任务队列或系统日志，仍能理解 Friday 为什么没有发送。
- 点击任一事件后能在详情页看到足以判断和反馈的完整信息。

## 2. 本期范围与边界

### 2.1 P0 范围

1. Home 顶部的运行状态展示与切换：试运行、正式运行、暂停。
2. 最近 24 小时的消息处理总览柱状图与统一事件列表。
3. 仅按已连接应用筛选来源：钉钉、飞书、Teams。
4. 紧凑三行事件列表与独立事件详情页。
5. 正式运行、试运行、等待、处理中、已处理、待你确认、发送失败、连接异常等可理解状态，以及清楚的处理结果。
6. 详情页内的内部反馈入口。
7. 实际已发送回复中的收件人反馈区域预览。
8. 空、加载、异常及前端演示状态。

### 2.2 明确不做

1. 不做卡片式首页、效率统计、“今日战报”或 24 小时处理总览以外的数据图表。
2. 不做跨天历史库、搜索、分页、按处理类型筛选或批量操作；这些会把 Home 变成审计台。
3. 不在列表中展开完整消息、执行依据、反馈或编辑器。
4. 不在 Home 中提供连接修复、重试发送、规则配置或 Connector 管理；它们属于 Settings。
5. 不展示模型名称、Prompt、原始推理、内部风险评分、任务标识、重试次数、工具调用或技术错误。
6. 不把生成内容称为“草稿”。产品内统一使用“回复”；是否外发由状态说明。
7. 本期不真实外发消息、不跳转第三方收件人反馈页、不提交或回流外部反馈数据；这些仅作为前端原型中的可见预览。

## 3. 产品模型与状态

### 3.1 Home 的责任

Home 是 Friday 的日常工作事件流，不是通用仪表盘。

它负责当天的运行状态和消息处理结果；Settings 负责长期规则，Memory 负责工作资料与关系地图，Feedback 负责汇总和校准长期反馈，Tasks 负责后续任务。

### 3.2 全局运行状态

| 状态 | 用户看到的说明 | Friday 的行为 | Home 主行动 |
| --- | --- | --- | --- |
| `试运行中` | `回复只供你查看，不会发送。` | 收到消息后直接处理并生成回复；不等待用户，也不对外发送。 | `正式启用` |
| `正式运行中` | `Friday 正在按你的规则协助回复。` | 先等待用户自己回复；等待结束后，常规消息自动发送，例外消息交由本人确认。 | `暂停`、`切回试运行` |
| `已暂停` | `Friday 已暂停处理新的工作消息。` | 保留既有事件，不再新增自动处理或发送。 | `恢复正式运行` |

从试运行进入正式运行，或从正式运行切回试运行，必须先出现清晰确认：前者说明后续回复会自动发送，后者说明后续回复不再发送。运行状态只在 Home 调整；Settings 只读展示当前状态并链接回 Home。

### 3.3 单条消息的处理路径

一条工作消息在列表中始终只有一个三行事件组。状态变化更新同一事件组，不为“接收、等待、处理”分别生成多条记录。

**正式运行的默认路径：**

```text
收到消息 → 等待你先回复 → Friday 处理 → 直接发送 → 已处理
```

**正式运行的例外路径：**

```text
Friday 处理 → 需要本人判断 → 待你确认
  ├─ 编辑回复后发送 → 已处理（处理结果：已发送）
  └─ 取消 → 已处理（处理结果：已取消，Friday 未发送）
```

**试运行的固定路径：**

```text
收到消息 → Friday 处理 → 测试完成，未发送
```

试运行不出现“等待你先回复”，因为 Friday 不会发送。

### 3.4 事件状态与处理结果

`已处理`是消息事件的统一正常终态，表示 Friday 或用户已经结束了这条消息的处理。`已发送`、`已取消，Friday 未发送`、`你已回复，Friday 未发送`和`无需回复`是该终态下的**处理结果**，不是并列的事件状态。这样用户不用通过“是否已发送”来判断一条消息是否还需要处理。

| 用户状态 | 出现条件 | 列表的最后一列 |
| --- | --- | --- |
| `等待你先回复` | 正式运行，仍处于用户优先回复的等待时间。 | `还会等待 3 分钟后继续处理…` |
| `正在处理` | Friday 正在整理并生成回复。 | `正在生成回复…` |
| `待你确认` | 仅当规则要求本人作关键判断。 | 已生成的回复摘要 |
| `已处理` | 该消息已完成自动处理、用户处理或无需回复判断。 | 回复或处理结果摘要 |
| `测试完成，未发送` | 试运行生成的回复。 | 已生成的回复摘要 |
| `发送失败` | 已生成回复但没有成功发送。 | `回复未发送。` |
| `连接异常` | 某个已连接应用无法继续处理。 | `Friday 暂时无法使用飞书。` |

| `已处理`下的处理结果 | 出现条件 | 详情页文案示例 |
| --- | --- | --- |
| `已发送` | Friday 自动发送，或用户在确认页选择发送。 | `回复已发送。` |
| `已取消，Friday 未发送` | 用户在 `待你确认`详情页选择取消。 | `已取消发送；Friday 未发送这条回复。` |
| `你已回复，Friday 未发送` | 用户在等待期内自己完成回复。 | `你已完成回复；Friday 未发送。` |
| `无需回复` | Friday 判断该消息只需知晓，无需对外回复。 | `已判断为无需回复。` |

等待时长使用用户在 Settings → General 中保存的当前值；Home 仅展示倒计时，不编辑该值。表中的 `3 分钟`仅为文案示例，页面显示真实剩余时间。

## 4. 页面信息架构

### 4.1 Home 列表页

页面按下列顺序排布：

1. 页面标题 `Home` 与当前日期。
2. 当前运行状态及相应主行动。
3. 标题 `最近 24 小时`。
4. 24 小时处理总览柱状图。
5. 来源筛选：默认 `全部应用`，展开后只列出当前已连接的钉钉、飞书、Teams；未连接应用不得出现在筛选中。
6. 三行事件列表。

#### 24 小时处理总览

总览使用 24 根按小时排列的**堆叠柱**。一根柱代表一个小时，柱内从下至上叠加三种消息结果；不要为每个小时并排放置三根柱，以避免 24 小时信息过密。

| 统计项 | 统计口径 | 视觉识别 |
| --- | --- | --- |
| `已处理` | 已进入正常终态的消息：包括已发送、已取消、用户已回复、无需回复，以及试运行完成的消息。 | 鼠尾草绿 `#82957D`，同时显示文字图例。 |
| `待处理` | 等待、处理中或待你确认的消息。 | 旧金色 `#B59663`，同时显示文字图例。 |
| `发送失败` | 已产生回复但未成功发送的消息。 | 陶土粉 `#BC8D86`，同时显示文字图例。 |

规则：

- 连接异常不是一条工作消息，不计入柱状图，只在事件列表中保留。
- 横轴显示最近 24 小时的小时刻度；当前小时只统计截至当前时刻的消息。
- 图例紧邻图表，始终同时显示三种状态的名称与当前总数，不能只依赖颜色。
- 悬停或键盘聚焦某小时，展示该小时三项的准确数量；来源筛选同时作用于柱状图和事件列表。
- 没有消息时，保留 24 小时刻度与低强调基线，并显示 `最近 24 小时暂无消息。`，不得显示空白图表框。

**图表颜色与细节 Token**

| Token | 色值 | 使用规则 |
| --- | --- | --- |
| `home-chart-processed` | `#82957D` | 仅用于“已处理”柱段和图例标记。 |
| `home-chart-pending` | `#B59663` | 仅用于“待处理”柱段和图例标记。 |
| `home-chart-failed` | `#BC8D86` | 仅用于“发送失败”柱段和图例标记。 |
| `home-chart-grid` | `#D9D6CE` | 图表基线、水平网格线与悬停参考线。 |
| `home-chart-focus` | `#839EB3` | 键盘焦点、当前悬停小时的细轮廓或小时标签；不改变柱段颜色。 |
| `home-chart-axis` | `#9990A8` | 小时刻度与低强调辅助文字；不用于状态判断。 |

柱段、图例和提示文字必须使用上述语义 Token，不得自行替换为高饱和的青绿、黄或红色。图表没有阴影、渐变、圆角数据卡或动画装饰；柱段之间保持极小间隙，网格线低强调。图例与悬停提示共同提供文字和数量，颜色不是判断状态的唯一方式。

#### 事件列表

列表不使用卡片容器。每个事件由紧凑的三行内容组成，事件与事件之间只用一条细横线分隔；整组内容可点击，悬停和键盘焦点清楚但克制。

```text
[{来源图标}]  {会话（没有则不显示）} · {发送人} · {时间}                         {倒计时或状态}
问题：{原消息摘要}
回复：{回复或处理结果摘要}
```

示例：

```text
[飞书图标]  产品项目群 · 刘晨 · 10:42                                  2分18秒后自动回复
问题：下周的上线时间能确定吗？
回复：目前计划在下周三完成上线，我会在周一同步最终排期…
```

规则：

- 第一行只承担来源、会话、发送人、时间和当前状态的快速识别，应明显小于问题与回复两行；会话不存在时不保留空位或分隔符。
- 只有 `等待你先回复` 显示倒计时，例如 `2分18秒后自动回复`；其余状态在同一位置显示 `已处理`、`正在处理`、`待你确认`、`测试完成，未发送`等文本状态。
- 问题和回复各自只显示一行，超出部分用省略号截断。
- `待你确认`是小型状态文本，不加大面积色块、置顶分区或全页提醒。
- `已处理`是正式运行中最常见的终态；以可靠的完成色和文字做轻量识别。已发送、已取消等具体结果在详情页中说明。
- `测试完成，未发送`使用 Trial 的低压力颜色，并明确写出“未发送”。
- 连接异常和发送失败也在同一列表内，不能被藏进单独错误页。
- 不显示列表列名、记录编号、分页、事件总数或审计筛选器。

### 4.2 事件详情页

点击列表行进入独立详情页。页首提供 `返回最近 24 小时`，返回后恢复此前的来源筛选和滚动位置。

详情页不采用左右多卡片面板，而是按阅读顺序呈现独立区段：

1. **事件信息**：来源应用、会话、发送人、发生时间、当前状态。
2. **原消息**：完整消息正文。
3. **执行依据**：一条自然语言说明，解释当前结果或为什么没有自动发送。
4. **回复**：完整生成内容或实际外发内容。
5. **当前可用操作**：仅在该状态确有必要时出现。
6. **反馈**：内部反馈；实际已发送的回复额外出现收件人反馈预览。

原消息、执行依据与回复必须使用同一套区段语言：上方是同级标题，下方是普通正文；区段之间仅以留白或细分隔线区分。执行依据不得使用警告符号、彩色提示框或与原消息、回复不同的视觉组件。

`执行依据`示例：

| 场景 | 文案示例 |
| --- | --- |
| 等待用户 | `等待你先回复，尚未开始处理。` |
| 自动发送 | `符合当前处理规则，回复已自动发送。` |
| 需要本人判断 | `涉及交付时间承诺，需要你确认后再回复。` |
| 用户取消 | `你已取消发送；Friday 未发送这条回复。` |
| 无需回复 | `这是一条通知信息，无需回复。` |
| 发送失败 | `飞书连接已失效，回复未发送。` |
| 连接异常 | `Friday 暂时无法使用飞书，因此没有继续处理新的消息。` |

详情页不得展示“模型如何思考”的过程、内部规则名或任何工程信息。

### 4.3 详情页内的状态操作

| 状态 | 回复区 | 用户可做的操作 |
| --- | --- | --- |
| `等待你先回复` | 不显示回复内容。 | 无；展示剩余等待时间。 |
| `正在处理` | 显示 `正在生成回复…`。 | 无。 |
| `待你确认` | 展示可编辑的完整回复。 | `发送`、`取消`。 |
| `测试完成，未发送` | 展示完整回复与“未发送”说明。 | 提交内部反馈。 |
| `已处理` | 展示完整回复或处理结果；事件信息下以普通文本显示具体结果。 | 有回复时可提交内部反馈；结果为`已发送`时可查看收件人反馈预览。 |
| `发送失败` / `连接异常` | 展示已生成回复（若有）与执行依据。 | 无。 |

点击 `发送`后，事件更新为 `已处理`，处理结果为`已发送`。点击 `取消`后，Friday 不再发送该条回复，事件同样更新为 `已处理`，处理结果为`已取消，Friday 未发送`。Home 不在失败或连接异常状态中增加“重试”“重新连接”等额外操作；用户需要时可自行前往 Settings。

## 5. 反馈

### 5.1 内部反馈：来自分身所有者

内部反馈帮助 Friday 校准后续表达和判断。它不在列表中出现，只放在有回复的详情页末尾。

用户可选择：

- `符合我`：快速确认这次回复符合预期。
- `需要调整`：展开输入框，填写“哪里不对、以后应怎样处理或表达”。

保存后，页面给出 `反馈已记录`，该信息在后续的 Feedback 页面中汇总。保存反馈不会改写已经处理完成的回复，也不承诺在当前页面立即生成另一版回复。

### 5.2 收件人反馈：来自外部对象

收件人反馈只与处理结果为`已发送`的回复关联，用于了解回复是否解决问题、还缺少什么信息。

本期详情页展示一个可见的 `收件人反馈` 预览区域，包含未来外发反馈页的内容：

1. 👍 `有帮助` / 👎 `未解决`；
2. `这条回复是否解决了你的问题？`；
3. `请说明还需要补充什么信息或下一步。`；
4. 👍 的文字补充可选；👎 的具体说明必填。

本期仅展示该区域，不实际附加到外发消息、不跳转第三方页面，也不接收提交结果。未来完成外发反馈能力后，详情页在此处展示收件人的反馈结果与具体文字。

## 6. 首次使用、空状态与异常状态

| 场景 | 页面内容 | 主行动 |
| --- | --- | --- |
| 尚未完成 Onboarding | Home 顶部呈现四步 Onboarding 区域；事件列表可见但不虚构数据。完成后该区域消失。 | 由四步 Onboarding PRD 定义。 |
| 已完成引导，但暂无事件 | `等待第一条工作消息`；`Friday 收到需要处理的消息后，会在这里展示判断与回复结果。` | 无。 |
| 没有已连接应用 | `连接一个工作应用后，Friday 才能开始处理消息。` | `前往 Settings`。 |
| 某来源筛选下无事件 | `最近 24 小时内没有来自飞书的工作消息。` | `查看全部应用`。 |
| 页面暂时无法加载 | `暂时无法加载最近事件，请重试。` | `重试`。 |
| 详情不存在或不可访问 | `这条工作事件暂时无法查看。` | `返回最近 24 小时`。 |

## 7. 视觉与交互规则

1. **总览为辅，列表优先。** 柱状图只用于看 24 小时的处理密度与结果分布；Home 主体仍是连续、可扫读的事件列表，不用卡片套卡片。
2. **状态清楚但不喧宾夺主。** 试运行使用低压力的浅紫；列表中的正式运行和已处理使用可靠的完成色；失败使用明确的警示色；`待你确认`只用克制的暖色标签。柱状图状态一律遵循本节定义的 Memory 莫兰迪色 Token。
3. **来源负责识别，不负责抢占注意力。** 应用以文字与小图标区分，不为每个来源赋予大面积背景色。
4. **用户语言。** 状态使用“已处理”“待你确认”“测试完成，未发送”；具体结果使用“已发送”“已取消，Friday 未发送”。不出现“草稿”“Codex reason”“send status”等内部或工程词。
5. **信息渐进展开。** 列表只提供识别和扫读；完整内容、反馈与编辑只在独立详情页出现。
6. **键盘与阅读可达。** 每行可聚焦并通过 Enter 打开；截断内容在详情页始终可完整阅读；状态不只依赖颜色表达。

## 8. 前端演示状态

本期仅交付 Web 前端，演示必须让评审者看见真实产品会遇到的状态，而不是只展示一条永远成功的静态消息。

| 演示场景 | 必须呈现的状态 |
| --- | --- |
| 正式运行常规消息 | `等待你先回复` → `正在处理` → `已处理`（处理结果：`已发送`）。 |
| 正式运行例外消息 | `待你确认`；可编辑回复，模拟发送后更新为 `已处理`（处理结果：`已发送`），或点击取消后更新为 `已处理`（处理结果：`已取消，Friday 未发送`）。 |
| 试运行 | `测试完成，未发送`，并可提交内部反馈。 |
| 无需回复 | `无需回复`与对应执行依据。 |
| 失败或断连 | `发送失败`或`连接异常`与用户可理解的执行依据。 |
| 收件人反馈 | 处理结果为`已发送`的详情中的收件人反馈预览，不发生实际跳转或提交。 |

前端演示中的 `发送` 只更新界面内的事件结果，不向钉钉、飞书或 Teams 外发任何消息；页面必须明确区分演示状态与真实外发能力。

## 9. P0 验收清单

### 列表与状态

- [ ] Home 默认显示最近 24 小时内的处理总览与统一事件列表。
- [ ] 总览以 24 根按小时堆叠的柱展示已处理、待处理和发送失败；来源筛选同时更新总览和列表。
- [ ] 连接异常不计入柱状图；图例与聚焦/悬停信息提供准确数量，不能只依赖颜色。
- [ ] 每条消息只保留一个三行事件组，状态更新不产生重复记录。
- [ ] 每个事件组第一行显示来源图标、可选会话、发送人、时间和倒计时/状态；第二、三行分别显示问题和回复或处理结果。
- [ ] 问题和回复均为单行截断；列表中不显示完整内容、执行依据和反馈。
- [ ] 来源筛选只展示已连接的钉钉、飞书、Teams。
- [ ] 正式运行常规消息的终态为 `已处理`，并在详情页显示处理结果为`已发送`；`待你确认`仅作为例外状态出现。
- [ ] 试运行始终显示“未发送”，且不出现用户等待倒计时。
- [ ] 发送失败、连接异常与无需回复均出现在同一事件流中。

### 详情与反馈

- [ ] 点击列表行打开独立详情页，返回后保留列表筛选与位置。
- [ ] 详情页能展示完整原消息、执行依据、完整回复和对应状态。
- [ ] 所有生成内容在用户界面中称为“回复”，不出现“草稿”。
- [ ] `待你确认`状态支持编辑回复、模拟发送和取消；两种操作都会进入`已处理`，并显示各自处理结果。
- [ ] 失败与连接异常详情不提供重试或重新连接操作。
- [ ] 有回复的详情可记录内部反馈；处理结果为`已发送`的详情展示收件人反馈预览。
- [ ] 外部反馈预览含 👍 / 👎、解决状态和具体文字反馈字段；👎 标明具体说明必填。

### 一致性与边界

- [ ] Home 负责试运行、正式运行、暂停和当天事件；Settings 不提供这些状态开关。
- [ ] Home 不展示模型、Prompt、内部判断或工程错误信息。
- [ ] 无连接、无事件、筛选无结果、加载失败和详情不可访问均有明确下一步。
- [ ] 前端演示不将任何点击伪装成真实的应用外发或外部反馈提交。
