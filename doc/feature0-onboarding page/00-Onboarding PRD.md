## 1. 一句话定义

**初始化是用户在数字人分身工作台内，为一个“连接器＋账号”工作身份确认资料范围和处理说明的过程；首次从选择 Connector 开始，切换到新 Connector 时从建立 Memory 开始，后台结果无需等待。**

除明确标注为 Friday App 的工作台选择与加载外，本文中的 Message、Memory、Settings、Feedback 均是数字人分身工作台内部能力，不构成 Friday 的全局导航。

## 2. 背景、目标与范围

### 2.1 背景

同一工作空间同一时刻只有一个**活动 Connector**，并按两个入口初始化：

| 入口 | 可见步骤 | 说明 |
| --- | --- | --- |
| 首次初始化 | 1. 选择并连接 Connector → 2. 建立工作 Memory → 3. 设置工作风格 | 当前没有活动 Connector 时使用；欢迎弹窗说明完整三步。 |
| 切换到新 Connector | 1. 建立工作 Memory → 2. 设置工作风格 | 用户已在 Settings 选择并确认新的 Connector；不再重复连接选择，也不显示首次欢迎弹窗。原三步流程的第 2、3 步在此路径中重新编号为第 1、2 步。 |

无论入口如何，Memory 与工作风格均在用户确认后转入后台；“完成配置”和烟花只代表当前身份的初始化流程结束，不代表后台任务已完成。


### 2.2 业务目标

- 让首次进入数字人分身工作台的用户在不阅读帮助文档的情况下理解当前工作边界和下一步。
- 在用户确认工作方式的处理说明后，将任务转入后台；用户无需等待产物即可完成首次配置。
- 让首次配置完成后直接进入 Message，开始阅读与管理真实工作信息，而不是进入运行仪表盘。
- 为生产化连接、Memory、正式使用和发送门禁建立明确的服务端验收边界，避免把本地演示误认为真实能力。

## 5. 功能需求

### 5.1 进入与身份选择规则

| 需求 | 规则 | 优先级 |
| --- | --- | --- |
| 首次进入判定 | Friday App 成功加载数字人分身工作台后，系统依据当前工作台及活动 Connector 的初始化状态决定进入初始化或该工作台的 Message；不能以一个固定演示邮箱作为生产判定。 | P0 |
| 活动 Connector | 同一工作空间同一时刻最多绑定一个活动 Connector。它是当前 Message 与时钟任务中心中任务、完成结果和未读状态的唯一数据归属。 | P0 |
| 首次欢迎弹窗 | 仅当用户尚未选择任何 Connector 时展示三个步骤、开始按钮与关闭按钮；如展示预计耗时，须明确仅为体验提示。关闭只收起说明，流程仍停在第 1 步。 | P0 |
| 切换入口 | 用户在 Settings 选择新的 Connector 后，先确认切换；确认后关闭 Settings 并进入该 Connector 的两步初始化。若该身份已完成初始化，则直接恢复其 Message，不重新初始化。 | P0 |
| 保留非活动身份 | 切换不会删除旧身份的 Memory、工作风格、任务或历史完成结果，也不会把它们合并到新身份。旧身份停止作为当前读取／处理来源，切回时恢复。 | P0 |
| 预计耗时 | 只有经过真实数据验证后才能展示具体时长；演示中的固定数字不作为产品承诺。 | P1 |
| 语言 | 首次流程与全站语言保持一致，中英文切换不能造成混合文案或步骤丢失。 | P0 |

### 5.2 首次初始化第 1 步：选择并连接 Connector

用户看到“连接你的工作入口”，理解 Friday 只会在已授权范围内工作。V1 仅展示钉钉作为可连接主渠道，说明它处理的范围和默认边界：只考虑与本人相关、符合规则的工作信息；不会因为连接就获得无限读取权或自动外发权。

| 情况 | 页面行为 |
| --- | --- |
| 未连接 | 主按钮为“连接钉钉”；继续按钮禁用，并说明必须选择一个工作来源。 |
| 用户发起连接 | 当前前端仅显示明确的本地演示说明和本地状态变化；不以成功状态替代真实授权。 |
| 本地连接完成 | 显示唯一选中的“连接器＋账号”和演示范围摘要；用户可继续到建立 Memory。 |
| 已选择 Connector 后连接其他 Connector | 弹出“切换到 {新 Connector}？”确认：当前仅支持一个 Connector；连接 {新 Connector} 将取消 {当前 Connector} 的连接，并将本次初始化的数据来源切换为 {新 Connector}。`取消`保留当前连接；`切换并连接 {新 Connector}`才先取消当前连接，再开始新 Connector 的连接。 |
| 切换失败 | 保持当前连接并说明失败原因与重试入口；不得同时显示两个已连接 Connector，或伪造新 Connector 已连接。 |
| 连接失败／取消 | 保留当前步骤，说明失败原因与重试入口；不创建虚假的连接记录。 |

连接后的长期管理入口属于 Settings；Onboarding 只完成首次建立和最小范围确认。

### 5.3 建立工作 Memory（首次第 2 步／切换后第 1 步）

这一环节回答“Friday 将依据什么理解我”。用户确认后，Friday 自动从已连接钉钉账号的工作资料中建立首版 Memory。

#### 用户流程

1. **进入此步**：用户看到当前活动的“连接器＋账号”、将读取的资料范围和“建立工作 Memory”按钮。
2. **确认范围**：点击按钮后打开来源范围确认弹窗；当前身份只有一个 Connector，确认后以该 Connector 的已授权范围提交任务。
3. **立即转后台**：提交成功后立即关闭范围确认弹窗，自动展开右上角的“任务中心”时钟面板约 3 秒。面板列出“建立工作 Memory”“正在后台处理”和粗略预计时间；不显示等待弹窗、环形倒计时、百分比或伪造的完成时间。
4. **继续或离开**：此步主按钮变为“继续”，用户可进入下一可见步骤，或直接离开当前页面；Memory 在后台继续。用户可随时点击时钟查看**当前活动身份**的运行任务与完成结果。
5. **首次可用、资料不足或失败**：由真实任务状态决定。首次可用时在时钟任务中心中显示完成结果；资料不足时生成安全初始工作画像并如实说明背景有限；失败时显示原因和“重试”，不显示已建立的假状态。

#### 时钟任务中心

| 入口／时机 | 用户可见行为 | 规则 |
| --- | --- | --- |
| 提交 Memory 或工作风格任务后 | 右上角**时钟**自动展开“任务中心”小面板，约 3 秒后自动收起。 | 只列出当前活动身份的任务，按“处理中”和“已完成”分组；处理中任务展示名称、状态和粗略预计时间（当前界面为“约 20 分钟”）。 |
| 用户点击时钟 | 打开或收起任务中心。 | 任务中心同时承担进度与完成结果入口；不展示假百分比或前端倒计时，不混入非活动身份任务。仅打开面板不清除未读红点。 |
| 后台任务真实完成后 | 该任务移入“已完成”，所属身份的右上角**时钟**出现红点。 | 用户点击对应完成结果后，才将该任务标为已读；当前身份没有未读完成结果时移除时钟红点。切换到其他身份时不展示该红点，切回后恢复。 |
| 工作风格完成结果 | 展示“你的工作风格已生成”和“查看个人风格”。 | 点击对应结果后进入 Settings 的个人资料／个人风格位置，并将该结果标为已读。 |
| Memory 完成结果 | 展示“工作记忆已构建完成”。 | 点击对应结果后将其标为已读；当前不额外跳转到 Message，也不在 Message 导航或列表中增加红点、卡片或通知。 |

前端不得以定时器把运行中任务改为已完成；任务完成、失败与重试必须来自可验证的后台状态。失败任务在任务中心显示原因和“重试”，但不生成完成结果或未读红点。当前本地前端仅提供该状态的展示和消费接口，尚未接入真实任务服务。

#### 首次资料范围与后续更新

- **时间范围**：建立首次 Memory 时读取连接当日向前一年的资料；后续更新只处理新出现或已更新的资料。
- **群聊**：读取用户参与群聊中的消息。
- **单聊**：读取用户与他人的单聊消息。
- **会议**：读取用户参与会议的会议纪要。
- **文档**：读取与用户直接相关的文档，包括 @ 用户、由用户创建/编辑/阅读/收发，或出现在上述消息和会议中的文档。
- **权限边界**：只读取该用户在钉钉中有权限访问的内容。
- **隐私处理**：P0 不在 Friday 侧额外增加脱敏、内容分类或人工复核；资料进入现有 Memory 系统后，按其既有能力处理。
- **更新方式**：新群聊和单聊消息实时补入 Memory；新增或更新的会议纪要、相关文档通过增量扫描补入或覆盖旧版本。
- **删除范围**：P0 不处理消息撤回、资料删除或权限变化后的 Memory 回溯清理。

#### 原始资料与实时更新数据

- **不建副本**：Friday 不建立原始聊天、会议纪要或文档的长期资料库；钉钉仍是原始资料来源。
- **首次建立**：原始资料只在建立 Memory 和工作方式期间使用；提炼完成后自动清理。建立失败或取消时同样清理。
- **实时更新**：只保留来源 ID和处理状态；内容写入 Memory 后立即清理。重试时从钉钉重新读取，不保留内容副本。
- **留存与空间**：Friday 不长期落盘保存原始资料，因此原始资料的最终留存为零，也不设置原始资料磁盘配额。
- **追溯与删除**：需要追溯时，依据来源 ID 从钉钉按权限读取。

#### 多账号 Memory 隔离

- **工作身份**：每个“连接器＋账号”都是独立工作身份，例如飞书、钉钉 A、钉钉 B。
- **单活动约束**：同一工作空间同一时刻只能有一个活动工作身份。用户在 Settings 选择另一 Connector 后必须确认切换；原身份变为非活动，不再读取或处理新的来源内容。
- **首次初始化**：首次连接新的工作身份时，按本节资料范围建立它自己的 Memory 和工作方式；由于 Connector 已在 Settings 选定，流程从本节开始并显示为第 1 步。切回已初始化的身份时直接恢复，不重复初始化。
- **隔离范围**：不同工作身份的资料来源、Memory、工作方式、实时更新状态和处理记录彼此隔离。Friday 在任一身份中只读取和使用该身份的资料，不跨身份检索、回复或更新。
- **任务延续与结果可见性**：身份切换不暂停或取消已提交的后台任务；它们继续在原身份下完成。任务结果、时钟状态和未读完成状态只在原身份的任务中心可见，切回后恢复显示。
- **跨账号范围**：P0 不提供跨账号合并或共享 Memory 的能力；如需共享资料，后续单独设计显式流程。

### 5.4 设置工作风格（首次第 3 步／切换后第 2 步）

第 3 步只让用户确认**要进行什么处理**，不等待任务产物，也不展示、编辑或确认提示词／工作方式草稿。任务完成后，用户再从时钟任务中心进入 Settings 查看个人风格。

#### 用户流程

1. **进入此步**：用户看到 Friday 将处理的范围和摘要：表达、判断、下一步与边界；前一步的 Memory 补充可继续在后台运行。
2. **确认处理说明**：用户点击“确认处理说明”后，弹出确认弹窗，明确 Friday 将基于当前已连接且可用的工作材料整理上述四项。
3. **开始后台处理**：用户点击“开始后台处理”后，工作风格任务立即排入后台；确认弹窗关闭，时钟自动展示该身份的运行任务。取消则留在此步，不创建任务。
4. **完成配置**：任务已提交后，此步主按钮变为“完成配置”。此时不出现提示词确认、查看风格、正式开始或工作方式结果，因为后台尚未产出信息。
5. **最终确认与去向**：点击“完成配置”后再弹出一次最终确认，说明工作风格会继续在后台处理，完成后将由通知提醒。用户确认完成后，Onboarding 结束并播放烟花；动效结束后的完成弹窗由用户点击“开始体验”进入 Message。

#### 工作方式的资料范围

工作方式不使用全部 Memory，只使用当前“连接器＋账号”中符合下列条件的资料；符合条件的资料全部使用，不再按相关性二次筛选。

- **本人消息**：当前连接账号本人发送，且来自已纳入范围的群聊或单聊；仅限有文字内容的原始消息。转发、系统通知、表情和仅含附件的消息不纳入。
- **本人文档**：文档创建者是当前连接账号，且有实际正文内容。仅阅读、被 @、收到或协作编辑但不是创建者的文档不纳入。

### 5.5 完成配置与完成去向

完成配置不表示后台工作方式任务已经完成，也不授予真实外发权限。它只完成当前活动“连接器＋账号”的初始化，并将用户带到该身份的 Message；生产环境的真实外发权限仍由服务端门禁和渠道健康状态决定。

| 需求 | 规则 | 优先级 |
| --- | --- | --- |
| 前置条件 | 工作风格任务已由用户确认并成功提交到后台；不要求任务完成。 |
| 点击完成配置 | 打开最终确认弹窗，告知任务仍在后台处理且完成后会在右上角时钟任务中心显示结果。 |
| 最终确认 | 用户确认后才写入当前工作身份的初始化完成状态并进入烟花庆祝。取消则回到当前可见的工作风格步骤，不取消已提交的后台任务。 |
| 本地演示 | 可以完成本地 Onboarding 并进入 Message，但不能改变真实授权、发送或外发状态。 |
| 真实环境缺少服务端发送门禁、渠道健康或授权 | 不授予真实外发权限，明确说明缺少条件与下一步。 |
| 所有真实条件满足 | 服务端写入正式使用状态，再展示庆祝动效；用户完成庆祝后进入 Message 默认列表。 |

#### 完成配置庆祝动效

用户在最终确认后，页面展示一次 **5 秒烟花庆祝动效**，向用户明确传达“当前工作身份已完成配置”。它不表示后台 Memory 或工作风格任务已经完成。

- 动效结束后展示静态完成弹窗，用户点击“开始探索”进入 Message；不自动跳转，确保用户能读到完成结果。

完成后不再展示占据主页面的初始化流程。用户可以在 Settings 切换活动 Connector 或查看长期偏好，在 Memory 查看当前身份的资料与工作画像，在 Message 看当前身份的后续工作信息；重新进入初始化只用于新的未初始化身份或明确的重设能力。

## 7. 数据、权限与非功能要求

### 7.1 最小数据

生产服务至少需要保存：账户标识、唯一活动 Connector、每个“连接器＋账号”的初始化当前步骤／完成状态、连接渠道与授权范围、首次 Memory 的来源范围和版本、工作方式版本、后台任务的提交／运行／完成／失败状态、粗略预计时间、已读／未读完成结果、完成配置时间，以及真实运行状态。所有记录按账户和私有工作空间隔离；身份数据不可混合。

前端只消费已授权的状态和摘要。它不能自行推断“已连接”“已读取”“已外发”或“正式启用”，更不能把 `localStorage` 的键名当作隔离边界。

### 7.2 安全与隐私

- 授权范围须最小化、可理解、可追溯；用户未确认的来源不得用于 Memory。
- Onboarding 的任何步骤、时钟任务中心、庆祝动效和完成弹窗都不得调用外部发送能力；真实正式模式仍必须经过用户点击、服务端门禁与渠道健康检查。
- 高风险承诺、敏感内容、权限不足和材料不足时，Friday 交回用户，而不是自动回复。
- 不把“所有数据都在本地”作为笼统承诺；外部 Memory 或云端控制面应按实际授权和存储边界说明。
- 页面不显示 Token、账号密钥、数据库 ID、内部 Prompt、原始思维链或调试日志。

### 7.3 可用性与可访问性

- 所有步骤在支持的桌面宽度内有稳定布局；窄屏按既有规格纵向排列。
- 进度、连接、处理、错误和禁用状态不能只依靠颜色表达。
- 键盘可聚焦所有按钮、输入框和弹窗操作；弹窗保留可见焦点并支持减少动效。
- 处理中允许用户理解当前动作和安全取消／返回；网络或服务异常不丢失已确认的步骤数据。

## 10. 验收标准

### 产品流程

- [ ] Friday App 完成数字人分身工作台加载后，未初始化用户进入该工作台的 Onboarding；已完成用户直接进入该工作台的 Message。
- [ ] 无活动 Connector 的用户看到三步欢迎与连接选择；关闭欢迎弹窗不跳过配置。
- [ ] 同一工作空间同一时刻仅有一个活动 Connector；选择新 Connector 必须经过切换确认，旧身份被保留为非活动身份而非删除或合并。
- [ ] 首次第 1 步已选择 Connector 后，点击另一 Connector 的连接入口必须显示互斥提醒；取消保留当前连接，确认后取消当前连接并连接新 Connector，页面任何时候最多显示一个已连接 Connector。
- [ ] 新 Connector 在 Settings 选定后直接进入两步初始化：建立 Memory 为第 1 步，设置工作风格为第 2 步；已初始化身份切回后直接恢复 Message。
- [ ] Friday 自动准备开源执行框架；用户不看到模型、下载、登录或配置入口。
- [ ] 首次路径未选择 Connector 不能进入 Memory；未提交首次 Memory 不能进入工作风格；未确认工作风格处理说明不能提交对应后台任务。
- [ ] Memory 来源确认后立即关闭弹窗，自动展示时钟任务中心；页面不出现等待弹窗、环形倒计时、百分比或“关闭／继续”交接按钮。
- [ ] 提交 Memory 或工作风格后，时钟任务中心展示处理中任务、状态和粗略预计时间，并约 3 秒后自动收起；后台任务真实完成后，同一入口展示完成结果与未读红点。
- [ ] 工作风格提交后不显示提示词确认、查看风格、正式开始或任务结果，只显示“完成配置”。
- [ ] 点击“完成配置”必须经过最终确认；确认后播放一次 5 秒烟花庆祝动效，在“减少动态效果”偏好下直接显示静态完成弹窗。
- [ ] Onboarding 的输入、确认、时钟任务中心、庆祝和完成均不触发对外消息、外部任务或联系人通知。
- [ ] 真实正式模式只在用户点击、渠道健康和服务端发送门禁全部满足时生效；否则明确说明权限状态。
- [ ] 庆祝结束后由用户点击完成弹窗进入 Message；动效和弹窗均不暗示后台任务或通知已经完成。
- [ ] 完成后进入 Message，而不是旧 Home 运行面板。
- [ ] Connector 切换不取消旧身份已经提交的后台任务；旧身份的时钟任务中心、未读红点和完成结果仅在切回该身份后显示，且不会混入当前身份。

### 真实性与安全

- [ ] 当前前端遗留的废止步骤在产品实现中删除；在真实验证前，不声称 Friday 已成功下载、安装或启动执行框架。
- [ ] 未接入的渠道没有“连接”或“已连接”假象；V1 对外只承诺钉钉主渠道。
- [ ] 建立 Memory 前可见来源范围；未授权来源不参与建立。
- [ ] 后台任务只能由可验证的后台状态变为完成；前端不以 20 分钟倒计时或其他定时器制造完成通知。
- [ ] 进度与完成结果只由时钟任务中心承载；完成任务的红点只出现于时钟。打开任务中心不清除红点，进入对应完成结果后才将其标为已读。
- [ ] 工作风格完成结果可从时钟任务中心跳转到 Settings 的个人资料／个人风格；Memory 完成结果不在 Message 额外创建卡片或红点。
- [ ] 不显示原始资料、系统 Prompt、模型推理、密钥或技术日志。
- [ ] 所有演示结果显式标为本地演示，且不能改变真实外发状态。

### 体验与实现

- [ ] 用户可回看已完成步骤，不能跳到未完成步骤；恢复流程时不丢失已确认信息。
- [ ] 中英文文案完整一致；键盘、焦点、禁用状态和减少动效均可用。
