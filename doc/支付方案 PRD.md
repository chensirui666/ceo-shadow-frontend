# Friday 支付方案 PRD

| 项目 | 内容 |
| --- | --- |
| 版本 | v1.1 |
| 更新日期 | 2026-09-02 |
| 适用产品 | Friday 的付费订阅套餐 |
| 已确认策略 | 国内：Ping++ 聚合微信支付/支付宝（必要时可改为直连）；海外：Stripe |

## 1. 背景与目的

Friday 需要让中国大陆和海外用户都能完成订阅购买，并在付款后获得相应的产品权益。由于收款主体、支付习惯、商户准入和税务要求不同，国内与海外使用两套支付通道：

| 市场 | 收款方案 | 首发目标 |
| --- | --- | --- |
| 中国大陆 | 以 Ping++ 聚合微信支付、支付宝为主；经评估也可直连微信支付或支付宝 | 至少开通微信支付、支付宝中的一种，支持人民币付款 |
| 海外 | 海外商户主体接入 Stripe | 支持国际银行卡，并在账户和市场允许时开通常见钱包方式；支持自动续费订阅 |

本计划的终点是：用户在 Friday 内选择套餐、完成支付，并获得对应权益；公司能够查询订单、处理退款和完成财务对账。

推进顺序应固定为：先确定谁在卖、卖什么、向谁卖；再完成面向用户的合规页面与支付渠道的账号、签约和审核；最后才将已开通的支付能力接入 Friday。具体技术设计、材料字段和渠道后台操作，由执行该步骤的人员按当时的官方要求完成。

---

## 2. 国内支付详细 SOP 流程

**完成目标：** 中国大陆用户可在 Friday 支付人民币，首发至少支持微信支付或支付宝其中一种；付款、退款与对账可正常闭环。

### 第一步：确定国内收款方案与首发范围

明确国内销售主体、收款币种（人民币）、首发套餐、价格、退款取消规则，以及首发的支付方式。

- 默认路径为 Ping++ 聚合接入；同时确认首发是否先开支付宝、微信支付，或两者一起开通。
- 如果 Ping++ 的商务条件、准入结果或业务场景不适合，再决定改为直连微信支付、支付宝；这个决定必须在账号申请前完成，避免重复进件。
- 国内首发以单次购买月付或年付为宜；自动续费/代扣另行确认渠道资格和用户授权要求后再做。

**做到什么程度：** 有一份确认过的国内售卖说明，写清销售主体、套餐价格、首发支付方式、退款规则和是否自动续费。

### 第二步：补齐用户可见的购买与合规信息

在正式申请渠道前，让支付机构和用户能清楚看到 Friday 卖什么、由谁卖、如何联系和如何退款。

- 准备可正常访问的官网或购买页，展示产品介绍、套餐/价格、公司名称和客服联系方式。
- 上线服务协议、隐私政策、付款说明、退款/取消政策和发票说明。
- 确认网站备案情况；若网站备案主体与收款主体不同，准备相应授权材料。
- 审核 AI 服务的实际业务描述、经营类目和可能需要的行业资质，按真实业务填写，不规避渠道准入规则。

**做到什么程度：** 所有付费相关页面可访问，且销售主体、商品、价格、协议和客服信息彼此一致。

### 第三步：准备商户申请材料

集中整理材料并妥善保管，提交时以渠道后台的最新清单为准。基础材料通常包括：

- 营业执照、企业全称、统一社会信用代码和注册地址；
- 法定代表人证件，以及经办人/管理员的身份和授权材料；
- 企业对公银行账户、开户行信息和财务联系人；
- 官网地址、产品介绍、价格页、客服联系方式、退款取消政策与协议页面；
- 网站 ICP 备案信息；备案主体不一致时的网站授权材料；
- 如业务类目要求，补充对应的行业许可证或说明。

身份证件、银行账户和证照应放在受控资料夹中，不放入代码仓库或普通聊天群。

**做到什么程度：** 一套可供 Ping++、微信支付或支付宝重复使用的材料包已备齐，信息与公开网站一致。

### 第四步：注册账户、签约并完成商户进件

按第一步确定的路径申请渠道账号和商户资格。

1. 注册 Ping++ 企业账户，确认是公司直连商户还是通过其服务商模式进件；若选择直连，则注册对应的微信支付/支付宝商户账户。
2. 按渠道要求提交第三步的材料，完成法人授权、经办人核验、对公账户验证等流程。
3. 阅读并签署服务协议和商户协议，重点确认费率、结算周期、退款规则、资金冻结/准备金、争议处理和终止条件。
4. 在渠道后台申请首发支付产品：例如支付宝电脑网站支付，或适合 Friday 使用场景的微信支付产品。若要同时支持两种方式，分别完成开通。
5. 等待审核；渠道补件时以最新要求补充，不以“已注册账号”视为可收款。

**做到什么程度：** 已取得正式商户号/应用信息，首发支付方式显示为已开通；费率、结算规则和协议已留档。

### 第五步：确认上线前的业务规则

在交给研发接入前，统一用户购买后和异常情况下的处理方式。

- 明确成功付款后用户获得什么套餐、有效期从何时开始；
- 明确用户取消、退款、支付失败、重复付款和订单超时的处理规则；
- 确认客服查询订单、发起退款和答复用户的方式；
- 确认财务使用哪些渠道账单完成日常对账和结算核对。

**做到什么程度：** 购买、退款、客服和对账的规则可以被产品页面、客服话术和财务流程一致地执行。

### 第六步：将国内支付接入 Friday 并上线

在商户审核和业务规则均完成后，研发将已开通的 Ping++（或微信/支付宝直连）支付能力接入 Friday。

研发在前述条件完成后，将已开通的支付能力接入 Friday：让用户完成购买后获得对应权益，并使订单查询、退款处理和财务对账可以正常进行。完成上线前验证后，向用户开放。

**完成标志：** 国内用户可以在 Friday 完成首发支付方式的付款；公司可以查到订单、处理退款并核对到账情况。

国内商户资料与产品申请以 [微信支付商户资料说明](https://pay.weixin.qq.com/doc/v3/merchant/4013836340)、[支付宝商家签约资料](https://opendocs.alipay.com/open/01n22g) 和 [Ping++ 产品说明](https://docs.pingxx.com/products.html) 的当期规则为准。

## 3. 国外支付详细 SOP 流程

**完成目标：** 海外用户可使用 Stripe 支持的常见方式购买 Friday 订阅，并能自行管理续费；公司可完成收款、退款、税务和对账工作。

### 第一步：确定海外销售范围

以现有海外商户主体作为海外用户的签约和收款主体，先确定首发市场和售卖规则。

- 确认目标国家/地区、结算币种、首发套餐、价格和免费试用规则；
- 确认海外主体在网站、账单、支付收据和用户协议中使用的准确名称；
- 确认退款、取消订阅、续费失败和客服支持规则；
- 首发以国际银行卡为基础。Apple Pay、Google Pay、PayPal 或当地支付方式，按 Stripe 账户资格、目标市场和用户需求逐步开通，不预先承诺所有方式都可用。

**做到什么程度：** 有一份确认过的海外售卖说明，明确销售主体、首发市场、套餐/币种、续费与退款规则。

### 第二步：完成海外法务与税务准备

在开始收款前确认海外主体有资格销售该服务，并明确向用户和政府承担的义务。

- 准备海外用户使用的服务协议、隐私政策、付款与续费说明、退款取消政策、客服联系方式和公司信息；
- 核对 Stripe 的可接受业务范围、争议/拒付和数据处理条款；
- 由法务或税务顾问判断主体所在国和目标销售地的间接税义务，确定是否需要税务登记、收税和申报；
- 如需收税，明确税号、税率、开票/收据和申报安排。Stripe Tax 可帮助计算已登记地区的税，但不能替代税务登记和申报。

**做到什么程度：** 海外销售页面和合同文本可上线，税务处理方式已明确，不以支付平台代替法务或税务判断。

### 第三步：准备 Stripe 账户审核材料

Stripe 会核验商户主体、控制人、结算账户和实际业务。申请前通常需要准备：

- 海外主体的注册证书、注册地址、税号或商业登记信息；
- 公司董事、账户代表人及实际受益人的身份和联系方式；
- 该主体名下可结算的银行账户及币种信息；
- 可访问的官网、产品说明、价格、公司信息、客服联系方式和各项用户政策；
- Stripe Dashboard 管理员名单及账户安全设置方案。

具体字段会随主体注册地和业务情况变化，以 Stripe Dashboard 的实时要求为准。

**做到什么程度：** 提交材料后，Stripe 账户没有待补的关键验证项，且网站公开信息与账户资料一致。

### 第四步：注册、激活并配置 Stripe

1. 用海外商户主体注册 Stripe 账户，填写真实的公司、控制人和业务信息。
2. 提交审核材料并按要求完成身份、企业和银行账户验证。
3. 开启双重验证，设置管理员和使用权限，避免共享主账号。
4. 设置结算银行账户、结算币种和收款信息；确认用户信用卡账单上会显示的商户名称。
5. 在 Stripe 中建立 Friday 的套餐与价格，并配置月付/年付、税务信息和用户管理订阅的入口。
6. 根据目标市场开启首发支付方式：国际银行卡为必选项；合资格时再开通钱包或当地方式。

**做到什么程度：** Stripe 账户审核完成，银行账户和首发支付方式可用，Friday 的套餐和价格已在 Stripe 中配置完成。

### 第五步：确认上线前的海外业务规则

在研发接入前，将支付平台配置和 Friday 的订阅规则对齐。

- 确认成功付款、自动续费、支付失败、取消、升级降级和退款时，用户权益应如何变化；
- 确认用户如何查看账单、更新付款方式和取消订阅；
- 确认客服、财务对退款、拒付和争议的处理方式；
- 确认财务按 Stripe 的付款、退款、手续费、税额和结算报表进行核对。

**做到什么程度：** 用户订阅生命周期和公司的客服、财务处理方式已有一致规则。

### 第六步：将 Stripe 接入 Friday 并上线

在 Stripe 已审核、支付方式已启用、套餐与业务规则已确认后，研发将 Stripe 的订阅能力接入 Friday。

研发在前述条件完成后，将 Stripe 的订阅能力接入 Friday：让用户完成订阅、管理续费，并使支付结果与 Friday 权益、订单查询、退款处理和财务对账保持一致。完成上线前验证后，逐步向海外用户开放。

**完成标志：** 海外用户可在 Friday 完成订阅购买和续费管理；公司可查询订单、处理退款/争议并完成税务与资金对账。

海外账户审核、订阅与税务配置以 [Stripe 账户上线清单](https://docs.stripe.com/get-started/account/checklist)、[Stripe Checkout](https://docs.stripe.com/payments/checkout)、[Stripe 订阅说明](https://docs.stripe.com/payments/checkout/build-subscriptions) 和 [Stripe Tax](https://docs.stripe.com/tax/set-up) 的当期规则为准。
