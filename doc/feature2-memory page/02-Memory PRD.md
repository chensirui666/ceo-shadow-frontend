## 1. 背景与目标

### 1.1 背景

Friday 会先把来自已授权工作应用、用户上传资料和日常工作对话的信息存入**上下文**；再从已有上下文中提取适合长期保留、能够帮助分身理解用户工作方式的信息，形成**用户 Memory**。若用户无法看见这两层的区别，Memory 就会变成不可理解的黑盒。

Memory 的首期目标不是做资料库、搜索引擎或知识图谱编辑器，而是用一张清晰的关系地图回答：**Friday 正在依据哪些来源形成工作记忆。**

### 1.2 用户目标

用户进入 Memory 时应能完成四件事：

1. 看见工作信息先进入上下文、再沉淀为用户 Memory 的关系；
2. 分别查看上下文与用户 Memory 的整体关系；
3. 按来源或关键词定位某类记忆；
4. 主动补充资料，并知道它何时成功加入地图。


## 2. 本期范围与边界

### 2.1 P0 范围

| 能力 | P0 决策 |
| --- | --- |
| Memory 地图 | 作为页面主体，展示节点与边的整体关系。 |
| 记忆层切换 | 在 `上下文` 与 `用户 Memory` 间切换，明确两层的职责。 |
| 来源筛选 | 仅按来源筛选，并同时收缩节点与边。 |
| 搜索 | 在当前记忆层内按关键词定位节点与关系。 |
| 颜色系统 | 使用稳定的低饱和莫兰迪色区分来源，避免单一色调。 |
| 上传文件 | 作为 `添加资料` 的第一项入口。 |
| 数据迁移 | 作为 `添加资料` 的第二项入口；固定为“复制整理 Prompt → 上传 Markdown”两步。 |
| 处理反馈 | 覆盖空、处理中、完成、失败和筛选无结果状态。 |
| 原型数据 | 前端先用与未来数据形态一致的 Mock 场景还原完整体验。 |

### 2.2 明确不做

1. 不提供节点点击、节点详情、右侧详情栏、节点编辑或节点删除。
2. 不将“历史数据迁移”作为独立的 Memory 来源类别。
3. 不提供 ChatGPT 迁移入口，也不在页面展示 Codex、Claude Code 等工具名称。
4. 不展示原始文件、消息原文、对话原文、构建日志、算法过程或技术字段。
5. 不做时间、节点类型或多选组合筛选；P0 保留来源筛选与关键词搜索。
6. 不做资料库、上传记录列表、来源管理后台、导出或全量删除。
7. 不将 Memory 设计成与 Friday 的日常聊天入口；用户不能在本页直接与 Friday 对话。

## 3. 记忆层与来源语义

### 3.1 两层记忆

| 记忆层 | 它是什么 | 用户在地图中看到什么 |
| --- | --- | --- |
| `上下文` | 所有刚被 Friday 接收到、读取到或由用户补充的工作信息。它是提炼用户 Memory 的候选材料。 | 当前上下文节点及其关系。 |
| `用户` | Friday 从上下文中提取出的、适合长期用于理解用户工作方式的信息。 | 已沉淀的用户 Memory 节点及其关系。 |

用户先看到 `上下文`；切换到 `用户` 后，查看的是从上下文中提炼出的用户 Memory。两层均以地图呈现，但不能混为一个“所有内容都永久记住”的黑盒。

### 3.2 来源

来源是用户可理解的工作信息类型，而不是后端处理路径。

| 来源 | 含义 | 颜色 | 是否在来源筛选中出现 |
| --- | --- | --- | --- |
| 钉钉 | 来自用户已授权钉钉工作消息与资料的工作信息。 | 鼠尾草绿 | 是 |
| 飞书 | 来自用户已授权飞书工作消息与资料的工作信息。 | 雾蓝 | 是 |
| Teams | 来自用户已授权 Teams 工作消息与资料的工作信息。 | 灰紫 | 是 |
| 文件 | 用户主动上传的工作资料。 | 柔和赭黄 | 是 |
| 对话 | 分身在日常接收消息、生成回复时沉淀的工作信息；通过数据迁移导入的 Markdown 也归入此类。 | 豆沙粉 | 是 |

`数据迁移` 是一种补充资料的方式，不是地图上的第六类来源。它完成后，内容以 `对话` 来源呈现。

## 4. 页面信息架构

```text
Memory
所有工作信息先进入上下文，再沉淀为用户 Memory。

[ 上下文 ] [ 用户 ] [ 来源：全部来源 v ] [ 搜索 Memory ] [ 添加资料 v ]

┌───────────────────────────────────────────────────────────────────────┐
│                                                                       │
│                        当前记忆层的关系地图                            │
│                  节点与边由 Friday 的记忆结果构成                      │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### 4.1 页面布局

- Memory 是主工作区页面，不使用 Settings 的居中设置浮层。
- 页面顶部保留标题、两层记忆切换、来源筛选、搜索和 `添加资料`；不放统计卡、资料列表或说明侧栏。标题与极短说明在上，标签和工具栏在下一行；工具栏左侧为记忆层标签，右侧依次为来源筛选、搜索和唯一主行动 `添加资料`。
- 关系地图占据页面主要注意力。节点与边是唯一主内容，避免让用户在多个模块间判断应看哪里。
- `添加资料` 是页面唯一主行动，使用下拉菜单承接两个低频操作。
- 页面遵循 Friday 的 Warm Editorial Workbench：暖白外层、白色工作区、细分隔线、克制的近黑文字。地图不使用渐变、拟物装饰、彩色统计图或技术监控面板。
- 来源提示不在地图底部单独排列为“图表图例”；它被整合进来源筛选控件或其紧邻的紧凑来源键中，以彩色圆点加来源文字表达。来源颜色不能是理解来源的唯一方式，筛选项始终保留文字。

### 4.2 关系地图

- 地图显示由 Friday 返回的节点与节点之间的关系；前端原型先使用同结构的 Mock 数据。
- 节点不支持点击、悬停详情、拖拽、编辑、删除或手动连线。
- 边只用于表达当前可见节点之间的关系。用户不需要理解边的类型、权重或算法含义。
- 不显示节点总数、关系数量、置信度、ID、创建时间、更新时间或来源明细；这些不是 Memory 首页的用户任务。
- 地图默认显示全部来源的上下文；用户切换记忆层、来源或搜索关键词后，地图只留下符合当前条件的节点，以及这些节点彼此之间的边。
- 关系地图必须呈现为一张互相渗透的个人记忆场，而不是五个按来源横向切开的色块。布局采用少量核心节点与大量卫星节点的非规则结构；不同来源可在局部成簇，但必须存在跨来源的连接。
- 节点颜色稳定对应来源：钉钉为鼠尾草绿、飞书为雾蓝、Teams 为灰紫、文件为柔和赭黄、对话为豆沙粉。颜色均为低饱和莫兰迪色；普通叶子节点使用更低饱和或更低不透明度，核心节点保留相对明确的来源色。边统一使用浅暖灰，且不抢占节点注意力。
- 节点层级通过尺寸、密度与连线数量建立，而不是用高饱和颜色或发光效果建立：少量核心节点可略大，卫星节点保持轻、小、疏密不均。地图不应有整齐网格、均匀间距或“示例数据”的规律排列。

### 4.3 视觉实现规则与本次迭代

本节是 Memory 页面前端与视觉设计的共同验收标准。目标是让地图读起来像一张持续生长的工作记忆网络，而不是传统后台中的分类图表。

#### 4.3.1 页面层级与控件布局

| 元素 | 实现规则 | 验收方式 |
| --- | --- | --- |
| 标题区 | 标题仅包含 `Memory` 与一行页面说明；标题区不放统计数字、状态卡或第二个行动按钮。`Memory` 可使用一处现代衬线字形表达产品气质，其余界面文字统一使用无衬线字体。 | 页面首屏只出现一个标题层级，用户一眼能找到地图。 |
| 工具栏 | 第二行固定为：左侧记忆层标签，右侧依次为来源筛选、搜索、`添加资料`。三个右侧控件视觉基线一致；`添加资料` 是唯一近黑实心主按钮，筛选和搜索均为低强调描边或浅底控件。 | 页面不出现并列的多个主按钮，也不出现独立的统计栏或说明栏。 |
| 标签 | `上下文` 与 `用户` 使用文字加细下划线表达当前状态；未选中标签只降低文字强调，不用颜色区分状态。 | 关闭颜色后仍能判断当前记忆层。 |
| 地图画布 | 地图直接延展在主工作区内，只保留工具栏下方的一条细分隔线；不再额外包一层有阴影、标题或边框的“图表卡片”。 | 首屏只有应用工作区与地图两个层级，不出现卡片套卡片。 |
| 来源提示 | 来源筛选器旁展示紧凑来源键，或在筛选下拉中展示来源键；每项必须同时包含彩色圆点与来源文字。页面底部不单独放图例。 | 不依赖颜色即可识别来源；地图底部没有独立 legend 行。 |

#### 4.3.2 地图编码与颜色 Token

**布局规则**

1. 地图必须是一张跨来源的关系网络：不同来源可局部聚簇，但至少存在跨来源连接；禁止将五类来源排列成五个彼此隔离的水平色团。
2. 节点按视觉层级分为三档：`核心节点`、`连接节点`、`叶子节点`。核心节点数量少、尺寸最大、连接最多；连接节点居中；叶子节点最小且占多数。节点层级只通过尺寸、连线数量和饱和度表达，不用发光、渐变或高饱和填充。
3. 节点的分布应不规则：局部允许疏密变化和卫星节点，禁止网格排列、等距分布或明显的 Mock 数据规律。
4. 连线统一使用低对比暖灰；普通边保持轻，不能与节点或标题竞争。筛选、搜索或记忆层切换后，只保留当前可见节点之间的边，不显示半透明“幽灵节点”或悬空边。

**颜色 Token**

| Token | 色值 | 使用范围 |
| --- | --- | --- |
| `memory-source-dingtalk` | `#82957D` | 钉钉核心或连接节点、来源键圆点。 |
| `memory-source-feishu` | `#839EB3` | 飞书核心或连接节点、来源键圆点。 |
| `memory-source-teams` | `#9990A8` | Teams 核心或连接节点、来源键圆点。 |
| `memory-source-file` | `#B59663` | 文件核心或连接节点、来源键圆点。 |
| `memory-source-conversation` | `#BC8D86` | 对话核心或连接节点、来源键圆点。 |
| `memory-edge` | `#D9D6CE` | 所有未被特别强调的关系边。 |
| `memory-node-muted` | 暖灰绿的低强调变体 | 大多数叶子节点；不再让每一个节点都使用完整来源色。 |

颜色只服务于来源识别：来源名称必须以文字出现在筛选器和来源键中；任何选中、禁用、失败或成功状态不能只通过节点颜色表达。实现时使用以上语义 Token，不在组件内散落硬编码色值。

#### 4.3.3 状态、反馈与动效

| 场景 | 视觉行为 | 约束 |
| --- | --- | --- |
| 切换记忆层 / 来源 / 搜索 | 在原地图区域内替换结果，保留工具栏位置与画布边界。 | 使用短暂淡入淡出或透明度过渡；不通过突然缩放、重排页面布局或整页刷新制造跳动。 |
| 搜索中 | 搜索框保持当前输入和清晰焦点；地图只显示匹配结果。 | 搜索控件有可见标签或可访问名称，不能只依赖占位文案。 |
| 处理中 | 既有地图保留，并显示页面内的整理提示。 | 不清空画布、不用无限转圈遮挡地图；等待较长时使用轻量骨架或进度提示。 |
| 成功 / 失败 | 成功与失败提示出现在触发操作附近或页面内固定状态区。 | 成功提示短暂出现；失败提示必须保留 `重试`，且说明“资料未加入 Memory”。 |
| 控件交互 | Tab、筛选、搜索、添加资料均有悬停、按下、键盘焦点与禁用状态。 | 状态变化只使用颜色、透明度或轻微阴影，不改变控件占位或挤压地图。 |

动效只用于解释“筛选后地图发生变化”或“新资料加入地图”这两件事。单次过渡保持轻、短、可中断；用户开启减少动态效果时，直接切换结果。

#### 4.3.4 可访问性与一致性

1. 正文、标签、筛选值和按钮文字与其背景保持足够文本对比度；来源色只用于点、节点与辅助提示，不用于浅色背景上的小字号正文。
2. 所有图标使用同一套线性图标语言；搜索、下拉箭头等图标需有文字、可访问名称或相邻标签，不能只靠图形猜测功能。
3. 关系地图本身不是可点击控件；它需要提供一句简短的可访问摘要，例如“正在显示上下文层，全部来源的 Memory 关系地图”，并随筛选状态更新。
4. 页面沿用 Friday 全局的间距、圆角、边框和阴影层级；本页不新增玻璃效果、渐变、拟物纹理、数据统计卡或仪表盘图表语言。


## 5. 功能需求

### 5.1 P0：记忆层切换

页面顶部使用文本标签切换 `上下文` 与 `用户`，默认选中 `上下文`。

| 标签 | 辅助说明 | 切换结果 |
| --- | --- | --- |
| `上下文` | `所有工作信息先在这里汇聚。` | 显示当前上下文地图。 |
| `用户` | `Friday 从上下文中沉淀出的长期工作理解。` | 显示用户 Memory 地图。 |

产品规则：

- 当前标签以文字和细下划线清晰标识，不能只依赖颜色。
- 切换标签只替换地图内容；来源筛选和搜索框保留当前输入，便于用户对比两层结果。
- 若某一层尚无可呈现内容，显示该层专属空状态，不将其误写成“系统没有记住任何信息”。

### 5.2 P0：来源筛选

筛选控件文案为 `来源：全部来源`。展开后按以下固定顺序展示：

`全部来源`、`钉钉`、`飞书`、`Teams`、`文件`、`对话`

产品规则：

- 默认值为 `全部来源`。
- 一次只选择一个来源，不支持多选、时间筛选或节点类型筛选。
- 筛选切换后，地图即时更新；用户不需要点击额外的“应用”按钮。
- 筛选影响节点和边：只显示所选来源的节点与它们之间的边，不保留与已隐藏节点相连的孤立边。
- 当前选项始终以文字保留在筛选控件内，用户可以一眼知道地图为何变化。

### 5.3 P0：搜索

搜索框占位文案为 `搜索当前 Memory`。它搜索当前记忆层中可用于定位的记忆标题和摘要，不展示原始消息或文件正文。

产品规则：

- 搜索与来源筛选共同生效：地图只保留同时符合当前记忆层、所选来源和关键词的节点与边。
- 输入关键词后即时更新地图，不需要额外提交按钮。
- 搜索没有匹配结果时显示 `没有找到相关的 Memory`，并提供 `清除搜索`。
- 清除搜索只清空关键词，不改变当前记忆层或来源筛选。

### 5.4 P0：添加资料

点击 `添加资料` 后，展示轻量下拉菜单，且只包含以下两项：

| 菜单项 | 说明 | 后续动作 |
| --- | --- | --- |
| `上传文件` | 添加一份用户主动选择的工作资料。 | 打开上传浮层。 |
| `数据迁移` | 将整理后的工作对话 Markdown 加入 Memory。 | 打开迁移浮层。 |

菜单不出现 `对话`、`历史记忆`、`连接应用`、`刷新地图` 或其他入口。

#### 5.4.1 上传文件

上传浮层内容：

```text
上传文件
添加一份工作资料，Friday 会在整理后将其加入 Memory。

[ 选择文件 ]

[ 取消 ] [ 开始添加 ]
```

产品规则：

- 用户选择文件后才能使用 `开始添加`。
- 提交后关闭浮层，回到地图并进入“正在整理”状态。
- 用户取消或关闭浮层时，不创建处理任务，也不改变当前地图。
- 上传文件成功后，新增内容按 `文件` 来源参与地图和来源筛选。

#### 5.4.2 数据迁移

数据迁移是固定的两步浮层，不要求用户选择外部工具，也不显示工具名称。

**第一步：复制整理 Prompt**

```text
数据迁移
先在你的对话工具中使用这段 Prompt，将工作相关内容整理成 Markdown。

请将当前工作中的对话整理为一份 Markdown 文档。
保留项目背景、已确认的决策、待办、工作偏好和关键结论；
移除个人生活及非工作内容；不要补充未出现的信息。

[ 复制 Prompt ]  [ 下一步 ]
```

`下一步` 不是外部工具跳转；它只进入 Markdown 上传步骤。用户可在复制前后任何时刻离开该浮层，不产生数据变更。

**第二步：上传 Markdown**

```text
上传 Markdown
将整理后的工作对话加入 Memory。

[ 选择 Markdown 文件 ]

[ 返回 ] [ 开始迁移 ]
```

产品规则：

- 只有选择 Markdown 文件后，`开始迁移` 才可操作。
- 用户完成迁移后，内容进入统一处理任务；成功后以 `对话` 来源加入地图。
- 迁移过程不展示对话原文、工具名称、历史数据数量或逐条清洗结果。
- 本期不支持 ChatGPT，也不需要用户在页面中区分 Codex 和 Claude Code。

### 5.5 P0：处理状态与用户反馈

页面以“资料处理任务”的状态驱动反馈。无论上传文件还是数据迁移，都使用同一套体验。

| 状态 | 页面表现 | 用户可做什么 |
| --- | --- | --- |
| 初始空状态 | 地图区域显示 `还没有可呈现的工作记忆`。 | 点击 `添加资料`。 |
| 处理中 | 保留原有地图，并在顶部显示 `正在整理新资料，完成后会加入 Memory。` | 继续查看地图或切换来源。 |
| 处理完成 | 显示短暂提示 `已加入 Memory`，地图平滑更新。 | 继续查看或筛选。 |
| 处理失败 | 显示 `这份资料暂时未能加入 Memory`。 | 点击 `重试`。 |
| 来源筛选无结果 | 地图区域显示 `这个来源还没有形成可呈现的 Memory`。 | 点击 `清除筛选`。 |
| 搜索无结果 | 地图区域显示 `没有找到相关的 Memory`。 | 点击 `清除搜索`。 |

产品规则：

- 失败不会清空既有地图，也不会让用户误以为资料已经加入。
- 地图只在处理完成后更新；处理中或失败时维持此前可用内容。
- 不显示“节点数增加”“已训练”“算法成功”或任何不可验证的结论。
- 加载、完成和失败都在 Memory 页面内反馈，避免用全局提示打断用户。

### 5.6 P0：前端原型的 Mock 原则

本阶段只实现前端时，Mock 的不是一段固定等待动画，而是未来用户能够感知的处理结果。

| 内部演示场景 | 用户看到的结果 |
| --- | --- |
| 空上下文 / 空用户 Memory | 对应层的专属空状态与 `添加资料`。 |
| 有可用地图 | 上下文或用户 Memory 地图，包含来源筛选与搜索。 |
| 上传/迁移处理中 | 保留当前地图，加上整理提示。 |
| 上传/迁移成功 | 提示完成，并显示预设的更新后地图。 |
| 上传/迁移失败 | 失败说明与 `重试`。 |
| 所选来源无内容 | 筛选无结果说明与清除操作。 |
| 搜索无匹配 | 搜索无结果说明与清除操作。 |

这些场景仅用于验证用户是否理解操作和结果。接入真实服务后，页面以真实处理结果替代预设场景，页面文案、状态和交互无需重新设计。

## 7. 隐私与可理解性规则

1. 只处理用户已授权应用中可读取的工作内容，以及用户主动上传或迁移的内容。
2. 上下文与用户 Memory 均以关系地图呈现，不展示工作消息、对话或文件的原文。
3. `对话` 来源仅说明信息来自分身的日常工作对话或用户迁移的整理结果；不暴露具体对话对象、内容或工具。
4. 数据迁移 Prompt 明确要求只保留工作内容、排除个人生活和非工作内容。
5. 任何情况下都不向用户承诺“所有资料永远只在本地”或“所有内容都会自动记住”。

## 8. 验收清单

### 页面与地图

- [ ] Memory 以关系地图为唯一主体，不出现资料列表、统计卡或节点详情。
- [ ] 节点和边不可点击、悬停、拖拽、编辑或删除。
- [ ] 页面清楚区分 `上下文` 与 `用户`；默认显示上下文。
- [ ] 默认显示全部来源；切换来源、记忆层或搜索关键词后，节点和边同步收缩。
- [ ] 节点颜色稳定对应五类来源，使用低饱和莫兰迪色；边不抢占节点注意力。
- [ ] 地图呈现为一个跨来源互联的记忆场，不出现五个按来源整齐分割的色团、网格化布局或示例数据式规律排列。
- [ ] 核心与卫星节点在尺寸、密度和连接数量上具有清晰但克制的层级；不使用高饱和、大面积发光或技术监控视觉。
- [ ] 来源图例只在来源筛选器或其紧邻的紧凑来源键中出现，不在地图底部形成独立图表图例。
- [ ] 页面提供来源筛选与关键词搜索，不提供时间、类型或多选组合筛选。

### 添加资料

- [ ] `添加资料` 菜单只含 `上传文件`、`数据迁移`。
- [ ] 上传文件后，成功结果归入 `文件` 来源。
- [ ] 数据迁移严格是“复制整理 Prompt → 上传 Markdown”两步，不显示工具选择。
- [ ] 数据迁移成功结果归入 `对话` 来源。
- [ ] 页面不展示 ChatGPT、Codex、Claude Code 或“历史数据迁移”作为来源类别。

### 状态与原型

- [ ] 空、处理中、成功、失败、来源筛选无结果、搜索无结果均有明确用户语言与下一步。
- [ ] 地图只在成功后更新；失败或处理中保留既有内容。
- [ ] 前端原型可稳定演示各状态，普通用户界面不出现内部场景开关。
