## 用户已确认的落地方案

用户明确指出：此前贴回三组问题不是确认。原三组方案的批量确认记录无效，不能作为实现依据。后续每次仅提一个简短的决策问题。

当前明确的决策：

1. 暂不支持 PNG，格式保留 PDF、MD、Word。
2. 暂不做月报／每月执行，只做日报／周报。执行安排仅两个控件：星期多选，选中的每天执行；时间单选，00:00–23:30，每半小时一项，共 48 项。取消原每天／每周／每月频率选择方案。
3. 只实现 Routine，保留所需文件查看和 Library 跳转接口，不建设 Library 页面。
4. 发送为可选项：无收件人也可创建、保存日程；不以缺少目标阻止正式配置生效。无目标时不发送，正式生成文件的收录仍遵循 PRD。
5. 执行时间固定使用创建日程时的用户时区；之后设备时区变化不改变该日程的执行时区。
6. PDF 提供三款自设计样式：刊物（Edition）、简讯（Signal）、画册（Folio）。用户已确认最终正文排版样稿，见 `doc/design/routine-pdf-approved/three-styles.png`。以此为实际模板视觉依据；图片本身不是可用 PDF 模板。不采用 Quill 或早期被否定的方案。
7. 用户已确认使用明确标注的示例数据跑通前端操作：试运行展示示例周报、收件人选择展示示例对象、执行记录可演示。不会真实生成内容或发送消息；预留服务接口供后续接入。
8. 内容模板仅保留“每日工作总结”和“每周工作总结”，沿用 PRD 对应主题和 Prompt；不实现其他六种内容模板。此决定覆盖 PRD 的八种模板要求。
9. 新建日程默认每天 09:00：星期一至星期日全部选中，用户可自行修改星期和时间。
10. 默认名称为“早间简报”；重复添加使用数字后缀“早间简报 2、早间简报 3”等，名称可编辑。
11. 新建日程默认内容模板为“每日工作总结”，用户可切换为“每周工作总结”；切换内容模板不自动修改执行星期和时间。
12. 新建日程默认文件格式为 PDF，用户可改为 MD 或 Word。
13. 默认 PDF 样式为第一款“刊物”，可在 Template 中切换“简讯”和“画册”。
14. 点击详情页标题直接编辑日程名称。
15. 从 PDF 切为 MD 或 Word 时保留原 PDF 样式，切回 PDF 后恢复。

16. 取消独立 Prompt 确认按钮；Add 更新 Prompt，直接编辑 Prompt 后在保存时重新总结主题，下次进入显示新主题。
17. 试运行只展示预览，不加入 Recent Sessions。
18. Add 和保存是独立操作；没点 Add 的主题输入不属于配置修改，保存忽略该输入，不自动添加、不阻止保存。
19. 删除前弹窗确认，确认后才删除。
20. UI 使用 HeroUI 组件；表单、下拉、勾选、Tab、弹窗、折叠区与按钮复用组件库，不自行实现基础控件。
21. 星期使用多选下拉框，框内显示已选星期；展开后选中项打勾，未选项不打勾。

PRD 已明确的行为按 PRD 执行；其他标注建议的待定规则不能据原批量记录视为已定案。
