# Message 信息驱动工作流设计

| 字段 | 决策 |
| --- | --- |
| 日期 | 2026-08-12 |

| 一级导航 | `Message · Task · Memory · Feedback · Settings` |

## 1. 产品决策

Friday 是一个人的工作分身：它接收与这个人有关的外部工作信息，并在预设授权边界内，尽可能在原渠道替这个人把事情完成。

产品以 **Message** 为中心，不是仪表盘、聊天客户端或项目管理工具。现有 Home 后续改为 `Message`；现有 Projects 后续改为 `Task`。

## 2. 核心对象

### Message

Message 是触发 Friday 工作的一条外部工作事件。它保存原始触发内容、来源、当前状态、关联 Task、处理结果和最终成果物。

Message 不是整段聊天、整场会议或整份文档的副本；它是由这次触发事件建立的一份工作案卷。

### Task

Task 是 Friday 无法代替本人完成、因此交回本人处理的一步。它不是通用待办清单，Friday 也不能替本人凭空向其他人新增承诺或派活。

Task 只会因以下三种原因建立：

1. 本人需要补充材料或事实；
2. 本人需要做 Friday 无法安全推断的实质判断；
3. 本人需要完成必须亲自或线下完成的行动。

每个 Task 必须说明：它来自哪条 Message、本人要做什么、Friday 为什么做不了、完成后 Friday 会继续做什么。

### 成果物

成果物是已经完成的工作，例如回复、文档、审批意见或发到原渠道的结果。成果物不是 Task。

### Memory

Memory 继续保存可复用的长期工作知识和材料。Message 不复制 Memory，也不保存整段上下文；它的审计记录本次处理使用了哪些 Memory／材料、何时使用，并可回跳到这些来源。

## 3. Message 进入规则

只有以下外部事件会创建 Message：

| 来源 | 创建条件 |
| --- | --- |
| 聊天 | 有人明确 @ 本人。 |
| 会议 | 本人参会，且会议已结束并已获得会议内容。 |
| 审批 | 当前轮到本人审批。 |
| 文档 | 有人在文档中明确 @ 本人。 |

Friday 可以读取完成工作所需的最小上下文或相关 Memory，但这些上下文不会另建 Message，也不会完整复制进 Message。

## 4. 生命周期

用户可见状态保持简单：

```text
待处理 → 处理中 → 已处理
                  → 已跳过
                  → 待确认 → 已处理 / 已跳过
                  → 跟进中 → 已处理
                  → 处理失败
```

| 状态 | 含义 |
| --- | --- |
| 待处理 | Friday 已接收外部触发，但尚未开始工作。 |
| 处理中 | Friday 正在首次理解请求、读取授权范围内的上下文并尝试完成工作。 |
| 已处理 | 工作已闭环：Friday 或本人已完成所需动作，结果已记录或已交付到原渠道。 |
| 已跳过 | 无需动作，或本人选择不让 Friday 继续处理；必须保留原因。 |
| 待确认 | Friday 已准备好结果，但还差一次明确授权才能行动。 |
| 跟进中 | 一个或多个关联 Task 尚未完成。 |
| 处理失败 | 因连接、权限或执行异常，Friday 无法完成原本可处理的动作，且无法自动恢复。 |

`处理中`只表示首次处理，不会在每一次人工操作后反复展示。本人确认或所有关联 Task 完成后，Friday 在后台继续工作，Message 直接收敛为`已处理`；只有新的信息真的带来一次必须确认的授权，才进入`待确认`。

一条 Message 可以关联多个 Task 和多个成果物。任一 Task 未完成时，Message 为`跟进中`；若同时存在待确认事项，主状态优先显示`待确认`，并把剩余 Task 数量作为次要进度展示。

## 5. 直接完成、确认与 Task 交接

### 直接完成

若 Friday 能按预设授权规则闭环，它直接产出成果物，并在原群、审批或文档中完成，不创建 Task，也不要求确认。

### 待确认

`待确认`表示成果已经准备好，只差一次授权，例如代表本人发送一条已准备好的回复。它不是 Task。

Friday 给本人发送一条钉钉提醒，内容必须包括：

- 来自哪个群、会议、审批或文档；
- 对方具体要求；
- Friday 已准备的结果或建议；
- 为什么必须本人确认；
- 确认、交给我处理、直接输入文字回复等操作。

在钉钉或 Friday 内确认，都会更新同一条 Message。确认后为`已处理`；选择“交给我处理”后，Friday 停止处理，Message 为`已跳过`。

### Task 交接

建立 Task 后，Message 变为`跟进中`。Friday 同样给本人发送简短钉钉提醒，但明确要求补充材料、作出判断或完成个人行动。

- 提交所需材料或判断，自动完成该 Task；
- 本人／线下行动由本人标记完成，并可补充一句结果；
- Friday 使用新输入继续完成原始工作并关闭 Message；除非真的出现新的待确认事项。

## 6. 注意力与通知规则

Friday 只在需要本人介入时占用注意力。

| 事件 | 是否给本人发钉钉提醒 |
| --- | --- |
| Message 已直接处理或已跳过 | 不单独提醒；结果已经在原渠道和 Message 记录中。 |
| 进入待确认 | 立即提醒。 |
| 新建或更新 Task | 立即提醒。 |
| 处理失败 | 仅在自动恢复失败且本人能够采取行动时提醒。 |

Friday 发给本人的钉钉消息只是原 Message 的通知和操作入口，绝不能创建新的 Message，也不能形成自我触发的回复循环。

## 7. 审计要求

每条 Message 必须以用户可读方式提供：

1. 原始外部触发内容和来源；
2. 状态历史，以及跳过、待确认、Task 或失败的原因；
3. 关联 Task、完成输入和处理责任人；
4. 成果物，以及外部动作是否已发出、已保存或未发送；
5. 本次决策使用的 Memory 和材料引用，而非重复存储其内容；
6. 本人确认或交接记录，以及操作发生在哪个渠道。

审计页不暴露原始 Prompt、模型过程、数据库标识符，也不完整复制与本次工作无关的聊天、会议或文档内容。

## 8. 预设授权边界

第一版使用 Friday 预设的判断规则，决定直接完成、待确认或 Task 交接。用户暂时不能在 Settings 中配置这条规则。未来可以提供“Friday 可以替我直接处理什么”的设置，但它明确不在本期范围内。

## 9. 范围与非目标

本设计只定义工作模型和行为，不定义具体页面布局、列表筛选、桌宠界面、连接器实现或用户可编辑的授权 Prompt。

Friday 也不替代钉钉：原应用仍是接收信息和完成工作的地方。Friday 只用最小的控制入口请求本人注意。

## 10. 后续实现验收

1. 群聊中未 @ 本人的消息、尚未结束的会议、未轮到本人的审批、未 @ 本人的文档均不会创建 Message。
2. 合格触发只创建一条包含原始触发内容的 Message，不复制完整上下文。
3. 可直接解决的 Message 到达`已处理`，有可追溯成果物且不创建 Task。
4. 需要授权的已准备结果进入`待确认`；钉钉或 Friday 内确认都关闭同一条 Message，不产生新 Message。
5. 缺材料、实质判断或个人行动建立 Task，且在所有关联 Task 完成前保持`跟进中`。
6. 多个 Task 保持同一条来源 Message；若同时待确认，待确认优先显示。
7. 直接完成和跳过不发无意义提醒；待确认、Task 和不可恢复的失败才提醒本人。
8. 审计可追溯使用过的 Memory／材料、处理结果和授权记录，同时不重复存储无关内容。
