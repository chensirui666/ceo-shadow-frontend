## 1. 一句话定义

**Contacts 是 Friday 按用户规则自动维护的人物档案：它让 Agent 理解“这是谁、与我有什么客观关系、通常如何沟通、有哪些业务标签”，而不是复制全部 Connector 通讯录。**

## 2. 背景、目标与原则

来自不同 Connector 的人和互动分散在私聊、邮件及群聊中。若这些资料只进入不可见的 Memory，用户无法核验 Friday 对某个人的理解，也无法修正联系人名称、关系描述或来源范围。

本期目标是让 Friday 按用户设置的规则自动纳入符合条件的人。联系人档案应把人物与用户的关系说清楚，并显示 Friday 读取过的 Connector 身份。

产品遵循四条原则：

1. **关系先于通讯录。** 只有能说清“此人为什么与用户有关”的人，才进入 Contacts。
2. **规则可见、可编辑。** 默认纳入规则公开展示在 Settings；用户以自然语言编辑后，由 Agent 解释并影响后续自动纳入。
3. **客观、可核验。** 档案只描述观察到的身份、互动和沟通方式；标签归属必须能回溯到用户定义的自然语言规则和允许读取的资料，不定义人格判断。
4. **来源可管理。** 同一个人在不同 Connector 的身份归属同一联系人档案，并逐项向用户展示和管理。

## 3. 本期范围与非目标

### 3.1 本期交付

- 联系人列表与个人档案；
- 按 Contacts 纳入规则自动维护联系人；
- 一个 Contact 可关联多个 Source identity；
- 在 Settings 编辑 Contacts 纳入规则；
- 联系人名称只读；关系描述、分类、来源身份和用户补充 Context 的编辑；
- 公司名称、最近状态与联系人 Tag 展示；
- 用户创建、管理和删除全局 Tag；一个 Contact 可关联多个 Tag；
- Agent 根据用户给出的 Tag 自然语言规则找出匹配联系人并自动打标；
- 单人档案的 Agent 更新；
- 将联系人加入全局黑名单，或邀请联系人加入当前 Friday 团队；
- Agent 在处理与该联系人有关的工作时使用该档案作为人物上下文。

### 3.2 明确不做

- 全量企业通讯录、泛群成员、客户群或项目群成员导入；
- 关系目标、P0–P3 重要度和关系网优先视图；
- 通过外部 Connector 邀请联系人、联系人 Status；
- 跨 Connector 身份的自动识别、合并或匹配算法；
- 展示完整原始私聊、完整邮件、完整群聊、Prompt、模型推理或内部技术日志。

## 4. 联系人准入与资料范围

### 4.1 准入条件

默认情况下，所有已连接 Connector 中满足以下**任一项**的人由 Friday 自动纳入 Contacts：

1. 用户与此人至少有 3 条私聊；
2. 此人直接给用户发过个人邮件；
3. 此人在群内直接 @ 过用户。

仅在企业通讯录中存在、仅同处泛群、只在正文中被提及、邮件订阅或通知账号，均不进入默认 Contacts。用户可在 Settings 以自然语言编辑 `Contacts 纳入规则`，由 Agent 解释并应用于后续自动纳入。用户将联系人加入黑名单后，该联系人即使仍满足规则也不得再次自动纳入或参与 Agent 后续处理。

### 4.2 用于形成档案的资料

除公司名称外，Agent 只可使用以下三类资料形成 Contacts 与个人档案：

1. 用户与此人的私聊信息；
2. 此人在群内 @ 用户的消息；
3. 此人发送给用户的个人邮件。

这三类资料支持“最近互动”“Relationship”“Context”“最近状态”和 Tag 归属的生成；Contacts 不因此成为原始消息浏览器。公司名称可从 Friday 当前有权限查询的全部资料中提取；无法确认时显示 `-`。

## 5. 页面与关键流程

### 5.1 联系人列表

Contacts 默认页是联系人列表，按**最近互动时间倒序**排列。页面标题下固定展示以下说明：

> Your assistant builds a working profile of the people you interact with, drawn from your conversations and background research.

这句用户文案不扩大本期读取边界；`background research` 仅指对第 4.2 节已授权资料的背景整理。

列表展示以下信息：

| 名称 | 最近状态 | 公司 | Tag | 信息来源 | 最近联系 |
| --- | --- | --- | --- | --- | --- |
| 头像、姓名及简短关系描述 | 近期项目推进或需跟进情况 | 联系人当前所属公司 | 可由用户管理的彩色标签 | 应用图标及该应用中的身份名称；完整内容可悬浮查看 | 最近互动日期 |

同一列表视口中，所有 Tag 使用一致的展示宽度；名称过长时省略显示，但用户可查看完整 Tag 名称及其规则。颜色仅用于视觉区分，不承载优先级或排序语义。

行末保留 `···` 操作列。操作菜单包括：`编辑信息`、`加入黑名单`、`邀请进 Team`。

标题区右侧提供以下工具：

- `搜索联系人`：按当前联系人可见的名称、描述、公司、Tag 和信息来源查找；
- 搜索框旁的 `分类` 分段 Tab：`全部`、`领导`、`同事`、`下属`、`客户`、`其他`；选中项以填充色呈现；
- `最近联系` 列表头内的联系时间筛选：`当天`、`最近一周`、`最近一个月`、`最近三个月`；
- `来源` 列表头内的来源多选筛选：以 Connector 图标加应用名展示 `钉钉`、`飞书`、`Teams` 等当前数据来源；
- `Tag` 表头内的管理入口：创建 Tag、查看定义，以及删除 Tag；
- 唯一主操作 `获取联系人`：深色紧凑按钮，左侧带聊天图标，说明 Contacts 的自动纳入机制。

联系时间和来源筛选可同时生效；未设置时展示全部联系人。点击一行在当前页面右侧打开个人档案预览，列表保持可见。

### 5.2 获取联系人说明

1. 用户点击带聊天图标的 `获取联系人`，打开说明弹窗。
2. 弹窗说明 Friday 会自动维护符合当前纳入规则的联系人，并提示规则可在 Settings 编辑。
3. 弹窗提供 `取消` 和 `聊天试试` 两个操作。
4. 正式接入聊天后，`聊天试试` 直接跳到对话框继续收集或修改联系人信息；当前没有聊天框时，它与取消一致，直接关闭弹窗。

未连接任何 Connector 时，入口替换为 `去连接` 并打开 Settings。

### 5.3 右侧个人档案预览

个人档案在 Contacts 页的右侧栏打开，不跳转为全页详情，也不遮住联系人列表。右侧栏分为基础信息、人物文本和操作三部分。

**基础信息**

- 头像；
- 人名；
- 关系描述；
- 分类；
- 公司名称；
- Tag：一个 Contact 可关联多个 Tag；
- 信息来源：一个 Contact 可关联多个 Source identity，逐项显示 Connector 与该 Connector 中此人的名称。

**Tag 规则**

Tag 是面向用户的自定义分类，不承担 P0–P3 优先级语义。每个 Tag 包含名称与自然语言规则，并分配一种颜色以便快速识别。一个 Tag 可归属多位联系人，一位联系人也可同时拥有多个 Tag。

用户可直接创建 Tag 并将其关联到联系人；也可在与 Agent 的对话中说明“哪些人满足这个 Tag”。Agent 根据该规则和第 4.2 节允许使用的资料，在当前 Contacts 中找出匹配者并打标。资料不足时 Agent 必须说明无法确认，不能凭空添加 Tag。黑名单联系人不得参与匹配或打标。

**人物文本**

基础信息之下是一篇连续、可阅读的人物文本，不拆成卡片、栅格或彼此割裂的内容区。文本自然包含以下事实：此人的一句话描述、最近多次互动（含时间、Connector 和可读摘要）、用户与此人的具体 Relationship，以及从互动中观察到的沟通 Context。

Context 只总结正式程度、回复节奏、是否常含行动项等可观察模式；资料不足时文本明确写“暂无足够互动判断沟通方式”。信息来源完全归属于基础信息，不在人物文本中重复切分展示。

### 5.4 单人操作

| 操作 | 结果 |
| --- | --- |
| `更新 Profile` | 由 Agent 重新读取此人允许使用的资料，更新一句话描述、Recent contacts、Relationship、Context、公司和最近状态；不借此新增其他联系人。 |
| `编辑信息` | 打开编辑栏，联系人姓名不可编辑；用户可编辑关系描述、分类、信息来源、Tag 及 `Additional context or instructions`。 |
| 移除来源身份 | 被移除的 Connector 身份不再用于该联系人的后续读取和更新；既有档案内容保留。 |
| 移除联系人 Tag | 在列表行内移除，仅移除该联系人的该 Tag，不影响其他联系人或 Tag 定义。 |
| 删除 Tag 定义 | 由 Tag 表头管理入口触发；确认提示必须明确说明“所有已打上该 Tag 的联系人都会失去该 Tag”。确认后删除定义及全部关联。 |
| `加入黑名单` | 由列表行末菜单触发；二次确认后，联系人从 Contacts 列表移除，且不再参与 Contacts 建模、档案更新与 Agent 后续处理。 |
| `邀请进 Team` | 由列表行末菜单触发，邀请该联系人加入当前 Friday 团队；不通过外部 Connector 发送邀请。 |

`Additional context or instructions` 是可选的多行自由文本。输入框说明为：`Optional — passed to your assistant when refreshing their people document`。用户保存后，原文同步到该联系人的 Context prompt，作为用户主动补充的 Context；它不被伪装为 Friday 从互动中观察到的事实。

**黑名单管理**

黑名单在 Settings 的 Contacts 配置中集中管理。每项展示联系人姓名与来源身份；用户可将联系人移出黑名单以恢复后续处理资格。移出黑名单不自动重建或补全此前的联系人档案。

## 6. Agent 使用 Contacts 的边界

Contacts 是 Agent 的人物上下文，不是 Agent 的自主行动授权。

当 Agent 正在处理与某联系人有关的工作信息时，可使用该人的关系描述、公司、Tag、最近状态、近期互动、Relationship、观察到的 Context，以及用户写入 Context prompt 的补充内容，以便正确识别对象、理解已有关系并生成适合的沟通表达。黑名单联系人不得作为上述上下文参与 Contacts 建模、档案更新、Tag 匹配或 Agent 处理。Agent 不能把推断当成事实，不能因为关系档案而擅自发送、承诺，也不能向当前对话暴露其他 Connector 的原始私密内容。

## 7. 关键状态与文案

| 场景 | 用户可见内容 |
| --- | --- |
| Contacts 为空 | 解释 Contacts 用于管理 Friday 自动纳入的人物关系，并提供带聊天图标的 `获取联系人`。 |
| 获取说明弹窗 | `Friday 会自动维护符合纳入规则的联系人。你可以在设置中编辑这些规则。` |
| Settings | 在 `Friday 如何为你工作` 下提供可保存的 `Contacts 纳入规则`和黑名单；默认规则包含 3 条私聊／个人邮件／群内直接 @ 三项；用户可用自然语言修改，交由 Agent 解释。 |
| Context 资料不足 | `暂无足够互动判断沟通方式。` |

## 8. 验收标准

1. Contacts 默认按最近互动时间倒序；标题下展示规定的英文说明，列表显示名称与关系描述、最近状态、公司、Tag、来源、最近联系及常驻行末操作菜单。
2. 默认 Contacts 规则为“至少 3 条私聊／直接个人邮件／群内直接 @ 用户”；Settings 中可用自然语言编辑并保存规则，由 Agent 解释后应用。
3. Friday 自动维护符合当前规则的联系人；加入黑名单的联系人不得再次自动纳入，也不参与后续 Contacts 建模、档案更新或 Agent 处理。页面没有候选预览、确认纳入、手动命令或发送步骤。
4. `获取联系人` 弹窗解释自动机制；`聊天试试` 在未接入聊天前关闭弹窗，接入后跳转到聊天框。
5. 每位联系人均可在不离开列表的情况下打开右侧个人档案预览；档案显示头像、人名、关系描述、分类、公司、Tag，以及一个 Contact 关联的多个可核验 Source identity。公司名称从当前有权限查询的资料中无法确认时显示 `-`。
6. 档案的人物文本连续呈现一句话描述、最近多次互动、Relationship 和 Context；Context 资料不足时不编造判断，信息来源不在正文中重复成独立内容区。
7. 联系人姓名不可编辑；用户可编辑关系描述、分类、信息来源、Tag 和 Additional context or instructions。保存的补充文本会同步到该联系人的 Context prompt，并与观察事实明显区分。移除某来源身份后，该身份不再参与未来读取和更新，既有内容不会被删除。
8. 用户可创建包含名称和自然语言规则的 Tag，并将其关联到一个或多个联系人。Agent 接到 Tag 条件后，只能基于允许资料为符合规则的非黑名单联系人自动打标；资料不足时必须明确无法确认。
9. 在列表行内移除 Tag 只影响当前联系人；在 Tag 表头管理入口删除 Tag 前，必须明确提示将从所有联系人移除，确认后同时删除 Tag 定义与全部关联。
10. 同一列表视口中的 Tag 展示宽度一致；长名称可省略，但完整名称与规则仍可查看，且 Tag 颜色不表达优先级。
11. `更新 Profile` 只更新当前联系人的档案内容，不新增联系人；它会更新人物文本、公司和最近状态。
12. 搜索可按名称、描述、公司、Tag 和来源工作；来源、最近联系与分类筛选可同时生效，且来源和最近联系筛选位于对应表头中。
13. 行末操作可编辑、加入黑名单，或邀请其进入当前 Friday 团队；加入黑名单必须二次确认并立即从列表移除。Settings 集中展示黑名单人员与其来源身份，并支持移出黑名单；Team 邀请不经外部 Connector 发送。
14. 不出现客户群导入、全量通讯录、P0–P3 重要度、期望关系、外部 Connector 邀请或关系网。
15. Agent 使用联系人档案改善对人的理解和表达，但不获得额外外发权限，也不展示跨来源原始私密内容。

## 9. 后续迭代

后续可单独讨论客户／项目群场景、真实 Connector 同步、聊天框跳转和更丰富的关系视图。本期不预先承诺这些能力。
