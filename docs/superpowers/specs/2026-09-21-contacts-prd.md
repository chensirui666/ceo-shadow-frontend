## 1. 一句话定义

**Contacts 是 Friday 中一份由用户主动发起、经确认后建立的人物档案：它让 Agent 理解“这是谁、与我有什么客观关系、通常如何沟通”，而不是复制全部 Connector 通讯录。**

## 2. 背景、目标与原则

来自不同 Connector 的人和互动分散在私聊、邮件及群聊中。若这些资料只进入不可见的 Memory，用户无法核验 Friday 对某个人的理解，也无法修正联系人名称、关系描述或来源范围。

本期目标是让用户通过一次明确的 Agent 任务，发现符合严格条件的人、先查看结果、确认后将其纳入联系人列表。联系人档案应把人物与用户的关系说清楚，并显示 Friday 读取过的 Connector 身份。

产品遵循四条原则：

1. **关系先于通讯录。** 只有能说清“此人为什么与用户有关”的人，才进入 Contacts。
2. **先预览，后写入。** Agent 返回候选表格后，只有用户确认，联系人才能出现。
3. **客观、可核验。** 档案只描述观察到的身份、互动和沟通方式；不定义期望关系、主观优先级或人格判断。
4. **来源可管理。** 同一个人在不同 Connector 的身份归属同一联系人档案，并逐项向用户展示和管理。

## 3. 本期范围与非目标

### 3.1 本期交付

- 联系人列表与个人档案；
- 从已连接 Connector 中通过 Agent 获取联系人；
- 候选结果预览和显式确认纳入；
- 联系人名称、关系描述、来源身份和用户补充 Context 的编辑；
- 单人档案的 Agent 更新；
- 删除联系人，或邀请联系人加入当前 Friday 团队；
- Agent 在处理与该联系人有关的工作时使用该档案作为人物上下文。

### 3.2 明确不做

- 全量企业通讯录、泛群成员、客户群或项目群成员导入；
- 固定联系人分类、关系目标、人工优先级和关系网优先视图；
- 通过外部 Connector 邀请联系人、联系人 Status；
- 自动或定期扫描、后台持续更新联系人；
- 在本期规定跨 Connector 同一人的识别、合并或匹配逻辑；
- 展示完整原始私聊、完整邮件、完整群聊、Prompt、模型推理或内部技术日志。

## 4. 联系人准入与资料范围

### 4.1 准入条件

所有已连接 Connector 中的人员都可以成为候选人，但只有满足以下**任一项**的人可由 Agent 返回并纳入 Contacts：

1. 用户与此人至少有 3 条私聊；
2. 此人直接给用户发过个人邮件；
3. 此人在群内直接 @ 过用户。

仅在企业通讯录中存在、仅同处泛群、只在正文中被提及、邮件订阅或通知账号，均不进入本期 Contacts。

### 4.2 用于形成档案的资料

Agent 只可使用以下三类资料形成候选人与个人档案：

1. 用户与此人的私聊信息；
2. 此人在群内 @ 用户的消息；
3. 此人发送给用户的个人邮件。

这三类资料支持“最近互动”“Relationship”和“Context”的生成；Contacts 不因此成为原始消息浏览器。

## 5. 页面与关键流程

### 5.1 联系人列表

Contacts 默认页是联系人列表，按**最近互动时间倒序**排列。页面标题下固定展示以下说明：

> Your assistant builds a working profile of the people you interact with, drawn from your conversations and background research.

这句用户文案不扩大本期读取边界；`background research` 仅指对第 4.2 节已授权资料的背景整理。

列表的三项主信息为：

| 名称 | 描述 | 信息来源 |
| --- | --- | --- |
| 头像与姓名 | 用户可编辑的简短关系描述，例如“Stardust AI 的同事” | 每个 Connector 的名称及此人在该 Connector 中的名称，供用户核验 |

行末保留 `···` 操作入口，不作为第四项信息列。操作菜单包括：`编辑信息`、`删除联系人`、`邀请进 Team`。

标题区右侧提供以下工具：

- `搜索联系人`：按当前联系人可见的名称、描述和信息来源查找；
- `联系时间` 筛选：`当天`、`最近一周`、`最近一个月`、`最近三个月`；
- `来源` 筛选：以 Connector 图标加应用名展示 `钉钉`、`飞书`、`Teams` 等当前已连接来源；
- 唯一主操作 `获取联系人`：深色紧凑按钮，左侧带聊天图标，沿用产品中“聊天图标 + 文案”的按钮语言。

联系时间和来源筛选可同时生效；未设置时展示全部联系人。点击一行在当前页面右侧打开个人档案预览，列表保持可见。

### 5.2 获取联系人

1. 用户点击带聊天图标的 `获取联系人`，打开说明弹窗。
2. 弹窗说明：Friday 可从已连接 Connector 中的私聊、发给用户的个人邮件及群内 @ 用户消息，获取用户与联系人的关系。
3. 弹窗提供 `取消` 和 `聊天试试` 两个操作。
4. 用户点击 `聊天试试` 后进入空态 Agent 对话；输入框预填下列指令，并在“如下已连接 Connector”后以用户可见名称列出当前可用 Connector：

   ```text
   /获取联系人 请从如下已连接 Connector 中寻找到满足任一条件的人：
   1. 与用户有至少 3 条私聊；
   2. 此人直接给用户发过个人邮件；
   3. 此人在群内直接 @ 过用户。
   ```

5. 用户点击发送后，Agent 汇总候选人并返回表格：`名称｜一句话描述｜信息来源`。
6. 表格下提供 `确认纳入`。点击前不创建联系人；点击后，表中全部候选人出现在 Contacts 列表。
7. 若没有候选人，Agent 明确说明未找到符合本期条件的人，不创建空联系人。

未连接任何 Connector 时，不进入 Agent 获取流程，入口替换为 `去连接`。

### 5.3 右侧个人档案预览

个人档案在 Contacts 页的右侧栏打开，不跳转为全页详情，也不遮住联系人列表。右侧栏分为基础信息、人物文本和操作三部分。

**基础信息**

- 头像；
- 人名；
- 关系描述；
- 信息来源：逐项显示 Connector 与该 Connector 中此人的名称。一个人在多个 Connector 的身份应归入同一个联系人档案。

**人物文本**

基础信息之下是一篇连续、可阅读的人物文本，不拆成卡片、栅格或彼此割裂的内容区。文本自然包含以下事实：此人的一句话描述、最近多次互动（含时间、Connector 和可读摘要）、用户与此人的具体 Relationship，以及从互动中观察到的沟通 Context。

Context 只总结正式程度、回复节奏、是否常含行动项等可观察模式；资料不足时文本明确写“暂无足够互动判断沟通方式”。信息来源完全归属于基础信息，不在人物文本中重复切分展示。

### 5.4 单人操作

| 操作 | 结果 |
| --- | --- |
| `更新 Profile` | 由 Agent 重新读取此人允许使用的资料，更新一句话描述、Recent contacts、Relationship 和 Context；不借此新增其他联系人。 |
| `编辑信息` | 打开编辑栏，用户可编辑人名、关系描述、信息来源及 `Additional context or instructions`。 |
| 移除来源身份 | 被移除的 Connector 身份不再用于该联系人的后续读取和更新；既有档案内容保留。 |
| `删除联系人` | 由列表行末菜单触发，二次确认后从 Contacts 移除该联系人。 |
| `邀请进 Team` | 由列表行末菜单触发，邀请该联系人加入当前 Friday 团队；不通过外部 Connector 发送邀请。 |

`Additional context or instructions` 是可选的多行自由文本。输入框说明为：`Optional — passed to your assistant when refreshing their people document`。用户保存后，原文同步到该联系人的 Context prompt，作为用户主动补充的 Context；它不被伪装为 Friday 从互动中观察到的事实。

## 6. Agent 使用 Contacts 的边界

Contacts 是 Agent 的人物上下文，不是 Agent 的自主行动授权。

当 Agent 正在处理与某联系人有关的工作信息时，可使用该人的关系描述、近期互动、Relationship、观察到的 Context，以及用户写入 Context prompt 的补充内容，以便正确识别对象、理解已有关系并生成适合的沟通表达。它不能把推断当成事实，不能因为关系档案而擅自发送、承诺，也不能向当前对话暴露其他 Connector 的原始私密内容。

## 7. 关键状态与文案

| 场景 | 用户可见内容 |
| --- | --- |
| Contacts 为空 | 解释 Contacts 用于管理 Friday 已确认的人物关系，并提供带聊天图标的 `获取联系人`。 |
| 获取说明弹窗 | `Friday 会从你已连接的信息源中，查找与你有明确互动的联系人。你可先在对话中查看结果，确认后再加入 Contacts。` |
| 候选结果 | `找到以下符合条件的联系人。确认后，他们将加入 Contacts。` |
| 无候选人 | `没有找到符合当前条件的联系人。` |
| Context 资料不足 | `暂无足够互动判断沟通方式。` |

## 8. 验收标准

1. Contacts 默认按最近互动时间倒序；标题下展示规定的英文说明，列表显示名称、描述、信息来源三项主信息与行末操作菜单。
2. 只有满足“至少 3 条私聊 / 直接个人邮件 / 群内直接 @ 用户”任一条件的人，才能由本期 Agent 任务返回为候选人。
3. 用户未点击 `确认纳入` 前，候选人不会出现在 Contacts。
4. `确认纳入` 后，每位联系人均可在不离开列表的情况下打开右侧个人档案预览。
5. 每个联系人档案均显示头像、人名、关系描述，以及可核验的 Connector 身份名称；同一个人在不同 Connector 的身份集中在同一档案。
6. 档案的人物文本连续呈现一句话描述、最近多次互动、Relationship 和 Context；Context 资料不足时不编造判断，信息来源不在正文中重复成独立内容区。
7. 用户可编辑人名、关系描述、信息来源和 Additional context or instructions；保存的补充文本会同步到该联系人的 Context prompt，并与观察事实明显区分。移除某来源身份后，该身份不再参与未来读取和更新，既有内容不会被删除。
8. `更新 Profile` 只更新当前联系人的档案内容，不新增联系人。
9. 搜索可按名称、描述和来源工作；联系时间与来源筛选可同时生效，来源筛选以图标加应用名显示。
10. 行末操作可编辑、删除联系人，或邀请其进入当前 Friday 团队；删除必须二次确认，Team 邀请不经外部 Connector 发送。
11. 不出现客户群导入、全量通讯录、固定分类、优先级、期望关系、外部 Connector 邀请、Status、关系网或后台自动更新。
12. Agent 使用联系人档案改善对人的理解和表达，但不获得额外外发权限，也不展示跨来源原始私密内容。

## 9. 后续迭代

后续可单独讨论客户／项目群场景、增量更新、候选人逐个选择和更丰富的关系视图。本期不预先承诺这些能力。
