# Feedback 质量驾驶舱设计

**日期：** 2026-08-10
**状态：** 已确认，待实现规划

## 1. 目标与范围

Feedback 是 Friday 的回复质量驾驶舱。它让工作分身的拥有者先判断近期回复的质量和反馈收集是否足够，再通过具体问答了解问题所在。

当前纯前端版本以本地演示数据呈现以下两类反馈，并在标题下明确标注“本地演示数据”。接入后端后才替换为真实收集结果：

- **同事评价**：收件人对最终回复的点赞、点踩和评语。
- **我的审核**：拥有者对草稿或最终回复的“像我”或“需调整”及补充意见。

页面不做传统表格、逐行列表、人工规则编辑、人工学习审批或待办管理。

## 2. 用户可见页面

### 2.1 时间范围

页面右上角提供单选范围：`近 7 天`、`近 30 天`、`ALL`，默认 `近 7 天`。

- 近 7 天与近 30 天：趋势按日展示。
- ALL：汇总全部历史反馈，趋势按月聚合，避免图表过密。
- 收到反馈、好评率、需关注反馈、趋势、来源占比和卡片以反馈收集时间为准；覆盖率以同一范围内的回复发送时间为准。

### 2.2 页面层级

1. 标题 `Feedback` 与副标题 `来自同事评价和我的审核`。
2. 四项指标：收到反馈、反馈覆盖率、好评率、需关注反馈。
3. 质量趋势与反馈来源两个可视化区块。
4. 真实反馈卡片墙。

指标定义：

| 指标 | 定义 |
| --- | --- |
| 收到反馈 | 范围内收集到的反馈记录数。 |
| 反馈覆盖率 | 范围内已发送回复中，至少关联一条反馈的回复数 ÷ 已发送回复总数。 |
| 好评率 | 范围内正向反馈 ÷ 全部有效反馈；正向包括同事点赞和“像我”，负向包括同事点踩和“需调整”。 |
| 需关注反馈 | 范围内的负向反馈数。它是质量信号，不代表用户有待办。 |

质量趋势使用按时间堆叠的正向/负向反馈柱状图；反馈来源显示同事评价与我的审核的占比。两者都用于解释质量变化，不能单独暗示训练或学习已经完成。

### 2.3 反馈卡片墙

反馈以双列卡片墙呈现，不出现表格列或传统逐行列表。

- 排序：负向反馈优先，其余按反馈时间倒序。
- 当前范围内的演示卡片一次展示；不提供“加载更多”。
- 每张卡片显示：评价状态、来源、问题、最终回答、反馈原话、反馈时间和 `查看详情`。
- 来源必须清晰标识为 `同事评价` 或 `我的审核`，不能混为同一种评价。
- 负向卡片可用克制的暖色强调；正向卡片使用低饱和绿色。颜色不能是唯一的语义载体。

### 2.4 详情

点击卡片后在当前页面右侧展开详情，不跳转至 Home。

详情显示完整问题、当时最终回复、反馈原文、反馈来源、评分/审核结果与时间。如同一回复收到多条评价，详情按时间展示这些评价。

详情页没有 `标记已处理`、`查看关联回复`、编辑、重发或训练确认按钮。反馈详情已经包含解释该反馈所需的完整问答；若需要处理真实工作沟通，应在原渠道中完成，而不是在 Feedback 中制造含糊的“完成”状态。

## 3. 后台自学习边界

后端接入后，每条有效反馈在被服务端持久化并关联具体回复后，后台异步写入工作画像：正向反馈强化偏好，负向反馈补充行为约束。纯前端演示不模拟或声称这一过程已经发生。

- 学习在反馈收集后自动开始，不依赖用户打开页面或任何人工确认。
- 同一外部反馈重复投递时，服务端必须按稳定反馈 ID 幂等处理，避免重复写入工作画像。
- Feedback 前端绝不展示工作画像写入、学习队列、学习状态、重试或内部错误。
- 学习任务失败不得回滚或隐藏已收集反馈；后台负责可靠重试。
- `需关注反馈` 仅表示负向信号数量，与后台是否已学习无关。

## 4. 前端与服务边界

前端当前通过一个本地数据模块提供三个读取能力；接入后端时只替换这个模块：

1. 按时间范围读取 Dashboard 汇总和趋势。
2. 分页读取真实反馈卡片。
3. 读取某张卡片的完整详情。

服务返回的反馈记录至少关联回复 ID、来源、正负向结果、反馈原文、反馈时间、问题和最终回答。工作画像学习的内部状态不属于前端数据模型或接口返回。

当前演示数据必须明确标注，不伪装为实时收集结果；不展示读取失败或 Retry。接入真实后端后，再补充相应空态与失败模式。

## 5. 非目标

- 不做全公司满意度调研、催评分或反馈阻断机制。
- 不让用户手动选择哪些反馈写入工作画像。
- 不提供手动标签、主题聚类、人工规则编辑、批量处理或自定义仪表盘。
- 不在 Feedback 中编辑、撤回、重发或补救外部消息。
- 不暴露反馈链接、token、学习任务、模型、Prompt 或技术日志。

## 6. 验收与验证

- 范围切换会同步更新四项指标、趋势、来源占比和卡片内容；ALL 使用月趋势。
- 覆盖率按“至少一条反馈的唯一回复”计算，不会因同一回复收到多条评价而重复计数。
- 每张卡片与详情均能显示完整、可追溯的问答和反馈来源。
- 负向反馈优先显示，页面不出现“已处理”或其他无客观完成标准的状态。
- 同事评价和我的审核始终可区分；辅助文字与视觉状态共同表达正负向含义。
- 后台学习不可用或重试时，已经收集的反馈仍可在前端读取；页面不暴露该内部过程。
- 验证覆盖指标计算、范围筛选、卡片排序、详情展开、空状态和读取失败重试。
