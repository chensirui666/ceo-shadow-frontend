# Friday Message NPS 方案

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-08-20 |
| 状态 | 已确认，待实施规划 |
| 所属页面 | Message 页 |

## 1. 目标

用一次标准 NPS 评分判断用户是否认为 Friday 整体值得推荐，而不是评价某一条回复写得好不好。

首期只收集 0–10 分，不要求说明原因、不创建待办、不改变工作画像，也不和现有的 Message 点赞／点踩或 Feedback 质量驾驶舱混合。

## 2. 触发与展示

用户必须同时满足以下两个条件，才具备一次评分资格：

1. 自首次正式启用 Active 起已满 14 天；
2. Friday 已完成至少 3 条真实协助回复，且回复成果物均已确认外发，并分布在用户时区的至少 3 个不同自然日。

- Trial 草稿、待确认但未发送、处理失败、已跳过、本人手动处理，以及文档／审批等非回复成果物，都不计入资格。
- 后端在两个条件都满足时写入“待邀评”资格，但不在第三条回复外发时立即打断用户。
- 用户下次进入 Message 页并连续停留约 15 秒后，显示一张可关闭的轻量 NPS 浮层。它不绑定任何 Message，也不要求进入详情页；页面存在确认、重试等需用户处理的操作时不显示。
- 浮层文案为：`你有多大可能把 Friday 推荐给同事或朋友？`，提供 0–10 十一个可点击数字，并标记 `0 完全不会` 与 `10 非常可能`。
- 点击即保存；成功后显示“感谢你的评分”并停止后续邀评。首期不允许修改，也不做周期性再邀评。
- 用户关闭而未评分时，7 天后的下一次满足展示条件的 Message 会话再展示一次；第二次关闭后停止。
- 若具备资格后的 14 天内从未展示过站内浮层，则由服务端向登录邮箱发送一次评分链接。链接进入 Friday 的正常登录流程，并由服务端再次核验资格；当前前端没有真实邮件链路，不得伪造该触达或称其已发送。

## 3. 数据边界

NPS 是独立的产品体验数据，不能写入 Message 的回复反馈记录或 Feedback 页面。

服务端需要保存首次正式启用时间、满足资格的第三条 Message ID 和回复成果物 ID、具备资格时间、站内首次／二次展示和关闭时间、邮件兜底发送时间（如有），以及最终评分和提交时间。服务端以用户标识施加唯一约束，避免多个浏览器或重复点击产生多条评分。

前端只读取当前用户的邀评状态和本次是否应展示、提交评分或记录关闭；不从 Message 状态推断真实外发、资格或邮件发送，也不计算或伪造评分结果。

## 4. 指标与判定

| 分数 | 分类 |
| --- | --- |
| 9–10 | 推荐者 |
| 7–8 | 中立者 |
| 0–6 | 贬损者 |

`NPS = 推荐者占有效评分的比例 − 贬损者占有效评分的比例`，取值范围为 -100 到 +100；中立者计入分母但不加不减。

同时记录：具备资格用户数、站内首次与二次展示数、邮件兜底发送数、有效评分数和回收率。汇总指标仅作为内部产品度量，不放入 Message 或 Feedback 的用户页面。

当有效评分少于 30 个时，只观察分数和回收率趋势；达到 30 个后，NPS 大于 0 才可作为“推荐者多于贬损者、产品价值获得初步验证”的信号。它不等同于长期留存、付费意愿或单条回复质量。

## 5. 异常与真实边界

- 提交失败时，保留评分选项并显示“评分未保存，请重试”；服务端去重保证重试安全。
- 已评分、两次关闭、或已过展示窗口的用户，均不再显示站内浮层。
- 当前前端仍是本地演示、没有经验证的真实外发或邮件链路，因此不得默认展示 NPS 浮层、生成模拟评分，或宣称 NPS 已采集或已发送邮件。只有显式的本地演示场景才可展示，并必须标注“本地演示”。

## 6. 验收

1. 只有首次正式启用满 14 天、且已有至少 3 条跨 3 个不同日期的真实协助回复外发确认成功的用户会具备资格；任一单条回复均不会单独触发。
2. 具备资格后，用户进入 Message 页连续停留约 15 秒才显示轻量浮层；不依赖打开任何详情页，也不打断确认、重试等操作。
3. 关闭后只在 7 天后的下一次符合条件会话展示一次；两次关闭后停止。14 天内从未展示站内浮层时才触发一次邮件兜底。
4. 0–10 任一点击能保存一次评分；重复点击、重复进入和多端请求不会产生第二条记录。
5. 失败重试不丢失用户选择，也不会造成重复评分。
6. 评分分类、NPS 计算、有效评分数与回收率符合第 4 节定义。
7. Message 点赞／点踩、Feedback 卡片和工作画像不读取、展示或修改 NPS 评分。
