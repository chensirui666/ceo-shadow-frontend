# 四步 Onboarding：选择本机 CLI Agent

## 目标

首次登录后，Friday 先让用户在本机选择一个执行 Agent，再完成既有的工作来源、Memory 和工作方式配置。P0 支持 Codex CLI、Claude Code 与 Pi；用户不需要向 Friday 提供或粘贴 API Key。

流程从三步调整为：

1. 选择 Agent；
2. 连接工作来源；
3. 建立 Memory；
4. 确认工作方式并正式开始。

后面三步仅顺延，原有完成条件与完成后进入 Message 的规则不变。

## 第 1 步：选择 Agent

用户登录后，Friday App 立即扫描当前 Mac 的 Codex CLI、Claude Code 和 Pi。页面沿用现有来源连接页的紧凑行列表：左侧为 Agent 名称、说明和状态，右侧只有当前动作。

页面只展示三种长期状态：

| 状态 | 右侧动作 | 含义 |
| --- | --- | --- |
| 未下载 | 下载 | 本机未检测到可用 CLI。 |
| 已下载 | 选择 | CLI 已安装，但尚未被 Friday 绑定或尚未通过可用性检查。 |
| 已连接 | 显示已连接的状态 | 唯一可执行的 Agent；第 2 步才可继续。 |

扫描中、下载确认、下载中、原生登录中、Pi 订阅选择中、健康检查中和失败提示都是临时操作状态，不能替代上表的长期状态，更不能显示为“已连接”。

### 下载

点击“下载”后先显示确认弹窗，清楚说明将下载对应 CLI。用户确认后，当前行显示下载进度并禁止重复触发；成功后仅变为“已下载”，由用户再次点击“选择 ”发起连接。用户取消或下载失败时，本机层清理或重新扫描；只有检测到可用二进制才显示“已下载”，否则回到“未下载”，显示可读原因与“重试”。

### 选择与连接

选择 Codex CLI 或 Claude Code 后，页面在同一流程中显示“等待你在浏览器完成登录”。Friday App 启动对应 CLI 的原生登录流程；用户完成登录后，App 自动执行一次不产生业务工作的健康检查。通过才标记为“已连接”。

选择 Pi 时：

- 本机已有一个可用的 Pi 模型时，直接进行健康检查；
- 没有可用模型时，页面在当前步骤提供订阅提供方选择：ChatGPT、Claude ；选定后启动 Pi 的原生登录；
- P0 不显示 API Key 输入，也不允许 Friday 保存 API Key；用户取消、授权过期或检查失败时均回到“已下载”。

## 互斥绑定与 Settings

一个账号在一台活跃 Mac 上只能连接一个 Agent。连接成功后，其余两个 Agent 保持自身安装状态，但不可选择，并提示必须先解除当前连接。

切换入口只在 Settings 的“Agent”区域。用户点击“解除绑定”后需要二次确认；它只停止当前 CLI 的新执行资格，不删除 Friday 的 Memory、Message、工作方式或其他账户数据。若当前 CLI 正在执行指令，P0 不允许解除或迁移，需等执行结束后再操作。解除后，原 Agent 回到“已下载”，用户可以在 Settings 绑定另一个 Agent。Onboarding 不承担切换功能。

## 本机与云端边界

Friday App 的本机终端控制层负责扫描、下载、启动原生登录、健康检查和解除绑定。它对 UI 提供五类动作：`scan`、`install`、`connect`、`healthCheck`、`unbind`。UI 不解析原始终端输出，只消费标准化结果与安全的错误摘要。

| 留在本机 | 云端最小同步 |
| --- | --- |
| CLI 登录 Token、API Key、Pi 提供方及模型配置、二进制路径、原始命令输出 | 已选 Agent、连接状态、最近健康检查时间、可读错误摘要 |

云端不保存凭证或 API Key。健康检查只验证 CLI 已可被安全调用；不创建任务、不读取工作资料、不发送外部消息。

## 失败与恢复

| 场景 | 页面结果 |
| --- | --- |
| 扫描失败 | 保留第 1 步，说明未能完成扫描并提供重新扫描。 |
| 下载取消或失败 | 保持“未下载”，提供可读原因与重试。 |
| 原生登录取消、超时或过期 | 回到“已下载”，用户可再次选择。 |
| 健康检查失败 | 不标记连接成功，回到“已下载”并提供重试。 |
| 当前 Agent 已连接 | 其他 Agent 不可选择；引导到 Settings 解除绑定。 |

## 验收与测试

- 新用户登录后看到四步进度和 Agent 扫描结果；没有已连接 Agent 时不能进入第 2 步。
- 三种 CLI 均覆盖：已下载、未下载、下载确认、下载进度、下载失败与重试。
- Codex CLI、Claude Code 覆盖原生登录成功、取消和健康检查失败；Pi 覆盖已有可用模型、订阅登录成功、取消和不可用状态。
- 解除绑定后可绑定另一个 Agent，且 Friday 的既有 Memory、Message 和工作方式仍在。
- 单元测试覆盖状态机及互斥规则；App 与本机控制层的契约测试覆盖标准化扫描、安装、登录和检查结果；端到端测试以模拟命令结果验证全部 UI 回退路径。真实 Mac 验收必须另外验证三种 CLI 的实际安装、登录与检查回调。

## P0 不做

- 在 Friday 内输入、传输或保存 API Key；
- Codex CLI 或 Claude Code 的模型挑选与模型参数配置；
- 多 Agent 并行连接、Onboarding 内切换 Agent、下载完成后自动连接；
- 将扫描、下载、登录或健康检查的模拟成功表述为真实连接；
- 导入 CLI 历史对话或改变现有来源、Memory、工作方式的产品边界。
