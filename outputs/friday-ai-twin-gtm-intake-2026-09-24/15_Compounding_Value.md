# 15. Compounding Value — Does Friday Get More Useful Over Time?

## Day 1

Friday can begin with the authorized sources and the work identity the user has connected. It can use a current group promise, relevant minutes, and the expected document location to surface a risk and take the next permitted action. The user may still need to identify the real project lead, clarify where the final artifact belongs, or correct a vague completion condition. A user does not need to wait six months for the first useful risk intervention.

**Observed product fact:** The feature owner confirms the risk-to-resolution loop runs. **Unknown:** Day-1 detection quality, setup time, and first-value rate.

## Day 30

If Friday has processed more authorized work, it may have a longer record of project names, recurring participants, earlier commitments, changed deadlines, corrections, and outcomes. That context can reduce repeated explanations and help it connect a new warning to an existing project. It can also make a wrong assumption more durable if stale context is not corrected. The value comes from **fewer missed handoffs and better interventions**, not a higher raw Memory count.

**Hypothesis / Not yet measured:** Fewer user corrections, more accurate owner selection, and fewer manual context searches by day 30. There is no longitudinal cohort result in the supplied material.

## Month 6

A long-running, authorized work history could help Friday recognize which projects routinely depend on which deliverables, which lead can unblock a specific risk, and what evidence typically satisfies recurring work. A newly installed assistant would have to reconstruct that context from available sources. However, continued access to source history and corrections matters more than merely accumulating memory; obsolete commitments must not override current decisions.

**Hypothesis / Not yet measured:** More eligible issues can be handled without the user restating context, while false alerts and harmful outreach stay controlled. The reviewed material does not show that new categories become automatically authorized or that Friday silently learns a broader send policy over time.

## Retention and switching cost

The candidate user with the highest retention value is a lead coordinating several overlapping projects through conversations, meetings, and document handoffs. Without Friday, that person would resume cross-source review, owner reminders, escalation, and closure checks. The potential switching cost is the source-linked record of promises, corrections, people, and outcomes, plus a working routine that contacts others in the right context. This is a **product hypothesis**, not a demonstrated moat. Customers must be able to see, correct, and export or delete their data according to the actual product policy; long-term value should not rely on trapping inaccessible information.

## Boundary

More historical context is not always better. A changed owner, revoked permission, or canceled project can make old memory actively harmful. Current source evidence and access rights must win. The Friday Onboarding PRD describes P0 identity separation and also a gap in retroactive cleanup after source deletion/revocation; compounding-value claims must not hide that limit.
